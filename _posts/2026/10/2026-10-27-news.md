## AWS What's New

### Amazon WorkSpaces Core Managed Instances now supports ModifyVolume API

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-workspaces-cmi-modifyvolume/](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-workspaces-cmi-modifyvolume/)
- **Published**: 2026-10-27 03:00:00
- **Fetched**: 2026-10-27 05:52:19

<div class="entry-summary">
<p>Amazon WorkSpaces Core Managed Instances now supports the ModifyVolume API, which lets you change volume size, volume type, IOPS, or throughput in place, without detaching the volume or restarting the instance. Previously, changing storage capacity or performance on a deployed managed instance required rebuilding it.</p> 
<p>With ModifyVolume, you can increase volume size up to 16,384 GiB, switch between supported Amazon EBS volume types, adjust IOPS for gp3, io1, and io2 volumes, and modify throughput for gp3 volumes. The API supports idempotency tokens to prevent duplicate changes, and you can track progress with the Amazon EC2 DescribeVolumesModifications operation.</p> 
<p>ModifyVolume is available in all AWS Regions where Amazon WorkSpaces Core Managed Instances is available.</p> 
<p>To get started, call ModifyVolume directly, or use it through your WorkSpaces Core partner solution once available. To learn more, see <a href="https://docs.aws.amazon.com/workspaces-instances/latest/api/API_ModifyVolume.html" rel="noopener noreferrer" target="_blank">ModifyVolume</a> in the WorkSpaces Instances API Reference and <a href="https://docs.aws.amazon.com/ebs/latest/userguide/ebs-modify-volume.html#elastic-volumes-limitations" rel="noopener noreferrer" target="_blank">Limitations</a> in the Amazon EBS User Guide, or visit <a href="https://aws.amazon.com/workspaces/vdi-partners/" rel="noopener noreferrer" target="_blank">WorkSpaces Core</a>.</p>
</div>

### OpenAI GPT-6.1 Terra is now generally available on Amazon Bedrock

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/openai-gpt-6-1-terra-on-amazon-bedrock/](https://aws.amazon.com/about-aws/whats-new/2026/10/openai-gpt-6-1-terra-on-amazon-bedrock/)
- **Published**: 2026-10-27 03:27:00
- **Fetched**: 2026-10-27 05:52:19

<div class="entry-summary">
<p>Today, AWS announces the general availability of OpenAI GPT-6.1 Terra on Amazon Bedrock. GPT-6.1 Terra expands the GPT-6 family with a balance of capability, speed, and cost efficiency for everyday workloads.&nbsp;</p> 
<p>As the newest model in the Terra line, GPT-6.1 Terra combines detailed visual reasoning, accurate computer use, and improved factuality and natural writing over GPT-5.6 Terra, for complex workflows. In OpenAI’s Agents’ Last Exam evaluation, it scored 15 percentage points higher than GPT-5.6 Terra, performed on par with GPT-6 Astra, and completed tasks more than three times faster than GPT-6 Astra and GPT-6.1 Sol. GPT-6.1 Terra offers balanced performance with input and output token prices at least 50% lower than those of GPT-6.1 Sol and GPT-5.6 Terra. It supports a context window of up to 1 million input tokens and accepts both text and image inputs. The Amazon Bedrock inference engine delivers the performance, security, and scale required for enterprise workloads.&nbsp;</p> 
<p>You can call GPT-6.1 Terra directly through Amazon Bedrock APIs or configure ChatGPT Work and Codex to use the model on Amazon Bedrock. Use it to draft proposals, interpret technical drawings, investigate codebases, and build agents that operate across business systems.&nbsp; Established AWS controls help you secure workloads, govern access, and audit model invocation activity.&nbsp;</p> 
<p>You can get started in the Amazon Bedrock console or programmatically through supported Amazon Bedrock APIs. For information about supported AWS Regions, endpoints, APIs, features, inference profiles and pricing, see the <a href="https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html">Amazon Bedrock documentation.</a> &nbsp;</p>
</div>

### CVE-2026-115418 - SQL injection in the database-query custom resource handlers in Amazon Web Services (AWS)

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-151-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-151-aws/)
- **Published**: 2026-10-27 01:50:46
- **Fetched**: 2026-10-27 05:52:21

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-151-AWS<br /> <b>Scope:</b> AWS<br /> <b>Content Type:</b> Important (requires attention)<br /> <b>Publication Date:</b> 10/26/2026 09:30 AM PDT</p> 
<p><b>Description:</b></p> 
<p>The AWS Cloud Development Kit (CDK) @aws-cdk/aws-redshift-alpha module provides experimental constructs that manage Amazon Redshift users, tables and privileges. We identified CVE-2026-115418, an issue where crafted user names, comments or passwords set in these constructs could change the SQL that runs with Amazon Redshift superuser privileges at deployment, including granting access to all cluster users. Exploiting the issue requires the ability to influence the CDK application's construct property values.</p> 
<p><b>Impacted versions:</b> &lt;2.274.0-alpha.0</p>
