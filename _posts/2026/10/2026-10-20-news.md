### Amazon GuardDuty adds optional threat detection rules for Runtime Monitoring

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/guardduty-runtime-optional-detection-rules/](https://aws.amazon.com/about-aws/whats-new/2026/10/guardduty-runtime-optional-detection-rules/)
- **Published**: 2026-10-20 01:01:00
- **Fetched**: 2026-10-20 03:37:06

<div class="entry-summary">
<p>Amazon GuardDuty now supports optional detection rules for Runtime Monitoring. You can enable more than 50 Runtime Monitoring rules that help detect process, file, and network activity that might be routine in one environment but a sign of compromise in another, such as modifying sudoers files or disabling audit logging.</p>
<p>The new rules provide detections for Amazon EC2 instances, Amazon EKS, and Amazon ECS on both EC2 and AWS Fargate, and span 13 finding types mapped to MITRE ATT&amp;CK® tactics including persistence, privilege escalation, execution, defense evasion, discovery, exfiltration, and command and control. This release introduces four new finding types: CommandAndControl:Runtime/SuspiciousCommand, CredentialAccess:Runtime/SensitiveFileRead, Discovery:Runtime/SensitiveFileRead, and Exfiltration:Runtime/SuspiciousCommand.</p>
<p>To get started, visit the GuardDuty console. You can enable rules in dry-run mode to evaluate detection efficacy before enabling live detection.</p>
<p>Custom Detection Rules for Runtime Monitoring is available in all AWS commercial Regions and the AWS GovCloud (US) Regions. To learn more, see <a href="https://docs.aws.amazon.com/guardduty/latest/ug/custom-detection-rules.html">Amazon GuardDuty Custom Detection Rules</a>. To receive programmatic updates on new Amazon GuardDuty features and threat detections, subscribe to the <a href="https://docs.aws.amazon.com/guardduty/latest/ug/guardduty_sns.html">Amazon GuardDuty SNS topic</a>.</p>
</div>

### EC2 Image Builder now integrates with ASG for faster image builds

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/ec2-image-builder-asg-faster-builds/](https://aws.amazon.com/about-aws/whats-new/2026/10/ec2-image-builder-asg-faster-builds/)
- **Published**: 2026-10-20 02:30:00
- **Fetched**: 2026-10-20 07:47:09

<div class="entry-summary">
<p>EC2 Image Builder now supports using existing instances from an Auto Scaling Group (ASG) for building images, enabling faster builds by eliminating the time spent in launching and bootstrapping new instances and reusing already running EC2 instances.</p>
<p>With this feature, you can provide an ASG in your Image Builder infrastructure configuration. Instead of launching a new instance at the build time, Image Builder selects an already-running instance from this ASG, applies your build components, and creates the image. The ASG continuously replenishes the pool as instances are used for builds, ensuring instances are always available for subsequent pipeline runs.</p>
<p>This feature is fully opt-in and does not affect existing pipelines. Pipelines without an ASG configured continue to use the default launch path with no behavior change.</p>
<p>This feature is available in all AWS Regions at no additional cost. To configure ASG integration in your Image Builder pipelines, see the <a href="https://docs.aws.amazon.com/imagebuilder/latest/userguide/infra-config-parent-instance.html">EC2 Image Builder documentation</a>.</p>
</div>

### Amazon ElastiCache Serverless for Valkey now supports online migration with zero downtime

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-elasticache-serverless-valkey-online-migration/](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-elasticache-serverless-valkey-online-migration/)
- **Published**: 2026-10-20 16:00:00
- **Fetched**: 2026-10-21 10:13:43

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><a href="https://aws.amazon.com/elasticache/">Amazon ElastiCache</a> Serverless for Valkey now supports online migration from self-managed Valkey and Redis OSS on Amazon EC2 with zero downtime. Zero downtime means zero Errors returned to the client during migration, measured the same way the <a href="https://aws.amazon.com/elasticache/sla/">ElastiCache SLA</a> measures availability. Your application continues reading and writing through cutover, and you do not need third-party replication tools.</p> 
<p>Online migration runs in three steps. You prepare the migration, start the data sync, and complete the cutover. ElastiCache gives you a migration endpoint your application can point to when you prepare the migration, and data replicates continuously from your source once you start the sync. You choose when writes move to the serverless cache, with a manual cutover or an automatic one once your data is in sync. ElastiCache records each step as an event on the cache’s Events tab, with the reason for any failed step.</p> 
<p>Online migration connects to your source using encryption in transit (TLS) and authentication, and reads credentials from AWS Secrets Manager, so your existing security controls stay in place. Online migration supports self-managed caches in cluster mode on Amazon EC2 running Redis OSS 4.0 through 7.2 or Valkey 7.2 through 8.1, and you can migrate them straight to Valkey 9.0.</p> 
<p>Migration usage is free for the first 180 days per AWS account, starting when the account first prepares a migration. After that, you pay per node-hour for the migration nodes that ElastiCache runs to replicate your data, for as long as a migration is active. The ElastiCache Serverless cache is billed separately at standard data storage and ECPU rates, including during the free period. For pricing details, see <a href="https://aws.amazon.com/elasticache/pricing/">Amazon ElastiCache pricing</a>. Online migration is available in all commercial AWS Regions, the China Regions, and the AWS GovCloud (US) Regions.&nbsp;</p> 
<p>To get started, create or select an empty ElastiCache Serverless cache to migrate into, then start the migration from the <a href="https://console.aws.amazon.com/elasticache/">ElastiCache console</a> or the AWS CLI. To learn more, see the <a href="https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/migration-to-serverless.html">documentation</a>.</p>
</details>

### AWS IAM Identity Center simplifies identity source changes from Active Directory

- **Published**: 2026-10-20 17:00:00
- **Fetched**: 2026-10-21 03:17:01

<div class="entry-summary">
<p>AWS IAM Identity Center now retains your workforce identities and their assignments when you change your identity source from Active Directory to an external identity provider (IdP), such as Okta or Microsoft Entra ID, or to the Identity Center directory. Specifically, it preserves your users, groups, group memberships, permission set assignments, and application assignments. Previously, this change required you to recreate them in IAM Identity Center.</p>
<p>IAM Identity Center helps you connect your workforce identities to AWS once and manage their access centrally across AWS applications and accounts. When you change your identity source from Active Directory, your existing identity store remains in place, so your users and groups keep the same IDs. As a result, users retain their access to AWS accounts and applications, and policies that reference your user IDs, group IDs, or identity store ID continue to work.</p>
<p>To make this change, configure your new identity source with the standard setup required for users to sign in. After the change, your workforce signs in through your dual-stack AWS access portal URL. Changing your identity source in the other direction, to Active Directory, works as before. This feature is available for organization instances of IAM Identity Center in all AWS Regions where IAM Identity Center is available. IAM Identity Center is provided at no additional cost.</p>
<p>To get started, navigate to the IAM Identity Center console. For more information, see <a href="https://docs.aws.amazon.com/singlesignon/latest/userguide/manage-your-identity-source-change.html">Change your identity source</a> in the IAM Identity Center User Guide. To learn more about IAM Identity Center, visit the <a href="https://aws.amazon.com/iam/identity-center/">product detail page</a>.</p>
</div>

### Amazon Bedrock Advanced Prompt Optimization now supports prompt shortening

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-prompt-optimization-shortening/](https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-prompt-optimization-shortening/)
- **Published**: 2026-10-20 17:00:00
- **Fetched**: 2026-10-21 10:13:43

<div class="entry-summary">
<p>Amazon Bedrock Advanced Prompt Optimization now supports prompt shortening, an optional setting that reduces the length of your prompt while maintaining or improving your evaluation scores. Advanced Prompt Optimization optimizes prompts for any model on Amazon Bedrock against your own evaluation criteria. Until now, optimization focused on quality alone. Optimized prompts were often longer than the original. Longer prompts raise input token costs and can increase time to first token, which matters at scale and in latency-sensitive applications.</p> 
<p>When you turn on prompt shortening for a prompt template in your input dataset, the optimizer reduces the prompt's length. The optimized prompt is returned only when it is shorter than your original prompt and scores at least as high on your evaluation. Otherwise your original prompt is returned, so the setting never leaves you with a longer or lower-scoring prompt. Results include a compression ratio and the original and optimized token counts, in the output file and on the console results page. For example, a compression ratio of 0.7 means the optimized prompt uses 30% fewer tokens. Prompt shortening works with any evaluation method, including steering criteria, LLM-as-a-judge rubrics, and custom Lambda evaluators.&nbsp;&nbsp;&nbsp;&nbsp;</p> 
<p>Prompt shortening is available in all AWS Regions where Advanced Prompt Optimization is available. To get started, enable prompt shortening for a prompt template in your input dataset and create an optimization job as usual. To learn more, see <a href="https://docs.aws.amazon.com/bedrock/latest/userguide/advanced-prompt-optimization-shorten.html">Shorten prompts</a> in the Amazon Bedrock User Guide, the <a href="https://aws.amazon.com/bedrock/pricing/">Amazon Bedrock pricing page</a>, and the <a href="https://aws.amazon.com/bedrock/">Amazon Bedrock product page</a>.</p>
</div>
