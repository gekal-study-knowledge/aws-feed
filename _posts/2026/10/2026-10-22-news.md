### AWS Neuron 2.33 adds native PyTorch support, Neuron Observer, and other new features

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-announce-neuron-2-33-0](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-announce-neuron-2-33-0)
- **Published**: 2026-10-22 00:00:00
- **Fetched**: 2026-10-22 06:11:13

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS Neuron 2.33 is now available, introducing TorchNeuron, the native PyTorch backend for AWS Trainium, in public beta. You can run models written with the standard PyTorch APIs on Amazon EC2 Trn2 and Trn3 instances, in eager mode or with torch.compile. This release also introduces Neuron Observer in public beta, which detects Trainium health issues in under a second and identifies the affected node or device.</p> 
<p>The vLLM Neuron plugin upgrades to vLLM 0.29.0, and the vLLM Omni Neuron plugin for Wan2.2 video generation is now part of the Neuron release. Both support native PyTorch compilation through TorchNeuron. A new Neuron Deep Learning AMI and Deep Learning Container for PyTorch training include TorchNeuron, PyTorch 2.14, and TorchTitan. Neuron Explorer opens profiles captured with torch.profiler. From a PyTorch memory snapshot, it now attributes allocations to the Python source lines that made them, for debugging out-of-memory errors in eager mode.</p> 
<p>Kernels written with the Neuron Kernel Interface (NKI) can now use the full Python language for metaprogramming, including generators and class inheritance. The NKI Library adds 25 new experimental kernels, including kernels for DeepSeek-V3.2, Qwen3.5, and Kimi Delta Attention.</p>

### Amazon Aurora and Amazon RDS now support On-Demand Capacity Reservation

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-aurora-rds-on-demand-capacity-reservations/](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-aurora-rds-on-demand-capacity-reservations/)
- **Published**: 2026-10-22 01:00:00
- **Fetched**: 2026-10-22 02:52:11

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Starting today, you can reserve compute capacity for your Amazon Aurora and Amazon RDS DB instances in one or more Availability Zones for as long as you need it. Reserving capacity helps ensure that DB instance create, restore, scale-compute, and start operations don't fail because of insufficient capacity.</p> 
<p>On-Demand Capacity Reservation is designed for workloads that need assurance that specific DB instance capacity will be available when they need it for business-critical events, such as migrations, product launches, seasonal peaks, high-availability deployments, or disaster recovery. You choose the DB instance class, engine, Availability Zones, and reserved capacity per Availability Zone, and RDS holds that capacity for you. Capacity can be reserved in two or more Availability Zones to support Multi-AZ deployments. To use the reserved capacity, reference the reservation when you create, restore, modify, or start a DB instance.</p> 
<p>You can reserve capacity for immediate use with no commitment and cancel at any time, or schedule a reservation to begin 5 to 120 days in the future with a minimum commitment. Reserved capacity is billed at On-Demand rates while the reservation is active, whether or not DB instances within the reservation are running. Discounts from your existing Reserved DB Instances or Database Savings Plans apply automatically.</p> 
<p>On-Demand Capacity Reservation is available for <a href="https://aws.amazon.com/rds/aurora/" rel="noopener noreferrer" target="_blank">Amazon Aurora</a> and <a href="https://aws.amazon.com/rds/" rel="noopener noreferrer" target="_blank">Amazon RDS</a> in all AWS commercial Regions. To learn more about On-Demand Capacity Reservation, visit the documentation for <a href="https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/capacity-reservations.html" rel="noopener noreferrer" target="_blank">Amazon Aurora</a> and <a href="https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/capacity-reservations.html" target="_blank">Amazon RDS</a>.&nbsp;</p>
</details>

### Amazon Cognito extends multi-Region replication to AWS GovCloud (US) Regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/cognito-multi-region-us-govcloud/](https://aws.amazon.com/about-aws/whats-new/2026/10/cognito-multi-region-us-govcloud/)
- **Published**: 2026-10-22 02:00:00
- **Fetched**: 2026-10-22 06:11:13

<div class="entry-summary">
<p>Amazon Cognito multi-Region replication (MRR) now supports AWS GovCloud (US) Regions, extending the resilience benefits of MRR to more workloads. MRR lets you synchronize user and machine identity data, including credentials, user pool configurations, and federation setups, to a secondary user pool in a standby Region you designate, in near real-time. With user data in the standby Region, you can redirect traffic and keep authentication available if there is a disruption in your primary Region.<br /> <br /> Previously, MRR was available in 16 commercial Regions. You can now also use MRR to replicate between additional AWS Regions, helping you meet resilience, data residency, and compliance requirements in the Regions that best align with your business needs.<br /> <br /> MRR is available as an add-on for user pools in the Essentials or Plus feature tiers, and requires a multi-Region AWS KMS customer managed key (CMK). For the full list of AWS Regions where Amazon Cognito is available, see <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/">AWS Capabilities by Region</a>. To get started, visit the <a href="https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-multi-region.html">developer guide</a> for instructions and the <a href="https://aws.amazon.com/cognito/pricing/">pricing page</a> for pricing details.</p>
</div>

### CVE-2026-112408 - Missing bucket ownership verification in Amazon SageMaker Python SDK default_bucket()

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-142-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-142-aws/)
- **Published**: 2026-10-22 04:54:30
- **Fetched**: 2026-10-22 06:11:15

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-142-AWS<br /> <b>Scope:</b> AWS<br /> <b>Content Type:</b> Important (requires attention)<br /> <b>Publication Date:</b> 10/21/2026 12:30 PM PDT</p> 
<p><b>Description:</b></p> 
<p>The Amazon SageMaker Python SDK is an open-source library for training and deploying machine learning models on Amazon SageMaker. We identified CVE-2026-112408, an issue in the default_bucket() function. The SDK uses a predictably named Amazon S3 bucket and does not check that the caller's AWS account owns it. A remote actor who creates that bucket first could achieve code execution in a remote SageMaker execution environment and obtain IAM credentials.</p> 
<p><b>Impacted versions:</b><br /> - V2: &lt; 2.257.3<br /> - V3: &gt;= 3.0.0 and &lt; 3.10.0</p>
