### Amazon SageMaker AI announces training session APIs for serverless model customization

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/training-session-apis-on-sagemaker-ai](https://aws.amazon.com/about-aws/whats-new/2026/10/training-session-apis-on-sagemaker-ai)
- **Published**: 2026-10-23 01:30:00
- **Fetched**: 2026-10-23 05:23:38

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon SageMaker AI serverless model customization now supports training session APIs, giving customers full control over their post-training algorithm without provisioning or managing GPU infrastructure. Managed techniques, including SFT, DPO, and other reinforcement learning methods, let customers pick a technique and a model and have SageMaker AI run the training. With training session APIs, teams get to write the training loop, whether that's reproducing SFT or DPO on their own terms or implementing a custom loss, a new RL reward signal, a data curriculum, or an algorithm straight from the latest research. Operations such as forward_backward(), optim_step(), and sample() become API calls against a live, stateful session, so customers compose whatever training procedure their technique requires while SageMaker AI handles GPU allocation, model and LoRA loading, distributed execution, fault recovery, checkpoint storage, and security.<br /> <br /> Customers can call these operations directly from their own Python code to drive reinforcement learning, supervised fine-tuning, or custom training objectives against a live session, with checkpointing and resume built in. Billing is per token processed, so local computation like reward scoring isn't billed as GPU time. SageMaker AI is also releasing the <a href="https://github.com/aws/sagemaker-training-sessions-cookbook">SageMaker training sessions cookbook</a>, a set of ready-to-run SFT and RL recipes customers can use as blueprints for their own training loops.<a href="https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-training-sessions.html"></a></p> 
<p>Training session APIs are generally available today in US East (N. Virginia), US West (Oregon), and Asia Pacific (Mumbai). To get started, install the SageMaker Python SDK and clone the cookbook, or launch a notebook in SageMaker Studio and connect a coding agent. To learn more, visit the <a href="https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-training-sessions.html">documentation&nbsp;</a>and the <a href="https://aws.amazon.com/sagemaker/ai/model-customization/">Amazon SageMaker AI webpage.</a></p>
</details>

### AWS CloudFormation now simplifies stack update rollback operations

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-cloudformation-cdk/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-cloudformation-cdk/)
- **Published**: 2026-10-23 02:30:00
- **Fetched**: 2026-10-23 05:23:38

<div class="entry-summary">
<p><a href="https://docs.aws.amazon.com/cloudformation/">AWS CloudFormation</a>&nbsp;now makes it simpler to complete an update rollback and get back to deploying. An update rollback returns your stack to a known good state. Starting today, if some resources cannot roll back automatically, force rollback enables you to complete the rollback it in a single operation. It works across every CloudFormation workflow, from the <a href="https://docs.aws.amazon.com/cli/latest/reference/cloudformation/">AWS CLI</a>, and SDKs to <a href="https://docs.aws.amazon.com/cdk/v2/guide/">AWS CDK</a>&nbsp;and AI agents.</p> 
<p>With force rollback, CloudFormation completes the update rollback and returns your stack to a deployable state in a single operation, instead of requiring you to identify, list, and retry the operation for each affected resource. Any resource that still needs attention, such as one affected a change outside CloudFormation, is recorded for you to review and resolve it before your next deployment.</p> 
<p>To get started, run continue update rollback with the force rollback option, then create a <a href="https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/drift-aware-change-sets.html">drift-aware change set</a> to review any configuration differences before your next deployment. To learn more, see &nbsp;<a href="https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/using-cfn-updating-stacks-continueupdaterollback.html">Continue rolling back an update&nbsp;</a> in the AWS CloudFormation User Guide.</p> 
<p>Force rollback is available in all Regions at no additional cost. Refer to the &nbsp;<a href="https://docs.aws.amazon.com/general/latest/gr/cfn.html#cfn_region">AWS Region table&nbsp;</a> for service availability details.</p>
</div>

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-145-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-145-aws/)
- **Published**: 2026-10-23 03:50:58
- **Fetched**: 2026-10-23 05:23:40

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-145-AWS<br /> <b>Scope:</b> AWS<br /> <b>Content Type:</b> Important (requires attention)<br /> <b>Publication Date:</b> 10/22/2026 11:30 AM PDT</p> 
<p><b>Description:</b></p> 
<p>AWS SAM CLI is an open-source framework for building serverless applications. We identified CVE-2026-115414, an OS command injection issue in the Terraform hook (sam build --hook-name terraform) in AWS SAM CLI. The Terraform hook generates a Makefile recipe that interpolates a Terraform resource address without fully neutralizing shell metacharacters, which could allow an actor who can influence the Terraform configuration or plan file consumed by a build to execute arbitrary commands as the build user on the host running the build.</p> 
<p><b>Impacted versions:</b> &gt;=1.63.0, &lt;=1.166.1</p>

### CVE-2026-115419 - Unintended disclosure of data element to wrong session in Strands Agents SDK A2A Server

- **Published**: 2026-10-23 05:07:11
- **Fetched**: 2026-10-23 05:23:40

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-146-AWS<br /> <b>Scope:</b> AWS<br /> <b>Content Type:</b> Important (requires attention)<br /> <b>Publication Date:</b> 10/22/2026 13:00 PM PDT</p> 
<p><b>Description:</b></p> 
<p>Strands Agents is an open-source SDK, available for Python and TypeScript, for building AI agents. The SDK includes an Agent2Agent (A2A) server component that exposes an agent over HTTP so other agents and clients can call it. We identified CVE-2026-115419, an issue where the A2A server did not properly isolate conversation state between callers. An authenticated remote user could access another caller's conversation history or influence model behavior for other callers in multi-tenant deployments.</p> 
<p><b>Impacted versions:</b><br /> - strands-agents (Python): all versions containing the multiagent.a2a module, &lt; 1.43.0<br /> - @strands-agents/sdk (TypeScript): &lt; 1.5.0</p>
