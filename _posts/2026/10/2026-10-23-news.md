### Amazon MSK Connect now supports pausing and resuming connectors

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-msk-connect-pause-resume](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-msk-connect-pause-resume)
- **Published**: 2026-10-23 00:00:00
- **Fetched**: 2026-10-24 03:51:42

<div class="entry-summary">
<p><a href="https://aws.amazon.com/msk/features/msk-connect/">Amazon MSK Connect</a> (Amazon Managed Streaming for Apache Kafka Connect) now supports pausing and resuming connectors, letting you temporarily pause a connector from processing records and resume it later. This is useful when you need to stop data flow during maintenance on a source database or a sink target, or to pause processing while you investigate an upstream or downstream issue.</p> 
<p>Amazon MSK Connect is a fully managed service that allows you to deploy, monitor, and scale Apache Kafka Connect connectors with <a href="https://aws.amazon.com/msk/">Amazon MSK</a> (Managed Streaming for Apache Kafka). Previously, pausing a connector meant deleting it and recreating it - a more disruptive operation, adding risk and operational overhead. With this launch, you can pause a running connector and resume it in place when you are ready — a paused connector keeps its configuration, capacity settings, and committed offsets, and its tasks continue processing from the offsets they last committed when you resume.</p> 
<p>This capability is available at no additional cost through the Amazon MSK Console, AWS CLI, AWS SDK, and AWS CDK in all AWS Regions where Amazon MSK Connect is available. To learn more, visit the <a href="https://docs.aws.amazon.com/msk/latest/developerguide/mskconnect.html">Amazon MSK Connect documentation</a>. To get started, visit the <a href="https://console.aws.amazon.com/msk">Amazon MSK Console</a>.</p>
</div>

### AWS CloudFormation now simplifies stack update rollback operations

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-cloudformation-cdk/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-cloudformation-cdk/)
- **Published**: 2026-10-23 02:30:00
- **Fetched**: 2026-10-23 05:23:38

<div class="entry-summary">
<p><a href="https://docs.aws.amazon.com/cloudformation/">AWS CloudFormation</a>&nbsp;now makes it simpler to complete an update rollback and get back to deploying. An update rollback returns your stack to a known good state. Starting today, if some resources cannot roll back automatically, force rollback enables you to complete the rollback it in a single operation. It works across every CloudFormation workflow, from the <a href="https://docs.aws.amazon.com/cli/latest/reference/cloudformation/">AWS CLI</a>, and SDKs to <a href="https://docs.aws.amazon.com/cdk/v2/guide/">AWS CDK</a>&nbsp;and AI agents.</p> 
<p>With force rollback, CloudFormation completes the update rollback and returns your stack to a deployable state in a single operation, instead of requiring you to identify, list, and retry the operation for each affected resource. Any resource that still needs attention, such as one affected a change outside CloudFormation, is recorded for you to review and resolve it before your next deployment.</p> 
<p>To get started, run continue update rollback with the force rollback option, then create a <a href="https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/drift-aware-change-sets.html">drift-aware change set</a> to review any configuration differences before your next deployment. To learn more, see &nbsp;<a href="https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/using-cfn-updating-stacks-continueupdaterollback.html">Continue rolling back an update&nbsp;</a> in the AWS CloudFormation User Guide.</p> 
<p>Force rollback is available in all Regions at no additional cost. Refer to the &nbsp;<a href="https://docs.aws.amazon.com/general/latest/gr/cfn.html#cfn_region">AWS Region table&nbsp;</a> for service availability details.</p>
</div>

### Amazon OpenSearch Serverless now supports a 5-second default refresh interval

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-opensearch-serverless-supports-5-second-refresh-interval/](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-opensearch-serverless-supports-5-second-refresh-interval/)
- **Published**: 2026-10-23 03:34:00
- **Fetched**: 2026-10-23 08:51:16

<div class="entry-summary">
<p>Starting today, Amazon OpenSearch Serverless reduces the default refresh interval to 5 seconds for both search and vector collections. The refresh interval controls how quickly newly ingested documents become available for search. By lowering the default from 10 seconds to 5 seconds, newly written data becomes searchable faster, giving applications quicker read-after-write visibility automatically, with no configuration changes and no action required on your part.</p> 
<p>This improvement applies to the next generation of Amazon OpenSearch Serverless and takes effect by default on both search and vector collections. Faster refresh is valuable for workloads that continuously ingest data and need near real-time retrieval, including full-text search over frequently updated content as well as vector use cases such as retrieval-augmented generation (RAG), semantic search, and recommendation and personalization systems. This means applications and AI agents can retrieve and act on the most recently ingested data sooner, improving the relevance and accuracy of search results and RAG responses for datasets that change frequently.</p> 
<p>The 5-second default refresh interval is available in all&nbsp;<a href="https://docs.aws.amazon.com/general/latest/gr/opensearch-service.html" rel="noopener noreferrer" target="_blank">24 regions</a>&nbsp;where Amazon OpenSearch Serverless is available today. To learn more, see the Amazon OpenSearch Serverless <a href="https://docs.aws.amazon.com/opensearch-service/latest/developerguide/serverless.html" rel="noopener noreferrer" target="_blank">documentation</a>.</p>
</div>

### Amazon OpenSearch Service introduces intelligent ingestion for logs and documents in Amazon S3

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-opensearch-intelligent-ingestion-logs-documents-s3](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-opensearch-intelligent-ingestion-logs-documents-s3)
- **Published**: 2026-10-23 05:54:00
- **Fetched**: 2026-10-24 06:48:51

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon OpenSearch Serverless now offers intelligent ingestion, a fully managed feature that turns logs and documents stored in Amazon S3 into searchable content in Amazon OpenSearch Serverless (NextGen) collections . With intelligent ingestion, you can set up ingestion with a few clicks in the AWS Management Console or a single API call, with no ingestion infrastructure to manage. Intelligent ingestion supports observability logs and structured data in JSON, NDJSON, and JSON array formats, and unstructured files in PDF, Word, plain text, and Markdown formats.</p> 
<p>You choose an S3 source and a collection index, and intelligent ingestion handles the rest. It automatically detects data types, parses documents, describes images, chunks text, generates vector embeddings, and indexes the results. You don't need to manage ingestion or document-processing infrastructure, or size capacity in advance. Use ingestion jobs for one-time loads such as migrations and backfills, or ingestion streams to keep an index in sync as new objects arrive in your bucket. Capacity scales with your workload up to the collection's configured limit, and you pay only for active processing. Source S3 buckets can be in the same AWS account as the collection or in a different account.</p> 
<p>For logs and structured data, intelligent ingestion applies transformations and optionally adds embeddings, with no pipeline code. For unstructured data, it parses PDF, Word, plain text, and Markdown files while keeping headings, reading order, and tables intact, so the content lands in an index ready for semantic and hybrid search. When documents contain charts, diagrams, screenshots, or photos, a vision-language model generates text descriptions that are indexed with the surrounding content, making visual information searchable too.</p> 
<p>Intelligent ingestion is available today for Amazon OpenSearch Serverless (NextGen) collections, with Amazon S3 as the source, in seven AWS Regions. To get started, open the Amazon OpenSearch Service console, choose your collection, and select the Ingestion tab. To learn more, see <a href="https://docs.aws.amazon.com/opensearch-service/latest/developerguide/serverless-intelligent-ingestion.html">Intelligent ingestion</a> in the Amazon OpenSearch Service Developer Guide. For pricing, see <a href="https://aws.amazon.com/opensearch-service/pricing/">Amazon OpenSearch Service pricing</a>.</p>
</details>

### AWS Continuum for code vulnerabilities is now generally available

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-continuum-for-code-vulnerabilities-is-now-generally-available](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-continuum-for-code-vulnerabilities-is-now-generally-available)
- **Published**: 2026-10-23 06:00:00
- **Fetched**: 2026-10-23 08:51:16

<div class="entry-summary">
<p>Today, AWS announces the general availability of AWS Continuum for code vulnerabilities. Continuum for code vulnerabilities&nbsp;discovers, validates, prioritizes, and remediates code vulnerabilities at machine speed.</p> 
<p>Continuum for code vulnerabilities builds a context graph from your AWS environment, including resource topology, identity relationships, and network reachability. It knows which resources are part of your application, and which findings carry real business risk. It ingests your existing vulnerability findings, scans your code, and then confirms which findings are exploitable by testing them in an isolated sandbox. The findings are prioritized by business impact. And finally, it provides remediation patches as pull requests directly to developer workflows with exploitability proof and blast radius assessment attached.</p> 
<p>Continuum for code vulnerabilities picks the right AI model for each task. Continuum starts in Learn mode where it proposes the remediation fixes that you approve. When it builds sufficient trust in its precision, you switch to the Enforce mode and let it act autonomous within the guardrails you set.&nbsp;</p> 
<p>AWS Continuum works alongside your existing AWS security services, including Amazon GuardDuty and AWS Security Hub. For more information about the AWS Regions where AWS Continuum is available, see the <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/" rel="noopener noreferrer" target="_blank" title="AWS Regional Table">AWS Region table.</a> To learn more, see the AWS Continuum <a href="https://aws.amazon.com/continuum/">product page</a>.</p>
