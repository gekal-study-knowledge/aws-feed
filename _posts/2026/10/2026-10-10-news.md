### Amazon Quick now supports brand templates for on-brand presentations and documents

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-quick-brand-templates-on-brand-presentations-documents/](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-quick-brand-templates-on-brand-presentations-documents/)
- **Published**: 2026-10-10 00:00:00
- **Fetched**: 2026-10-10 06:26:46

<div class="entry-summary">
<p>Starting today, you can upload brand templates in Amazon Quick, allowing you to create presentations and documents that match your approved visual identity. Brand managers set up a template once and everyone gets on-brand output, without hunting for the right file in each chat.</p>
<p>Brand managers upload PowerPoint or Word templates, or pull them from a connected file store such as SharePoint. Quick extracts the colors, fonts, logos, layouts and brand rules from each file. A brand manager reviews and edits what Quick found before publishing it to the whole organization.</p>
<p>Quick also follows a template's rules as it creates new assets. If a request breaks a rule, Quick explains why and suggests an on-brand alternative. For each task, Quick picks the best-fit template based on guidance the brand manager writes. Users can still choose a different template.</p>
<p>Administrators decide who can create and publish brand templates using custom permissions, ensuring that only the proper members of brand, marketing, or other approved teams can set visual standards.&nbsp;</p>
<p>Brand assets are generally available today in the Amazon Quick desktop app. To learn more, see the <a href="https://docs.aws.amazon.com/quick/latest/userguide/brand-assets-desktop.html" target="_blank">Amazon Quick documentation,</a> or <a href="https://portal.aws.amazon.com/billing/signup/service?app=AmazonQuickSuite&amp;tier=free&amp;funnel=boost&amp;additionalState=ampDeviceId%3Da8b6426f-6802-4b96-8ebb-e39fff4fab5f%26ampSessionId%3D1791568256376#/validation&amp;refid=0ea79374-057c-4897-84f0-5fe792905a8f">create an account for free</a> and start using Quick in minutes.</p>

### AWS Lambda supports OAuth authentication for self-managed Apache Kafka event sources

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-Lambda-supports-oauth-kafka-esm/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-Lambda-supports-oauth-kafka-esm/)
- **Published**: 2026-10-10 01:30:00
- **Fetched**: 2026-10-10 06:26:46

<div class="entry-summary">
<p>AWS Lambda now supports OAuth authentication for <a href="https://docs.aws.amazon.com/lambda/latest/dg/with-kafka.html">self-managed Apache Kafka event source mappings</a> (ESM), including&nbsp;Kafka clusters that customers run themselves and managed offerings such as Confluent Cloud, Aiven, and Redpanda. With this launch, customers can authenticate their Lambda Kafka consumers through their enterprise identity provider, helping them meet the security and compliance requirements for their Kafka applications.</p>
<p>Customers building event-driven Kafka workloads for use cases such as payment processing, fraud detection, and real-time data pipelines use Kafka ESM to build serverless Kafka consumers. Kafka ESM provides automatic scaling, error handling, batching, and event filtering. Previously, Kafka ESM supported only SASL/PLAIN, SASL/SCRAM, and mutual TLS (mTLS) as&nbsp;<a href="https://docs.aws.amazon.com/lambda/latest/dg/kafka-cluster-auth.html">authentication methods</a>,&nbsp;so customers in regulated industries that require OAuth could not use Kafka ESM with their clusters. With OAuth support, customers can use their enterprise identity provider, such as <a href="https://aws.amazon.com/cognito/">Amazon Cognito</a> or Okta,&nbsp;to authenticate their Kafka ESM and apply the same identity governance and access policies across their Kafka clusters and Lambda consumers.</p>
<p>This capability is available in all&nbsp;<a href="https://builder.aws.com/build/capabilities">AWS commercial Regions</a>&nbsp;where self-managed Kafka ESM is available. To use OAuth authentication, create a new Kafka ESM with your authentication configuration through the AWS Management Console, Lambda API, AWS CLI, AWS CloudFormation, or AWS SAM. To learn more, see the <a href="https://docs.aws.amazon.com/lambda/latest/dg/with-kafka.html">AWS Lambda developer guide</a> and <a href="https://aws.amazon.com/lambda/pricing/">AWS Lambda pricing</a>.&nbsp; &nbsp;&nbsp;</p>
</div>

### Amazon S3 Vectors metadata pre-filtering is now available in AWS GovCloud (US) Regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/s3-vectors-metadata-pre-filtering-in-govcloud-regions/](https://aws.amazon.com/about-aws/whats-new/2026/10/s3-vectors-metadata-pre-filtering-in-govcloud-regions/)
- **Published**: 2026-10-10 02:00:00
- **Fetched**: 2026-10-10 06:26:46

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon S3 Vectors metadata pre-filtering is now available in the AWS GovCloud (US-East) and AWS GovCloud (US-West) Regions. Pre-filtering evaluates metadata filters before running similarity search, returning up to 5x more of the matching vectors when your filter is selective. S3 Vectors also adds a prefix match operator ($startsWith) for filtering on values like paths and URLs. Together, these improvements give your retrieval-augmented generation (RAG), agentic, and semantic-search applications more complete results when you filter, so your applications return more relevant answers.</p>
<p>S3 Vectors provides native support to store and query vectors in Amazon S3, delivering purpose-built, cost-optimized vector storage and query at billion-vector scale. With this launch, indexes in new vector buckets in the AWS GovCloud (US) Regions use metadata pre-filtering by default, with no change to how you write vectors with PutVectors or run filtered queries with QueryVectors. To use pre-filtering on an existing index, update it in place with the UpdateIndexMode API. You can also compare pre-filtering against your current filtering on the same index, using a per-query parameter on QueryVectors, before you update.</p>
<p>Metadata pre-filtering is available at no additional cost in all commercial AWS Regions where Amazon S3 Vectors is available, and in the AWS China Regions. We are in the process of deploying this change and plan to complete the deployment in the coming days. To get started, use the AWS CLI, AWS SDKs, or the Amazon S3 console. To learn more, visit the Amazon S3 Vectors <a href="https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-metadata-filtering.html" rel="noopener noreferrer" target="_blank">documentation</a> and the <a href="https://aws.amazon.com/blogs/aws/amazon-s3-vectors-now-supports-metadata-pre-filtering-for-higher-recall-on-filtered-searches" rel="noopener noreferrer" target="_blank">AWS News blog</a>.</p>
<p><a href="https://signin.aws.amazon.com/signup?request_type=register">&nbsp;</a></p>
