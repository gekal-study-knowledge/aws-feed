### Amazon MSK Connect now supports updating connector plugins and worker configurations

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-msk-connect-update-plugin-worker-configurations](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-msk-connect-update-plugin-worker-configurations)
- **Published**: 2026-10-30 00:00:00
- **Fetched**: 2026-10-30 11:22:45

<div class="entry-summary">
<p><a href="https://aws.amazon.com/msk/features/msk-connect/"><u>Amazon MSK Connect</u></a> (Amazon Managed Streaming for Apache Kafka Connect) now lets you update the custom plugin and worker configuration of an existing connector. This is useful when you need to update the custom plugin to run a new version of your connector code, for example one with updated dependencies. You can also update the worker configuration to change worker-level settings, such as switching key and value converters or tuning producer and consumer properties for throughput and latency.</p> 
<p>Amazon MSK Connect is a fully managed service that allows you to deploy, monitor, and scale Apache Kafka Connect connectors with <a href="https://aws.amazon.com/msk/"><u>Amazon MSK</u></a> (Managed Streaming for Apache Kafka). Previously, updating a connector's plugin or worker configuration meant deleting the connector and recreating it - a disruptive operation that added risk and operational overhead. With this launch, you can update a connector's plugin and worker configuration in place. The connector keeps its committed offsets, so its tasks continue processing from where they left off once the update completes.</p> 
<p>This capability is available at no additional cost in all AWS Regions where Amazon MSK Connect is supported. To learn more, visit <a href="https://docs.aws.amazon.com/msk/latest/developerguide/msk-connect.html"><u>Amazon MSK Connect developer guide</u></a>.</p>
</div>

### Amazon RDS for Oracle and SQL Server now support storage autoscaling on additional storage volumes

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-rds-oracle-sqlserver-autoscaling-additional-storage-volumes](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-rds-oracle-sqlserver-autoscaling-additional-storage-volumes)
- **Published**: 2026-10-30 03:06:00
- **Fetched**: 2026-10-30 07:35:07

<div class="entry-summary">
<p><a href="https://aws.amazon.com/rds/sqlserver/" target="_blank"><u>Amazon RDS for SQL Server</u></a> and <a href="https://aws.amazon.com/rds/oracle/" target="_blank"><u>Amazon RDS for Oracle</u></a> now support RDS storage autoscaling on <a href="https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_PIOPS.ModifyingExisting.AdditionalVolumes.html" target="_blank">additional storage volumes</a>. RDS storage autoscaling automatically scales storage capacity in response to growing database workloads, with zero downtime.</p> 
<p>Additional storage volumes allow you to add up to three additional volumes to increase your storage capacity up to 256 TiB. Previously, you had to manually provision storage capacity on the additional storage volumes based on anticipated application capacity demands while autoscaling could be enabled on the primary storage volume. Under-provisioning could result in application downtime, and over-provisioning could result in under-utilized resources and&nbsp;higher costs. With RDS storage autoscaling, you simply set your desired maximum storage limit for each additional storage volume, and autoscaling takes care of the rest.</p> 
<p>RDS storage autoscaling continuously monitors actual storage consumption, and scales capacity up automatically when actual utilization approaches provisioned storage capacity. Autoscaling works with new and existing database instances. Autoscaling has no additional charges and you only pay for the provisioned storage resources. You can enable it by using the AWS Management Console, AWS CLI, or Amazon RDS API.</p> 
<p>RDS storage autoscaling for additional storage volumes is available for Amazon RDS for SQL Server and Amazon RDS for Oracle in all commercial AWS Regions and the AWS GovCloud (US) Regions. To learn more, please visit&nbsp;the <a href="https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_PIOPS.Autoscaling.html">Amazon RDS storage autoscaling</a> documentation.&nbsp;</p>
</div>

### AWS Marketplace now enables partners to list once and sell through multiple subsidiary accounts

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-marketplace-subsidiary-account-authorization](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-marketplace-subsidiary-account-authorization)
- **Published**: 2026-10-30 05:12:00
- **Fetched**: 2026-10-30 11:22:45

<div class="entry-summary">
<p>Today, AWS announces that AWS partners who operate multiple legal entities can publish a product listing once in their primary account and enable their local subsidiaries to sell it through direct private offers — eliminating the need to recreate and maintain duplicate listings across every account.</p> 
<p>From the primary account, which retains ownership of the listing, partners authorize which products each subsidiary can sell and which buyer countries it can extend private offers to. Each subsidiary transacts under its own local tax identity, selects the local currencies it supports, and sets its own disbursement preferences and bank account. The AWS Marketplace insights report in the primary account provides a consolidated view of offers, agreements, and renewals across all connected subsidiary accounts. Partners can revoke a subsidiary authorization or a subsidiary connection at any time, which immediately stops that subsidiary from creating new offers — agreements and offers already extended to buyers remain unchanged.</p> 
<p>This capability is available today at no additional cost in all AWS Regions where AWS Marketplace is available. To get started, see &nbsp;<a href="https://docs.aws.amazon.com/partner-central/latest/getting-started/manage-subsidiary.html">Managing subsidiary account connections&nbsp;</a> and &nbsp;<a href="https://docs.aws.amazon.com/marketplace/latest/userguide/subsidiary-offers.html">Creating private offers as a subsidiary account&nbsp;</a>.</p>
</div>

### AWS Glue Data Catalog now supports Apache Iceberg table optimization in the US West (N. California) Region

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/glue-data-catalog-optimizers-us-west-1/](https://aws.amazon.com/about-aws/whats-new/2026/10/glue-data-catalog-optimizers-us-west-1/)
- **Published**: 2026-10-30 17:00:00
- **Fetched**: 2026-10-31 01:30:22

<div class="entry-summary">
<p>AWS Glue Data Catalog now supports automatic table optimization for Apache Iceberg tables in the US West (N. California) Region. Apache Iceberg is an open table format that delivers fast query performance over large tables in data lakes. With this launch, you can enable table optimization for individual tables or for all tables in your Data Catalog.</p>
<p>Apache Iceberg tables accumulate small files, snapshots, and unreferenced files with every write, which slows queries and increases storage costs over time. Table optimization continuously monitors your tables to compact small files in the background, remove snapshots that are past your retention settings, and delete unreferenced files that are no longer needed. You can monitor each run from the AWS Glue console, Amazon CloudWatch metrics, and logs.</p>
<p>You can enable table optimization using the AWS Glue console, AWS CLI, or AWS SDKs. For the full list of Regions where table optimization is available, see Supported Regions for table optimizers. To learn more, see Optimizing Iceberg tables in the AWS Glue Developer Guide. To get started, visit the AWS Glue product page.</p>
</div>
