## AWS What's New

### AWS Capabilities by Region now offers availability notifications for individual features and advanced filters

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/awscapabilities-enhancements/](https://aws.amazon.com/about-aws/whats-new/2026/10/awscapabilities-enhancements/)
- **Published**: 2026-10-08 00:00:00
- **Fetched**: 2026-10-08 02:11:37

<div class="entry-summary">
<p>Today, AWS announces feature-level availability notifications and advanced filters for <a href="https://builder.aws.com/build/capabilities/explore">AWS Capabilities by Region</a> in AWS Builder Center. You can now set availability notifications for AWS service, or to an individual feature of an AWS service, in the AWS Regions you are interested in, and receive an in-app notification and a weekly email digest covering all the capabilities that became available since you enabled availability notifications. Setting availability notifications for a service covers every feature within it, and an 'All regions' option covers every Region, including AWS Regions that launch in the future.</p>
<p>In addition to the feature level availability notifications , you can now filter API operations and CloudFormation resources by availability status and compare Regions to show all capabilities, only matching ones, or only differences. With over 19,000 API operations and more than 5,000 CloudFormation resource types, these filters quickly narrow a full listing down to the exact differences between Regions, working alongside search and existing display preferences.&nbsp;</p>
<p>Comparing capabilities in AWS Capabilities by Region requires no account. Setting up availability notifications requires a Builder ID, which is free. To get started, visit <a href="https://builder.aws.com/build/capabilities/explore">AWS Capabilities by Region</a> on AWS Builder Center. To learn more, explore the <a href="https://builder.aws.com/faq#aws-capabilities-by-region">AWS Builder Center FAQ</a></p>
</div>

## AWS Security Bulletins

### CVE-2026-105811 - Authorization bypass through a user-controlled key in the Amazon Q Business Lambda hook sample in QnABot on AWS

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-126-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-126-aws/)
- **Published**: 2026-10-08 03:25:26
- **Fetched**: 2026-10-08 07:36:43

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-126-AWS
 <br />
 <b>Scope:</b> AWS
 <br />
 <b>Content Type:</b> Important (requires attention)
 <br />
 <b>Publication Date:</b> 10/06/2026 13:00 PM PDT</p>
<p><b>Description:</b></p>
<p>QnABot on AWS is a sample solution of a multi-channel, multi-language conversational interface (chatbot) that responds to your customer's questions, answers, and feedback. We identified CVE-2026-105811 in the optional Amazon Q Business Lambda hook sample of QnABot on AWS. The Amazon Q Business Lambda hook sample (q-business-lambda-hook) is an optional integration sample included in the QnABot on AWS repository. It requires separate, manual deployment and additional setup; it is not deployed automatically with QnABot. Customers who have not deployed this sample are not affected and do not need to take action.</p>
<p>Authorization bypass through a user-controlled key in the sample included with QnABot on AWS versions 7.0.0 through 7.4.5 might allow an authenticated remote user to read arbitrary Amazon S3 objects in the deploying AWS account.</p>
<p>To remediate this issue, affected customers should update the QnABot on AWS stack to version 7.4.6 or later and then redeploy the Amazon Q Business Lambda hook sample stack. Updating the QnABot on AWS stack alone does not deliver the fix.</p>
<p><b>Impacted versions:</b> &gt;=7.0.0, &lt;7.4.6</p>
<p><b>Please refer to the article below for the most up-to-date and complete information related to this AWS Security Bulletin.</b></p>
</div>

### CVE-2026-107352 - Missing authorization checks in Amazon Athena engine version 3 request handling

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-128-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-128-aws/)
- **Published**: 2026-10-08 05:19:18
- **Fetched**: 2026-10-08 07:36:43

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-128-AWS
 <br />
 <b>Scope:</b> AWS
 <br />
 <b>Content Type:</b> Important (requires attention)
 <br />
 <b>Publication Date:</b> 10/07/2026 13:00 PM PDT</p>
<p><b>Description:</b></p>
<p>Missing authorization checks in Amazon Athena engine version 3 request handling could have allowed an authenticated user to read limited query metadata (AWS account identifiers and SQL statement text) from other AWS accounts. AWS remediated the issue on September 1, 2026, and has confirmed no customer metadata was accessed. Query results, credentials, and Amazon S3 data were not affected. No customer action is required.</p>
<p><b>Resolution:</b></p>
<p>This issue was addressed service-side on September 1, 2026.</p>
<p><b>Please refer to the article below for the most up-to-date and complete information related to this AWS Security Bulletin.</b></p>
