### Amazon OpenSearch Service now supports index-level encryption

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/opensearch-index-level-encryption](https://aws.amazon.com/about-aws/whats-new/2026/10/opensearch-index-level-encryption)
- **Published**: 2026-10-12 11:30:00
- **Fetched**: 2026-10-13 08:26:39

<div class="entry-summary">
<p>Amazon OpenSearch Service now supports index-level encryption, letting you encrypt each index at rest with its own AWS Key Management Service (AWS KMS) customer managed key.&nbsp;This helps you protect data with different ownership or sensitivity under separate keys on the same domain. For example, you can encrypt each tenant's data with its own key in a multi-tenant application.</p>
<p>Index-level encryption builds on the existing encryption at rest capability in Amazon OpenSearch Service. To enable it, set the encryption mode to Native and specify a customer managed AWS KMS key when you create a new domain using the AWS Management Console or the AWS CLI. You can then register additional keys with the domain and use them to encrypt individual indexes.</p>
<p>Index-level encryption is available for domains running OpenSearch version 3.3 or later in 14 AWS Regions: US East (N. Virginia, Ohio), US West (Oregon), Canada (Central), Asia Pacific (Mumbai, Seoul, Singapore, Sydney, Tokyo), Europe (Frankfurt, Ireland, London, Paris), and South America (São Paulo).&nbsp;There is no additional charge for the feature. Standard AWS KMS and OpenSearch Service charges apply.</p>
<p>To get started, see <a href="https://docs.aws.amazon.com/opensearch-service/latest/developerguide/index-level-encryption.html" target="_blank" title=" Index-level encryption">Index-level encryption</a> in the Amazon OpenSearch Service Developer Guide.</p>
</div>

### AWS Secrets Manager adds managed external secrets support for Databricks and Twilio

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/secrets-manager-managed-external-secrets-databricks-twilio/](https://aws.amazon.com/about-aws/whats-new/2026/10/secrets-manager-managed-external-secrets-databricks-twilio/)
- **Published**: 2026-10-12 16:00:00
- **Fetched**: 2026-10-13 08:26:39

<div class="entry-summary">
<p>AWS Secrets Manager now extends its managed external secrets capability to include Databricks and Twilio, enabling you to automatically rotate the credentials that your data pipelines and messaging applications use to call these services. You set up rotation directly from the AWS Management Console or API without writing or maintaining any custom rotation Lambda functions.</p>
<p>Long-lived credentials often stay unrotated because rotation is hard to set up and hard to distribute safely to the applications that use the updated credential. With managed external secrets, you can use Secrets Manager to rotate the Databricks personal access tokens that your jobs and continuous integration and continuous delivery (CI/CD) pipelines use. You can also rotate the service principal OAuth client secrets that your automation workflows use. Each replacement personal access token retains the scopes of the token it replaces, so a narrowly scoped token stays narrowly scoped.</p>
<p>For Twilio, you can use Secrets Manager to rotate the API keys and Auth Tokens that your applications use to send messages and place calls. For both services, you store the credential in Secrets Manager as a managed external secret and set a rotation schedule. Secrets Manager always returns the current credential, so your applications pick up rotated values automatically, with no code changes required.</p>
<p>These integrations join existing managed external secrets support for BigID, Cisco Security Platform, Confluent Cloud, Datadog, GitLab, Jenkins, MongoDB Atlas, Netskope, Paddle, Salesforce, Snowflake, and SonarQube.</p>
<p>Databricks and Twilio managed external secrets are available in all AWS Regions where AWS Secrets Manager managed external secrets is supported. To learn more, visit the &nbsp;<a href="https://docs.aws.amazon.com/secretsmanager/latest/userguide/managed-external-secrets.html">AWS Secrets Manager managed external secrets documentation</a>.</p>
</div>

### Amazon EMR now supports native data quality checks in Apache Spark jobs

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-emr-data-quality-spark/](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-emr-data-quality-spark/)
- **Published**: 2026-10-12 16:00:00
- **Fetched**: 2026-10-13 08:26:39

<div class="entry-summary">
<p>Amazon EMR now validates data quality natively within Apache Spark jobs. Data engineering teams can catch quality issues inline before bad data reaches downstream systems, without building or maintaining separate validation infrastructure. Amazon EMR Data Quality, powered by AWS Glue, is available at no additional cost and uses the same declarative rules language (Data Quality Definition Language) and APIs as AWS Glue for a consistent experience across both engines, and works with Apache Iceberg, Apache Hudi, and Delta Lake across EC2, EKS, and Serverless deployment modes.</p>
<p>With this feature, you can author validation rules in your Spark scripts or reference rules stored in the AWS Glue Data Catalog, and then apply them at any stage of your pipeline i.e., after reading data, during transformation, or after processing. With 30+ rule types, including dynamic rules that compare against historical runs and ML-based anomaly detection for tracking drift over time without specifying fixed thresholds, Amazon EMR Data Quality provides the flexibility of choosing the validation framework that fits your needs. You can take actions like failing a pipeline, filtering invalid records, or routing them to quarantine based on the quality evaluation results. Results are produced at the dataset, rule, and row level, so that you can easily identify which records or rules are driving the quality failures.</p>
<p>Amazon EMR Data Quality is available on AWS runtime for Apache Spark (emr-spark-8.1.0) in all AWS Commercial, and AWS GovCloud (US) Regions where Amazon EMR is available.</p>
<p>To get started, visit Amazon EMR Data Quality <a href="https://docs.aws.amazon.com/emr/latest/ManagementGuide/emr-data-quality.html">documentation</a> and add DQDL rules for data quality validation to the Spark scripts of your EMR workloads.</p>
</div>

### Amazon ElastiCache for Valkey introduces ElastiCache Insights

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-elasticache-valkey-elasticache-insights/](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-elasticache-valkey-elasticache-insights/)
- **Published**: 2026-10-12 16:00:00
- **Fetched**: 2026-10-13 08:26:39

<div class="entry-summary">
<p><a href="https://aws.amazon.com/elasticache/">Amazon ElastiCache</a> for Valkey now features ElastiCache Insights, a pre-built dashboard in Amazon CloudWatch for your node-based clusters. ElastiCache Insights brings cluster health, memory, compute, network, command throughput, latency, keyspace, and errors into a single view sourced from a set of OpenTelemetry metrics that ElastiCache publishes automatically.</p>
<p>You can use ElastiCache Insights to check the health of your cache workloads across a Region at a glance, detect when a node nears its memory, network, or connection limits, and filter your view to a cluster, shard, node, or Availability Zone. You can also save a copy as the starting point for a custom dashboard tailored to your workload.</p>
<p>With detailed monitoring, you can choose metrics to publish every 15 seconds and view them on the Metrics tab or in your custom dashboard. <a href="https://aws.amazon.com/cloudwatch/pricing/">CloudWatch pricing for OpenTelemetry metrics</a> applies to ElastiCache detailed monitoring.</p>
<p>To get started, open the Metrics tab for a cluster in the <a href="https://console.aws.amazon.com/elasticache/">Amazon ElastiCache console</a> and choose View in ElastiCache Insights. You can also choose ElastiCache Insights under Infrastructure Monitoring in the Amazon CloudWatch console.</p>
<p>ElastiCache Insights is available for node-based Valkey clusters in all AWS Regions where Amazon CloudWatch supports OpenTelemetry metrics. To learn more about ElastiCache Insights, see <a href="https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/otel-metrics.html#otel-metrics.insights-dashboard">Monitoring ElastiCache with OpenTelemetry metrics</a> in the Amazon ElastiCache User Guide.</p>
</div>

### AWS Transfer Family supports custom ports for public SFTP servers

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/transfer-family-custom-ports-sftp/](https://aws.amazon.com/about-aws/whats-new/2026/10/transfer-family-custom-ports-sftp/)
- **Published**: 2026-10-12 17:00:00
- **Fetched**: 2026-10-13 08:26:39

<div class="entry-summary">
<p>AWS Transfer Family now lets you configure custom ports on public SFTP servers and choose a communication mode for each port. You can support clients that require different ports or start SFTP connections differently on a single server.</p>
<p>Previously, public SFTP servers accepted connections only on port 22 and used server-first communication. With this launch, you can configure up to three ports (22, or any port from 2000 to 65535), allowing you to use the port numbers your business or network requires and offer multiple ports on one server. Some SFTP clients initiate communication themselves, and their connections can occasionally stall on a server-first port. For each port, you can now select client-first or server-first communication and direct clients to the port that matches their connection behavior. Using a port other than 22 can also reduce unwanted connection attempts from automated scanners that target port 22.</p>
<p>This capability is available in all AWS Regions where Transfer Family public SFTP servers are offered. To get started, visit the AWS Transfer Family console or use the AWS CLI or AWS SDKs. To learn more, visit Create an SFTP-enabled server in the <a href="https://docs.aws.amazon.com/transfer/latest/userguide/create-server-sftp.html">AWS Transfer Family User Guide</a></p>
</div>
