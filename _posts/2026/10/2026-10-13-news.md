### Announcing consumption-based pricing for short-term memory in Amazon Bedrock AgentCore

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/agentcore-memory-consumption-based-pricing](https://aws.amazon.com/about-aws/whats-new/2026/10/agentcore-memory-consumption-based-pricing)
- **Published**: 2026-10-13 01:00:00
- **Fetched**: 2026-10-13 08:26:39

<div class="entry-summary">
<p><b>Announcing consumption-based pricing for short-term memory in Amazon Bedrock AgentCore</b></p>
<p>Amazon Bedrock AgentCore memory now prices short-term memory (STM) based on the data your agents ingest, retrieve, and store, replacing the previous flat rate per event. AgentCore memory gives agents in-session context through short-term memory and persistent knowledge across sessions through long-term memory. With consumption-based pricing, developers building agents that write frequent, small events pay in proportion to what they use.</p>
<p>STM is priced across three dimensions: ingestion at $1.00 per GB, retrieval at $0.20 per GB, and storage at $0.10 per GB-month. Ingestion and retrieval are billed per event with a 12 KB minimum and 64 KB maximum billable size, while storage is billed on each event's actual size. Most workloads see lower costs, with small-payload use cases seeing the largest reductions. You can manage storage costs by setting a shorter time to live (TTL) on your memory resources. Long-term memory pricing is unchanged.</p>
<p>Consumption-based pricing for AgentCore Memory short-term memory is available in all AWS Regions where AgentCore Memory is offered. To get started, visit the <a href="https://aws.amazon.com/bedrock/agentcore/pricing/">Amazon Bedrock AgentCore pricing page</a>.</p>
</div>

### AWS Lambda announces Lambda Web Functions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-lambda-web-functions/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-lambda-web-functions/)
- **Published**: 2026-10-13 04:30:00
- **Fetched**: 2026-10-13 08:26:39

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS Lambda announces Lambda Web Functions, a new serverless compute primitive where your code handles HTTP requests directly. Your code listens on a port and handles requests as it would on any HTTP server. You use frameworks you already know, such as Express or Hono, with no adapters or custom configuration. This enables you to serve workloads such as AI inference endpoints, server-side rendered (SSR) web apps, streaming API endpoints, microservices, and webhooks. You pay for active CPU time and the memory your environment holds, not for idle CPU time your code spends waiting on databases or downstream services. With this launch, we are also renaming existing Lambda functions to Lambda Event Functions, a naming change only that requires no code changes or redeployments for your existing functions.</p>
<p>Builders use Lambda to go from code to production quickly and without managing servers, across event-driven pipelines, request-response APIs, and data processing. As AI-driven development accelerates, they want to build locally and deploy with a familiar programming model and pay for workloads based on active CPU usage, while serving users with low latency. Lambda Web Functions delivers this. Today, Lambda Web Functions supports the Node.js runtime. A single warm execution environment can serve multiple concurrent requests, which reduces cold starts by orders of magnitude. You can stream results to clients incrementally with native HTTP streaming.</p>
<p>You can create and configure Lambda Web Functions using the AWS Lambda API, <a href="https://docs.aws.amazon.com/lambda/latest/dg/agent-setup-guide.html">Agent Toolkit for AWS</a>, AWS Management Console, AWS CLI, AWS CloudFormation, AWS SAM, AWS CDK, or the AWS SDKs. With multi-Region routing, you can deploy once and serve each request from the Region closest to the end user. Web Functions support <a href="https://docs.aws.amazon.com/lambda/latest/dg/web-functions-networking.html">Amazon Virtual Private Cloud (VPC)</a> connectivity, allowing your function to access resources that exist within a VPC.</p>
<p>Lambda Web Functions is available today in the following AWS Regions: US East (N. Virginia), US East (Ohio), US West (Oregon), Asia Pacific (Tokyo), and Europe (Ireland). For the current list, see the <a href="https://builder.aws.com/build/capabilities">AWS Capabilities by Region</a> page. To learn more, see the <a href="https://docs.aws.amazon.com/lambda/latest/dg/web-functions.html">Lambda Web Functions developer guide</a>. For pricing details, see <a href="https://aws.amazon.com/lambda/pricing/">AWS Lambda Pricing</a>.  To see Lambda Web Functions in action, see the <a href="https://aws.amazon.com/blogs/aws/announcing-aws-lambda-web-functions-for-fast-consistent-web-app-performance-anywhere/">AWS News Blog announcement</a>.</p>
</details>

### Amazon Connect Customer now prefills step-by-step guides for after contact work

### Amazon CloudFront now supports AWS Lambda Web Functions as an origin

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/cloudfront-lambda-web-functions-origin/](https://aws.amazon.com/about-aws/whats-new/2026/10/cloudfront-lambda-web-functions-origin/)
- **Published**: 2026-10-13 08:10:00
- **Fetched**: 2026-10-13 14:15:44

<div class="entry-summary">
<p>Starting today, you can deliver web applications built on AWS Lambda Web Functions through CloudFront's global edge network. &nbsp;</p>
<p>With CloudFront in front of a Lambda Web Function, you get TLS termination at the edge for lower latency and faster connections, caching for better performance, and custom domains with managed TLS certificates. No changes to application code are needed. CloudFront Origin Access Control (OAC) restricts your Lambda Web Function so it's reachable only through CloudFront, so unintended requests that bypass your security protections do not reach your origin. With OAC in place, CloudFront's edge network protects your Lambda Web Function from network-layer DDoS attacks, and you can attach AWS WAF for additional application-layer security. For applications that authenticate their own users, OAC ensures that original credentials reach the application unchanged, so existing sign-in flows keep working.</p>
<p>CloudFront support for AWS Lambda Web Functions is available worldwide, except in the CloudFront China region. To get started, use the CloudFront Console, SDK, CLI, or CloudFormation to configure your Lambda Web Function as a CloudFront origin. For more information, refer to the <a href="https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-lambda-web.html" rel="noopener noreferrer" target="_blank">CloudFront Developer Guide</a>. There are no additional fees associated with this feature.</p>
</div>

### AWS DataSync Enhanced mode now supports FSx for OpenZFS, NFS 4.2, and object metadata controls

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/datasync-enhanced-openzfs-nfs42-metadata/](https://aws.amazon.com/about-aws/whats-new/2026/10/datasync-enhanced-openzfs-nfs42-metadata/)
- **Published**: 2026-10-13 17:00:00
- **Fetched**: 2026-10-14 05:02:49

<div class="entry-summary">
<p>AWS DataSync Enhanced mode now supports Amazon FSx for OpenZFS as a source or destination location, NFS version 4.2 for on-premises NFS servers and FSx for OpenZFS file systems, and a new ObjectMetadata option for object storage transfers. Previously, customers transferring data to or from FSx for OpenZFS were limited to Basic mode.</p>
<p>NFS 4.2 lets you transfer data from NFS servers on the latest version without reconfiguring them to an older protocol version. The ObjectMetadata option gives you control over whether an object's user metadata is copied to the destination, which helps when destination metadata must stay intact, such as buckets served by AWS Storage Gateway, or when source metadata keys are not compatible with the destination, such as Azure Blob Storage. Existing tasks remain unaffected and continue to run as scheduled.</p>
<p>These capabilities are available for Enhanced mode tasks in all AWS Regions where AWS DataSync Enhanced mode is supported. To learn more, visit the <a href="https://docs.aws.amazon.com/datasync/latest/userguide/what-is-datasync.html">AWS DataSync documentation</a>.</p>

### Amazon Route 53 now supports registrations, transfers, and renewals for Premium Domains

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/route-53-premium-domains/](https://aws.amazon.com/about-aws/whats-new/2026/10/route-53-premium-domains/)
- **Published**: 2026-10-13 17:00:00
- **Fetched**: 2026-10-14 09:05:44

<div class="entry-summary">
<p>Amazon Route 53 Domains now supports Premium Domain Names. Customers can now search for, register, transfer, renew, and restore registry premium names directly through Route 53.</p>
<p>Most domain registries set aside a selection of "premium" domains - names that are short, memorable, or in high demand. Previously, Route 53 Domains did not support these premium names, which meant customers who wanted them had to register and manage them through other registrars, fragmenting their portfolios across multiple providers. With this launch, customers can now discover and acquire premium domains directly in Route 53 Domains, consolidate their existing premium domains from other registrars, and manage premium and standard domains together through a single, unified experience. Finding and registering a premium domain works just like it does for standard domains. Premium domains appear automatically in domain search and availability results, with pricing shown upfront, so customers know the cost before they commit.</p>
<p>To learn more about Amazon Route 53 Domains and start registering premium domains, visit the <a href="https://aws.amazon.com/route53/domains/" rel="noopener noreferrer" target="_blank">Amazon Route 53 Domains page</a>. For a complete list of supported top-level domains, see the <a href="https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/registrar-tld-list.html" rel="noopener noreferrer" target="_blank">Route 53 TLD list</a>.</p>
