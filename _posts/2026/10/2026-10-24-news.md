### AWS Transit Gateway and AWS Cloud WAN now support 1:1 NAT

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-transit-gateway-cloud-wan-1-1-nat/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-transit-gateway-cloud-wan-1-1-nat/)
- **Published**: 2026-10-24 00:43:00
- **Fetched**: 2026-10-24 03:51:42

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS Transit Gateway and AWS Cloud WAN now provide managed one-to-one network address translation (NAT) directly on their attachments, through integration with Regional Private NAT Gateway. This enables customers to connect private networks that share the same IP address ranges without renumbering either network, deploying a NAT appliance, or writing return-traffic rules.</p> 
<p>Networks with overlapping Classless Inter-Domain Routing (CIDR) blocks have long been unable to communicate, a common blocker during mergers and acquisitions, when connecting partner networks over AWS Site-to-Site VPN, in multicloud connectivity, and when independently provisioned VPCs need to interconnect. Using this capability, customers can define address-translation rules on a AWS Transit Gateway or AWS Cloud WAN attachment, specifying the private IP range each source CIDR translates to, across Amazon VPC, AWS Site-to-Site VPN, AWS Direct Connect, and SD-WAN appliances connected through Transit Gateway Connect. Both services apply translation automatically in both directions, with no separate return-traffic rule and no NAT appliance to deploy. AWS operates, scales, and manages the NAT capability as part of the attachment. For example, if a customer acquires a business and both VPCs use 10.0.0.0/16, they translate one VPC's addresses to a non-overlapping range on its attachment and connect the networks immediately. Customers set it up in minutes using the AWS Management Console, AWS Command Line Interface (AWS CLI), AWS SDKs, and AWS CloudFormation, and monitor translated traffic through Amazon CloudWatch metrics and Amazon EventBridge events.</p> 
<p>AWS Transit Gateway and AWS Cloud WAN offer 1:1 NAT through Regional Private NAT Gateway in all AWS commercial&nbsp;regions where they operate. For full pricing details, see &nbsp;<a href="https://aws.amazon.com/vpc/pricing/">Amazon VPC pricing&nbsp;</a>. To learn more, see the &nbsp;<a href="https://aws.amazon.com/transit-gateway/">AWS Transit Gateway&nbsp;</a> and &nbsp;<a href="https://aws.amazon.com/cloud-wan/">AWS Cloud WAN&nbsp;</a> product pages, and the <a href="https://docs.aws.amazon.com/vpc/latest/tgw/">AWS Transit Gateway&nbsp;</a> and <a href="https://docs.aws.amazon.com/network-manager/latest/cloudwan/what-is-cloudwan.html">AWS Cloud WAN&nbsp;</a> documentation.</p>
</details>

### Amazon Connect Customer Global Resiliency now supports persistent chat across linked AWS Regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-connect-global-resiliency-persistent-chat](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-connect-global-resiliency-persistent-chat)
- **Published**: 2026-10-24 02:00:00
- **Fetched**: 2026-10-24 06:48:51

<div class="entry-summary">
<p>Amazon Connect Customer Global Resiliency now provides customers a mechanism to deliver long, persistent chat experiences across linked AWS Regions. With this capability, end users can resume previous conversations with full context, metadata, and transcripts carried over across Regions, eliminating the need for end users to repeat information and allowing agents to provide personalized service with access to the entire conversation history across AWS Regions.</p> 
<p>For example, an end user can start a chat in US-East (N. Virginia) and later come back to it in the linked US-West (Oregon) Region, continuing the same conversation with an agent with full conversation history&nbsp;and&nbsp;chat attachment. To adopt this capability, onboard to <a href="https://docs.aws.amazon.com/connect/latest/adminguide/global-routing-across-acgr-regions.html">Global routing</a>.</p> 
<p>This feature is available in all AWS Regions where <a href="https://docs.aws.amazon.com/connect/latest/adminguide/get-started-connect-global-resiliency.html">Amazon Connect Customer Global Resiliency</a> is supported. To learn more, visit <a href="https://docs.aws.amazon.com/connect/latest/adminguide/setup-connect-global-resiliency.html">Amazon Connect Customer Admin Guide</a>.</p>
</div>

<p><b>Description:</b></p> 
<p>Amazon Web Services Multi Model Server (MMS) is an open source tool for serving machine learning models for inference. It was published by AWS on GitHub, PyPI, and Docker Hub, and reached end of life; its source repository has been archived and read-only since November 20, 2025.</p> 
<p><b>CVE-2026-115812:</b> An issue in model archive extraction could allow a crafted model archive to write files outside the intended directory, potentially resulting in code execution with the privileges of the MMS process.</p> 
<p><b>CVE-2026-115813:</b> An issue in the model download path could allow the MMS management interface to be directed to make requests to unintended network destinations.</p>

### CVE-2026-115845 - Incomplete validation in the run_script Python sandbox in AWS MCP Server

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-149-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-149-aws/)
- **Published**: 2026-10-24 04:09:22
- **Fetched**: 2026-10-24 06:48:53

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-149-AWS<br /> <b>Scope:</b> AWS<br /> <b>Content Type:</b> Important (requires attention)<br /> <b>Publication Date:</b> 10/23/2026 12:00 PM PDT</p> 
<p><b>Description:</b></p> 
<p>AWS MCP Server is a managed server that gives AI agents access to AWS through the Model Context Protocol (MCP), including a run_script tool that runs Python scripts in a sandboxed environment.</p> 
<p>We identified CVE-2026-115845, an issue in the Python code validator of the run_script tool in AWS MCP Server. An incomplete list of disallowed inputs might allow an authenticated remote user to execute arbitrary code within their own isolated session environment via a crafted script.</p> 
<p><b>Impacted versions:</b> N/A (managed service, exclusively hosted)</p> 
<p><b>Please refer to the article below for the most up-to-date and complete information related to this AWS Security Bulletin.</b></p>
