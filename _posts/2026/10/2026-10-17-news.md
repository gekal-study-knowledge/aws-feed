### Beam model by Reflection is now available on Amazon SageMaker JumpStart and AWS Trainium

### Nemotron 3.5 Super VL model now available on Amazon SageMaker JumpStart

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/01/nvidia-nemotron-3.5-super-vl-on-sagemaker-jumpstart/](https://aws.amazon.com/about-aws/whats-new/2026/01/nvidia-nemotron-3.5-super-vl-on-sagemaker-jumpstart/)
- **Published**: 2026-10-17 02:59:00
- **Fetched**: 2026-10-17 04:14:39

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>NVIDIA's Nemotron 3.5 Super VL is now available on Amazon SageMaker JumpStart, expanding the portfolio of foundation models available to AWS customers. This vision-language model from the Nemotron 3.5 family accepts images, video, and text as input and generates text, enabling customers to deploy multimodal AI solutions on AWS infrastructure.</p>
<p>Nemotron 3.5 Super VL is designed for document intelligence, GUI understanding, video question answering, and multimodal agentic applications. It pairs a 120B-parameter hybrid Mixture-of-Experts (MoE) language backbone with 12B active parameters and a vision encoder, supporting context lengths of up to 1 million tokens. The model includes a built-in Multi-Token Prediction (MTP) head for speculative decoding to accelerate text generation, with reasoning configurable per request. It supports ten languages including English, French, Spanish, German, Japanese, Hindi, Korean, and Chinese. Post-trained with multimodal supervised fine-tuning on image, video, document, chart, and GUI data followed by GRPO reinforcement learning, it delivers structured JSON output, tool calling, and configurable reasoning for enterprise agent workflows. SageMaker JumpStart offers two variants: NVFP4 for optimized inference on G7 instances with NVIDIA RTX PRO 4500 Blackwell Server Edition GPUs, and BF16 reference weights on ml.p5en.48xlarge for customization including SFT, RL, distillation, and domain adaptation.</p>
<p>With SageMaker JumpStart, customers can deploy Nemotron 3.5 Super VL with just a few clicks to address their specific AI use cases.</p>
<p>To get started with these models, navigate to the SageMaker JumpStart model catalog in the SageMaker console or use the SageMaker Python SDK to deploy the models to your AWS account. For more information about deploying and using foundation models in SageMaker JumpStart, see the <a href="https://docs.aws.amazon.com/sagemaker/latest/dg/studio-jumpstart.html">Amazon SageMaker JumpStart documentation</a>.</p>
</details>

### Amazon EMR Serverless now supports IPv6 and dual-stack connectivity

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-emr-serverless/](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-emr-serverless/)
- **Published**: 2026-10-17 04:20:00
- **Fetched**: 2026-10-20 07:47:09

<div class="entry-summary">
<p>Amazon EMR Serverless now supports IPv6 and dual-stack connectivity, expanding beyond the IPv4-only connectivity that was previously available. You can now run your Apache Spark and Apache Hive jobs over IPv6 in your Amazon Virtual Private Cloud (VPC) by supplying dual-stack (IPv4 and IPv6) or IPv6-only subnets. This gives you greater flexibility in how your applications connect to data stores and services, while maintaining full backward compatibility with your existing IPv4 workloads.</p>
<p>As Spark and Hive workloads scale to many workers, the IPv4 address space in your VPCs and subnets can become a constraint, and a growing number of organizations face compliance mandates that require IPv6 adoption. With dual-stack connectivity, your EMR Serverless applications accept both IPv4 and IPv6, making it easy to adopt IPv6 gradually while maintaining backward compatibility with your existing IPv4 workloads. With IPv6-only subnets, you can eliminate the need for IPv4 addresses entirely, overcoming IPv4 address exhaustion and meeting the networking standards and compliance requirements that call for IPv6, while your jobs reach IPv6 endpoints and services both inside and outside your VPC.</p>
<p>IPv6 and dual-stack connectivity for Amazon EMR Serverless is available at no additional cost in all AWS Regions where Amazon EMR Serverless is available. IPv6 and dual-stack subnets are supported on all EMR Serverless release versions. To get started, see <a href="https://docs.aws.amazon.com/emr/latest/EMR-Serverless-UserGuide/ipv6-subnets.html">Configure IPv6 subnets for EMR Serverless applications</a> and <a href="https://docs.aws.amazon.com/emr/latest/EMR-Serverless-UserGuide/vpc-access.html">Configuring VPC access for EMR Serverless applications</a>.</p>
</div>

### CVE-2026-102551 & CVE-2026-102552 - Issue with FreeRTOS-Plus-TCP

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-139-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-139-aws/)
- **Published**: 2026-10-17 02:34:49
- **Fetched**: 2026-10-17 04:14:40

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-139-AWS
 <br />
 <b>Scope:</b> AWS
 <br />
 <b>Content Type:</b> Important (requires attention)
 <br />
 <b>Publication Date:</b> 10/16/2026 10:15 AM PDT</p>
<p><b>Description:</b></p>
<p>FreeRTOS-Plus-TCP is an open-source, thread-safe TCP/IP stack for the FreeRTOS kernel, distributed by Amazon for use on embedded and IoT devices. AWS identified two issues with FreeRTOS-Plus-TCP, affecting multiple versions.</p>
<p><b>CVE-2026-102551:</b> improper verification of the source of a communication channel in the IPv6 Router Advertisement handler. The handler does not fully validate that a received Router Advertisement originates from an on-link source before acting on it. Under certain conditions, a remote third-party might influence an endpoint's IPv6 gateway, prefix, and address configuration, potentially enabling interception of the device's IPv6 traffic. This issue is reachable in the library's default configuration, where ipconfigUSE_IPv6 and ipconfigUSE_RA are both enabled.</p>
<p><b>CVE-2026-102552:</b> improper verification of the source of a communication channel in the DNS resolver. The resolver does not fully validate that a DNS reply originates from the server that was queried before accepting it. Under certain conditions, a remote third-party might insert a chosen address into the device's DNS cache, potentially redirecting the device's subsequent connections for the affected name.</p>
<p><b>Impacted versions:</b></p>
<p>- CVE-2026-102551 (Router Advertisement): &lt;= V4.4.1
 <br />
 - CVE-2026-102552 (DNS resolver): &lt;= V4.4.1</p>
<p><b>Please refer to the article below for the most up-to-date and complete information related to this AWS Security Bulletin.</b></p>

### CVE-2026-109587 & CVE-2026-109588 - Issue with FreeRTOS-Kernel

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-138-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-138-aws/)
- **Published**: 2026-10-17 02:34:49
- **Fetched**: 2026-10-17 04:14:40

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-138-AWS
 <br />
 <b>Scope:</b> AWS
 <br />
 <b>Content Type:</b> Important (requires attention)
 <br />
 <b>Publication Date:</b> 10/16/2026 10:00 AM PDT</p>
<p><b>Description:</b></p>
<p>FreeRTOS-Kernel is a real-time operating system kernel for microcontrollers and small microprocessors, distributed by Amazon. AWS identified two issues with the FreeRTOS-Kernel Arm Cortex-R82 (Armv8-R AArch64) MPU port, affecting multiple versions.</p>
<p><b>CVE-2026-109587:</b> incorrect authorization in the Arm Cortex-R82 MPU port. On MPU-enabled builds, the port does not correctly enforce the memory-region boundaries assigned to an unprivileged task when it passes a buffer argument to an MPU system call. Under certain conditions, an unprivileged task might read and write privileged kernel memory outside the regions assigned to it. This issue affects Arm Cortex-R82 builds with configENABLE_MPU=1; applications that do not use the FreeRTOS MPU are not affected.</p>
<p><b>CVE-2026-109588:</b> numeric truncation in the MPU buffer authorization check on the Arm Cortex-R82 MPU port. On MPU-enabled builds, the buffer-length validation does not correctly account for the full length of a buffer passed to a stream buffer system call. Under certain conditions, an unprivileged task might read or write privileged kernel memory beyond the validated buffer window. This issue affects Arm Cortex-R82 builds with configENABLE_MPU=1; applications that do not use the FreeRTOS MPU are not affected.</p>
<p><b>Impacted versions:</b></p>
<p>- CVE-2026-109587 (MPU region authorization): V11.3.0 and V11.3.1 (Arm Cortex-R82 builds with configENABLE_MPU=1)
 <br />
 - CVE-2026-109588 (MPU buffer length truncation): V11.3.0 and V11.3.1 (Arm Cortex-R82 builds with configENABLE_MPU=1)</p>
<p><b>Please refer to the article below for the most up-to-date and complete information related to this AWS Security Bulletin.</b></p>
