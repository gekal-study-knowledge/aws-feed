### AWS Lambda durable functions now exports live telemetry for execution insights

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/lambda-durable-telemetry/](https://aws.amazon.com/about-aws/whats-new/2026/10/lambda-durable-telemetry/)
- **Published**: 2026-10-29 03:00:00
- **Fetched**: 2026-10-29 08:51:21

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS Lambda announces the Durable Execution Telemetry Exporter plugin for Lambda durable functions. This new observability plugin captures the step-by-step history of your durable executions and sends them to one or more destinations of your choice. You can use the exported data to gather operational and business insights and keep history beyond the standard retention period. We are also releasing a companion Model Context Protocol (MCP) server that lets AI agents such as Kiro query your exported telemetry data using natural language.</p> 
<p>Lambda durable functions helps you build resilient multi-step applications and AI workflows that run for up to one year. The new Telemetry Exporter sends data such as execution status, operation timing, step input and output, and errors to 13 built-in destinations. Destinations include Amazon CloudWatch Logs, Amazon S3 for Amazon Athena, Amazon DynamoDB, Amazon Aurora, and Amazon OpenSearch Service. You can redact sensitive fields before export and set a sampling rate to control data volume. With the MCP server, an on-call engineer can ask an AI agent to list recent failed executions and find the cause of a failure, and a business analyst can find all transactions for a specific customer.</p> 
<p>The exporter is available for TypeScript, Python, Java, and Go. To get started, <a href="https://docs.aws.amazon.com/durable-execution/sdk-reference/observability/telemetry/exporter/">install</a> the exporter, register the plugin in your function handler, then <a href="https://docs.aws.amazon.com/durable-execution/sdk-reference/observability/telemetry/mcp/">add</a> the MCP server to your agent.</p> 
<p>The Durable Execution Telemetry Exporter is available at no additional charge in all AWS Regions that support Lambda durable functions. To learn more, see the Durable Execution SDK <a href="https://docs.aws.amazon.com/durable-execution/sdk-reference/observability/telemetry/">documentation</a> and the <a href="https://aws.amazon.com/blogs/compute/observing-aws-lambda-durable-functions-with-the-durable-execution-telemetry-exporter/">blog post</a>.</p>

### Amazon ECS Managed Instances adds cross-instance and Spot consolidation

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/ecs-managed-instances-consolidation/](https://aws.amazon.com/about-aws/whats-new/2026/10/ecs-managed-instances-consolidation/)
- **Published**: 2026-10-29 03:00:00
- **Fetched**: 2026-10-29 08:51:21

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Today, <a href="https://aws.amazon.com/ecs/managed-instances/">Amazon Elastic Container Service (Amazon ECS) Managed Instances</a> introduces two infrastructure optimization updates: cross-instance and Spot consolidation. Cross-instance consolidation evaluates tasks running across multiple underutilized instances together, packing them onto fewer instances to raise utilization and lower costs. Spot consolidation extends this capability to Spot capacity, consolidating underutilized Spot Instances after first verifying replacement capacity is available.</p>
<p>Amazon ECS Managed Instances provisions, configures, and operates right-sized Amazon EC2 instances for your workloads, balancing availability and cost. Its infrastructure optimization continuously monitors your fleet, reclaiming idle capacity and consolidating underutilized instances with graceful start-before-stop task replacement. Until now, optimization evaluated each instance in isolation for replacement, which worked well when a capacity provider was configured with diverse instance types. However, when a capacity provider was configured with a narrow range of instance types, there were fewer opportunities to consolidate multiple underutilized instances, because no single replacement could yield savings. With cross-instance consolidation, ECS now evaluates and repacks tasks across multiple instances simultaneously. For example, in our testing with a capacity provider configured for c9g instances with a minimum size of 4xlarge, running 261 tasks (each 1 vCPU, 1.94 GiB), cross-instance consolidation reduced the fleet from 19 instances (seven 4xlarge, seven 8xlarge, four 12xlarge, and one 24xlarge) to 13 instances (eight 4xlarge and five 8xlarge), while raising CPU utilization from 42% to 91% and memory utilization from 41% to 88%. Spot consolidation applies the same approach to Spot capacity, first verifying replacement capacity is available. With these enhancements, ECS Managed Instances delivers deeper cost optimization for both your On-Demand and Spot workloads.</p>
<p>Cross-instance and Spot consolidation are now available at no additional cost in all AWS Regions, and apply automatically to all existing and new ECS Managed Instances capacity providers. To learn more, see our <a href="https://docs.aws.amazon.com/AmazonECS/latest/developerguide/managed-instances-infrastructure-optimization.html">documentation</a>.</p>
</details>

### Quick now supports smart approvals for agentic actions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/quick-smart-approvals-agentic-actions/](https://aws.amazon.com/about-aws/whats-new/2026/10/quick-smart-approvals-agentic-actions/)
- **Published**: 2026-10-29 03:28:00
- **Fetched**: 2026-10-29 08:51:21

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon Quick now supports smart approvals, a review layer that reduces unnecessary approval prompts while preserving human oversight of the actions that matter most. As agents take more actions on a user's behalf, such as sending email, updating records, and creating tickets, asking a person to approve every step leads to approval fatigue and weaker oversight over time. With smart approvals, a separate review model called the classifier evaluates each eligible action against the user's request. It approves routine actions automatically and refers consequential actions to the user for review.</p> 
<p>Your existing policies always come first. Smart approvals only reviews actions where the user's setting is "ask" each time. Denied actions stay denied, and smart approvals never grants new access. The classifier sends higher-impact actions to the user for review. These include sending content outside the organization, changing permissions, deleting content, making payments, and actions that go beyond what the user asked for. Each automatic approval covers only the exact action that was reviewed. If a review fails or times out, the action goes to the user.</p> 
<p>Smart approvals is on for all users by default. Administrators control who can use it with custom permissions, and users can turn it off for their conversations and scheduled runs in chat options. AWS CloudTrail records each action review made through smart approvals and each change to a user's smart approvals setting.</p> 
<p>Smart approvals is available in Amazon Quick in all AWS Regions where Amazon Quick agentic capabilities are supported. For more information, see the <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/" rel="noopener noreferrer" target="_blank">AWS Region table</a>.</p> 
<p>To learn more about smart approvals, see <a href="https://docs.aws.amazon.com/quick/latest/userguide/smart-approvals.html" rel="noopener noreferrer" target="_blank">smart approvals</a> in the Amazon Quick User Guide. For more information about Amazon Quick, see the <a href="https://aws.amazon.com/quick/" rel="noopener noreferrer" target="_blank">Amazon Quick product page</a>.</p>
</details>

### AWS Lambda supports Seekable OCI (SOCI) lazy loading for Lambda Managed Instances

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-lambda-seekable-oci-soci/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-lambda-seekable-oci-soci/)
- **Published**: 2026-10-29 03:44:00
- **Fetched**: 2026-10-29 08:51:21

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS Lambda now supports <a href="https://github.com/awslabs/soci-snapshotter">Seekable OCI (SOCI)</a>&nbsp;for lazy loading <a href="https://aws.amazon.com/lambda/lambda-functions/">Event Functions</a> packaged as Open Container Initiative (OCI) images running on <a href="https://aws.amazon.com/lambda/lambda-managed-instances/">Lambda Managed Instances</a>. With SOCI support, Lambda fetches only the files needed at each stage of the execution environment startup rather than downloading the entire image upfront, reducing container startup times by up to 70%.</p> 
<p>Customers building compute-intensive applications such as data processing pipelines, high-throughput API backends, and batch computation workloads require substantial memory and CPU resources to process large datasets, serve low-latency responses at scale, and run complex computations efficiently. Container images for these workloads can reach several gigabytes, and downloading and preparing the full image can take several minutes when provisioning new execution environments. SOCI support on Lambda Managed Instances eliminates this bottleneck by streaming only the required files at each stage of the execution environment startup, so your functions start faster as you scale.</p> 
<p>To get started, create a <a href="https://docs.aws.amazon.com/lambda/latest/dg/lambda-managed-instances-seekable-oci.html#lambda-managed-instances-seekable-oci-create-index">SOCI index</a>&nbsp;(a table of contents for the files in your image layers) for your container image and push it to <a href="https://aws.amazon.com/ecr/">Amazon ECR</a>. When creating or updating your function, set the image URI to the SOCI-indexed tag in Amazon ECR (for example, my-function:v1-soci) and publish a function version. Lambda automatically detects the SOCI index and enables lazy loading with no additional configuration. If you use a coding assistant such as Kiro, Claude Code, or Codex, install the Lambda Managed Instances skill from the <a href="https://docs.aws.amazon.com/lambda/latest/dg/agent-setup-guide.html">Agent Toolkit for AWS</a> to configure and deploy functions through your agent.</p> 
<p>The feature is available in all <a href="https://builder.aws.com/build/capabilities">AWS commercial Regions</a> where Lambda Managed Instances is available. To learn more, visit the <a href="https://docs.aws.amazon.com/lambda/latest/dg/lambda-managed-instances-seekable-oci.html">AWS Lambda Managed Instances developer guide</a>.&nbsp;</p>
</details>

<p><a href="https://aws.amazon.com/rds/oracle/">Amazon Relational Database Service (Amazon RDS) for Oracle</a> now supports the September 2026 Monthly Recommended Patch (MRP) for Oracle Database version 19c and 26ai. An MRP is a minor engine version that builds on a quarterly Release Update (RU), bundling Oracle's Critical Security Patch Update (CSPU) with additional Oracle-recommended fixes. The September 2026 MRP is applied on top of the July 2026 RU and includes the <a href="https://www.oracle.com/security-alerts/cspusep2026.html#AppendixDB">Oracle September CSPU</a>. We recommend upgrading to the September 2026 MRP as it includes the latest security updates for Oracle Database.</p> 
<p>This release also includes the updated Oracle time zone file (DST version 46), which reflects the latest daylight saving time rule changes in several regions, including British Columbia and Alberta in Canada (effective November 1, 2026) and Morocco and Western Sahara (effective September 20, 2026), which are moving to permanent UTC offsets. If you store timestamps that include time zone information for these areas, the updated time zone file keeps that data aligned with the new rules.</p> 
<p>You can apply the September 2026 MRP for new database instances, or upgrade existing instances to engine version 19.0.0.0.ru-2026-07.mrp-2026-09.r2 or 26.0.0.0.ru-2026-07.mrp-2026-09.r2 from the Amazon RDS Management Console, or by using the AWS SDK or CLI. To learn more about Oracle MRPs supported on Amazon RDS for each engine version, see the <a href="https://docs.aws.amazon.com/AmazonRDS/latest/OracleReleaseNotes/Welcome.html">Amazon RDS for Oracle Release notes</a>.</p>
