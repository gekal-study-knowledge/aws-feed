### Amazon Redshift long-term system table retention with Amazon S3 Tables is now available in additional AWS Regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/redshift-long-term-system-table-retention-expansion/](https://aws.amazon.com/about-aws/whats-new/2026/10/redshift-long-term-system-table-retention-expansion/)
- **Published**: 2026-10-16 00:00:00
- **Fetched**: 2026-10-16 06:06:34

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><a href="https://aws.amazon.com/redshift/">Amazon Redshift</a> long-term retention for system table data through native integration with <a href="https://aws.amazon.com/s3/features/tables/">Amazon S3 Tables</a> is now available in additional AWS Regions. With this feature, you can configure your Redshift system table data retention beyond the current 7-day limit to meet your compliance, auditing, and observability requirements. Once enabled, AWS automatically writes system table data to S3 Tables in <a href="https://aws.amazon.com/what-is/apache-iceberg/">Apache Iceberg format</a> and manages partitioning, compaction, and retention.</p>
<p>Customers use Redshift system tables to monitor query performance, audit data warehouse activity, and meet compliance requirements. With this feature, system table data is replicated automatically, eliminating the need for custom extract transform load (ETL) pipelines and any resource contention with your production workloads. If you operate multiple data warehouses, you can consolidate their system table data into a single location for cross-warehouse observability and analysis. Because the data is stored in the open Apache Iceberg format, you can query it through Redshift, <a href="https://aws.amazon.com/athena/">Amazon Athena</a>, <a href="https://duckdb.org/">DuckDB</a>, or any Iceberg-compatible engine, and build observability dashboards using AWS services or third-party tools without additional operations overhead. Additionally, the <a href="https://github.com/aws/agent-toolkit-for-aws/tree/main/skills/specialized-skills/system-table-skills">AWS Agent Toolkit</a> provides skills for querying system table data to surface performance insights and optimization recommendations.</p>
<p>This feature is available for Amazon Redshift Provisioned <a href="https://aws.amazon.com/redshift/features/rg/">RG</a> and <a href="https://aws.amazon.com/redshift/features/ra3/">RA3</a> instances and Amazon Redshift <a href="https://aws.amazon.com/redshift/redshift-serverless/">Serverless</a> in the following additional AWS Regions: Asia Pacific (New Zealand), Canada West (Calgary), AWS GovCloud (US-East), and AWS GovCloud (US-West). To learn more, visit our <a href="https://docs.aws.amazon.com/redshift/latest/mgmt/system-table-s3-tables.html">documentation</a> or the <a href="https://aws.amazon.com/blogs/big-data/long-term-system-tables-retention-in-amazon-redshift-with-amazon-s3-tables/">blog</a>.</p>

### Amazon CloudFront announces dual-stack support for VPC origins

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/cloudfront-vpc-origin-dualstack/](https://aws.amazon.com/about-aws/whats-new/2026/10/cloudfront-vpc-origin-dualstack/)
- **Published**: 2026-10-16 01:00:00
- **Fetched**: 2026-10-16 06:06:34

<div class="entry-summary">
<p>Amazon CloudFront now supports end-to-end IPv6 delivery to origins inside your Amazon Virtual Private Cloud (Amazon VPC), with the new dual-stack VPC origins. With VPC origins, customers keep their Application Load Balancers (ALB), Network Load Balancers (NLB), and EC2 instances in private subnets that only their CloudFront distributions can reach. With dual-stack support, customers can now send IPv6 traffic all the way to these private origins to meet their IPv6 architecture and regulatory requirements, without exposing origins to the internet.</p>
<p>Previously, CloudFront supported dual-stack for public origins but connected to VPC origins over IPv4 only. Customers faced a tradeoff: move origins to public subnets for IPv6 and give up VPC origin security or keep them private and stay on IPv4. Now, with this launch, customers can configure their VPC origins as dual-stack and get end-to-end IPv6 without sacrificing security.</p>
<p>Dual-stack VPC origins are available in all AWS Commercial Regions where VPC origins are supported. The full list of supported Regions is available <a href="https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-vpc-origins.html#vpc-origins-supported-regions">here</a>. There is no additional cost for using dual-stack VPC origins. To learn more, visit <a href="https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-vpc-origins.html">CloudFront VPC origins.</a></p>
<p>&nbsp;</p>
</div>

### Amazon DynamoDB Streams now supports timestamp-based stream processing

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-dynamodb-streams-timestamp-processing](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-dynamodb-streams-timestamp-processing)
- **Published**: 2026-10-16 03:30:00
- **Fetched**: 2026-10-16 06:06:34

<div class="entry-summary">
<p>Amazon DynamoDB Streams now supports timestamp-based stream processing, enabling you to begin reading stream records from a specific point in time. Previously, you could only start from the oldest retained record (up to 24 hours old) or from new records written after you start consuming the stream. Now, you can supply a timestamp and begin processing at the first record written at or after that time using the AT_TIMESTAMP shard iterator type.</p>
<p>Timestamp-based stream processing can be used with the Amazon Kinesis Client Library (KCL) through the DynamoDB Streams Kinesis adapter. It helps you avoid reprocessing entire retained streams or missing records when resuming stream consumption, supporting common use cases such as recovery after an interruption, data replay for debugging and auditing by reading from a specific point in the past, skipping a backlog by resuming from a recent timestamp near the latest records, and synchronizing after a restore by beginning at the export timestamp following a point-in-time recovery (PITR) export.</p>
<p>Timestamp-based stream processing is available in all commercial AWS Regions, the AWS GovCloud (US) Regions, and the China Regions. There is no additional charge for this feature beyond standard GetRecords API request charges. To get started, see <a href="https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Streams.Timestamp.html">Amazon DynamoDB Streams timestamp documentation</a> in the DynamoDB developer guide.</p>
</div>
