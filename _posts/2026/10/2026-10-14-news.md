### Amazon Location Service launches an interactive API Playground featuring Places, Routes and Maps APIs

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-location-service-api-playground](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-location-service-api-playground)
- **Published**: 2026-10-14 03:46:00
- **Fetched**: 2026-10-14 09:05:44

<div class="entry-summary">
<p>Amazon Location Service now offers a complete, interactive API Playground that lets developers explore and test every Places, Routes, and Maps API visually without writing code. With this release, all 14 Amazon Location Service Places, Maps and Routes APIs are available in an interactive API Playground, where developers can make real API calls, see results rendered on an interactive map, adjust parameters, and copy ready-to-use request snippets directly into their applications.</p>
<p>The API Playground covers Amazon Location Service's Places, Routes, and Maps APIs: search and geocoding (Geocode, ReverseGeocode, Autocomplete, Suggest, SearchText, SearchNearby, and GetPlace), route planning and optimization (CalculateRoutes, CalculateRouteMatrix, CalculateIsolines, OptimizeWaypoints, and SnapToRoads), and mapping (Dynamic Map and GetStaticMap). Customers can simulate validating delivery addresses, planning truck-safe multi-stop routes, visualizing drive-time service areas, or embedding maps into their apps — with no SDK setup or test scripts required.</p>
<p>The API Playground is available in the following AWS Regions: US East (Ohio), US East (N. Virginia), US West (Oregon), Asia Pacific (Mumbai), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Malaysia), Asia Pacific (Tokyo), Canada (Central), Europe (Frankfurt), Europe (Ireland), Europe (London), Europe (Spain), Europe (Stockholm), and South America (São Paulo).</p>
<p>To get started, visit the <a href="https://console.aws.amazon.com/location/api-playground">Amazon Location Service API Playground</a> in the AWS Console, or learn more in the <a href="https://docs.aws.amazon.com/location/latest/developerguide/api-playground.html">Developer Guide</a>.</p>

### AWS Deadline Cloud now helps users find their accessible resources in the Deadline Cloud monitor

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/deadline-cloud/resources](https://aws.amazon.com/about-aws/whats-new/2026/10/deadline-cloud/resources)
- **Published**: 2026-10-14 03:54:00
- **Fetched**: 2026-10-14 09:05:44

<div class="entry-summary">
<p>AWS Deadline Cloud now lets users who have access to specific queues, fleets, or jobs, rather than an entire farm, find the resources they can reach directly from the Deadline Cloud monitor. Deadline Cloud is a fully managed service that helps teams run compute-intensive workloads for visual effects, animation, product design, simulation, and gaming.</p>
<p>Previously, a user with access to only one queue had to get the farm ID from an administrator before they could reach their work. With this launch, the Deadline Cloud monitor displays to users queues they have access to, the parent IDs needed to reach them, and their level of access, covering both direct and group-inherited permissions. Teams now can share a single monitor entry point (URL) across different permission levels without additional coordination.</p>
<p>Resource discovery is available in all AWS Regions where Deadline Cloud is available. To learn more, visit the <a href="https://docs.aws.amazon.com/deadline-cloud/latest/userguide/view-member-resource-access.html">AWS Deadline Cloud user guide</a>.</p>

### AWS Agent Registry now supports custom metadata for registry records

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-agent-registry-custom-metadata-registry-records](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-agent-registry-custom-metadata-registry-records)
- **Published**: 2026-10-14 06:00:00
- **Fetched**: 2026-10-14 09:05:44

<div class="entry-summary">
<p>AWS Agent Registry is the centralized, governed catalog for agents, MCP servers, agent skills, gateways, and custom resources within your organization. As organizations scale to hundreds of such resources, a name and description alone are insufficient for effective governance and discovery. Custom metadata lets you extend every registry record with your organization's own structured fields, so both people and automated systems can find and govern resources consistently.
 <br />
 <br />
 With custom metadata, publishers can record fields like team ownership, data classification, or review status directly on each registry record. You define a schema once per registry with common attributes, then extend it with type-specific fields — such as a model family for agent records. Each field supports free text, a URL, a Boolean, or a choice from a list of allowed values, and the registry validates required fields and values on every record creation or update. You can then filter search results on any custom metadata field from the AWS Management Console, the AWS CLI, the AWS SDKs, or the registry's MCP endpoint.
 <br />
 <br />
 Custom metadata is available in all AWS Regions where AWS Agent Registry is available: US East (N. Virginia), US West (Oregon), Asia Pacific (Sydney), Asia Pacific (Tokyo), and Europe (Ireland).
 <br />
 <br />
 To learn more, visit the <a href="https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/registry.html">AWS Agent Registry documentation</a>. For detailed setup guidance, see <a href="https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/registry-custom-metadata-schema.html">Define a custom metadata schema</a> and&nbsp;<a href="https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/registry-custom-metadata-values.html">Set custom metadata values on a record</a>.</p>

### Amazon ECS adds LiveTaskCount and removes the charge for RunningTaskCount metric

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/ecs-service-metrics/](https://aws.amazon.com/about-aws/whats-new/2026/10/ecs-service-metrics/)
- **Published**: 2026-10-14 07:00:00
- **Fetched**: 2026-10-14 09:05:44

<div class="entry-summary">
<p>Today, Amazon Elastic Container Service (Amazon ECS) announces LiveTaskCount, a new ECS service metric that reports how many tasks are actively running in your service, available to all customers at no additional charge. Additionally, the existing RunningTaskCount metric in Amazon CloudWatch Container Insights no longer incurs a charge.</p>
<p>LiveTaskCount reports the number of actively running ECS tasks across all desired states (ACTIVATING, RUNNING, and DEACTIVATING), including tasks still running while transitioning to a stopped state, for example, tasks undergoing connection draining during a scale-in event. This comprehensive state coverage makes LiveTaskCount well suited for autoscaling policies and capacity planning where a complete view of active, metric-generating tasks is required. It is available at no charge as part of ECS service utilization metrics and does not require opting in to CloudWatch Container Insights. The existing CloudWatch Container Insights RunningTaskCount metric tracks tasks where both the current and desired state are RUNNING, and continues to serve as a health and stability signal for customers who depend on it. With today's update, RunningTaskCount is now available at no additional charge for all CloudWatch Container Insights users.</p>
<p>These updates are available in all AWS Regions where Amazon ECS is available. No action is required, and the pricing change for RunningTaskCount takes effect beginning October 1, 2026, and applies automatically. To learn more, see <a href="https://docs.aws.amazon.com/AmazonECS/latest/developerguide/service_utilization.html#cw_live_task_count">ECS CloudWatch metrics</a> and <a href="https://docs.aws.amazon.com/AmazonECS/latest/developerguide/cloudwatch-container-insights.html">ECS Container Insights metrics</a>. For a pricing example, see <a href="https://aws.amazon.com/cloudwatch/pricing/">Amazon CloudWatch pricing</a>.</p>
</div>

### AWS Security Hub now supports resource criticality for prioritization

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/security-hub-resource-criticality/](https://aws.amazon.com/about-aws/whats-new/2026/10/security-hub-resource-criticality/)
- **Published**: 2026-10-14 10:00:00
- **Fetched**: 2026-10-14 14:44:38

<div class="entry-summary">
<p>Today, AWS Security Hub adds resource criticality to exposure prioritization, helping central security teams focus on the exposures that threaten their most business-critical resources.</p>
<p>You can set criticality with an automation rule, for example marking every compute resource in a specific account as Very High. The rule applies to resources already in your inventory and to new resources as Security Hub discovers them. Security Hub also infers criticality from resource tags and resource names, with no configuration required, and records which source determined the value. Criticality appears as a column on the Resources page for sorting, filtering, and grouping, and on the Impact assessment tab of an exposure finding. Resource criticality is included with Security Hub Essentials at no additional cost and is always on for all customers.</p>
<p>Resource criticality is included with Security Hub Essentials at no additional cost and requires no new enablement. To learn more, see&nbsp; <a href="https://docs.aws.amazon.com/securityhub/latest/userguide/what-is-securityhub-v2.html">AWS Security Hub User Guide</a> and the <a href="https://aws.amazon.com/security-hub/">AWS Security Hub product page</a>.&nbsp;For a list of AWS Regions where Security Hub is available, see the <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/">AWS Region table</a>.</p>
