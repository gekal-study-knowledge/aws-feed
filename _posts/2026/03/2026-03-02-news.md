### AWS Batch now supports configurable scale down delay

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/03/aws-batch-configurable-scale-down-delay/](https://aws.amazon.com/about-aws/whats-new/2026/03/aws-batch-configurable-scale-down-delay/)
- **Published**: 2026-03-02 00:00:00
- **Fetched**: 2026-03-02 00:00:00

<div class="entry-summary">
<p>AWS Batch now allows you to configure a scale down delay for managed compute environments, helping reduce job processing delays for intermittent and periodic workloads. With the new <i>minScaleDownDelayMinutes</i> parameter, you can specify how long AWS Batch keeps instances running after their jobs complete (from 20 minutes to 1 week), preventing unnecessary instance terminations and relaunches that can delay subsequent job processing.<br /> <br /> You can configure the scale down delay when creating or updating a compute environment via the AWS Batch API (<i>CreateComputeEnvironment</i> or <i>UpdateComputeEnvironment</i>) or the AWS Batch Management Console. The delay is applied at the instance level, based on when each instance last completed a job.<br /> <br /> Scale down delay is supported today in all <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/">AWS Regions</a> where AWS Batch is available. For more information, see the <a href="https://docs.aws.amazon.com/batch/latest/APIReference/API_ComputeScalingPolicy.html#Batch-Type-ComputeScalingPolicy-minScaleDownDelayMinutes">AWS Batch API Guide</a>.</p>
</div>

### OpenSearch OR2 and OM2 instances in AWS GovCloud (US-East, US-West) Regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/03/amazon-opensearch-or2-om2-us-gov-region/](https://aws.amazon.com/about-aws/whats-new/2026/03/amazon-opensearch-or2-om2-us-gov-region/)
- **Published**: 2026-03-02 00:00:00
- **Fetched**: 2026-03-02 00:00:00

<div class="entry-summary">
<p>Amazon OpenSearch Service, expands availability of OR2 and OM2, OpenSearch Optimized Instance family to 12 additional regions. The OR2 instance delivers up to 26% higher indexing throughput compared to previous OR1 instances and 70% over R7g instances. The OM2 instance delivers up to 15% higher indexing throughput compared to OR1 instances and 66% over M7g instances in internal benchmarks<br /> <br /> The OpenSearch Optimized instances, leveraging best-in-class cloud technologies like Amazon S3, to provide high durability, and improved price-performance for higher indexing throughput better for indexing heavy workload. Each OpenSearch Optimized instance is provisioned with compute, local instance storage for caching, and remote Amazon S3-based managed storage. OR2 and OM2 offers pay-as-you-go pricing and reserved instances, with a simple hourly rate for the instance, local instance storage, as well as the managed storage provisioned. OR2 instances come in sizes ‘medium’ through ‘16xlarge’, and offer compute, memory, and storage flexibility. OM2 instances come in sizes ‘large’ through ‘16xlarge’ Please refer to the Amazon OpenSearch Service <a href="https://aws.amazon.com/opensearch-service/pricing/">pricing page</a> for pricing details.<br /> <br /> OR2 and OM2 instance family is now available on Amazon OpenSearch Service across 2 additional regions: AWS GovCloud (US-East, US-West).</p>
</div>

### Issue with AWS-LC: an open-source, general-purpose cryptographic library (CVE-2026-3336, CVE-2026-3337, CVE-2026-3338)

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-005-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-005-aws/)
- **Published**: 2026-03-02 00:00:00
- **Fetched**: 2026-03-02 00:00:00

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><b>Bulletin ID:</b> 2026-005-AWS<br /> <b>Scope:</b> AWS<br /> <b>Content Type:</b> Important (requires attention)<br /> <b>Publication Date:</b> 2026/03/02 14:30 PM PST</p> 
<p><b>Description:</b></p> 
<p>AWS-LC is an open-source, general-purpose cryptographic library. We identified three distinct issues:</p> 
<p>- CVE-2026-3336: PKCS7_verify Certificate Chain Validation Bypass in AWS-LC<br /> Improper certificate validation in PKCS7_verify() in AWS-LC allows an unauthenticated user to bypass certificate chain verification when processing PKCS7 objects with multiple signers, except the final signer.<br /> - CVE-2026-3337: Timing Side-Channel in AES-CCM Tag Verification in AWS-LC<br /> Observable timing discrepancy in AES-CCM decryption in AWS-LC allows an unauthenticated user to potentially determine authentication tag validity via timing analysis.<br /> - CVE-2026-3338: PKCS7_verify Signature Validation bypass in AWS-LC<br /> Improper signature validation in PKCS7_verify() in AWS-LC allows an unauthenticated user to bypass signature verification when processing PKCS7 objects with Authenticated Attributes.</p> 
<p><b>Impacted versions:</b></p> 
<p>- PKCS7_verify Certificate Chain Validation Bypass in AWS-LC &gt;= v1.41.0, &lt; v1.69.0<br /> - PKCS7_verify Certificate Chain Validation Bypass in aws-lc-sys &gt;= v0.24.0, &lt; v0.38.0<br /> - Timing Side-Channel in AES-CCM Tag Verification in AWS-LC &gt;= v1.21.0, &lt; v1.69.0<br /> - Timing Side-Channel in AES-CCM Tag Verification in AWS-LC &gt;= AWS-LC-FIPS-3.0.0, &lt; AWS-LC-FIPS-3.2.0<br /> - Timing Side-Channel in AES-CCM Tag Verification in aws-lc-sys &gt;= v0.14.0, &lt; v0.38.0<br /> - Timing Side-Channel in AES-CCM Tag Verification in aws-lc-sys-fips &gt;= v0.13.0, &lt; v0.13.12<br /> - PKCS7_verify Signature Validation bypass in AWS-LC &gt;= v1.41.0, &lt; v1.69.0<br /> - PKCS7_verify Signature Validation bypass in aws-lc-sys &gt;= v0.24.0, &lt; v0.38.0</p>
