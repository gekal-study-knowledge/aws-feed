### Amazon RDS Custom for SQL Server adds ability to view and schedule new operating system updates

- **Link**: https://aws.amazon.com/about-aws/whats-new/2026/03/amazon-rds-custom-sql-server-operating-system-updates/
- **Published**: 2026-03-19

<p><a href="https://aws.amazon.com/rds/custom/" target="_blank">Amazon RDS Custom</a> for SQL Server now provides customers with ability to view and schedule new operating system (OS) updates for RDS provided engine versions (RPEV). With RPEV, RDS Custom provides a SQL Server version pre-installed on an Amazon Machine Image (AMI). When new operating system updates are available for RPEV, customers can now view upcoming updates, apply them immediately, or schedule them for application in the next maintenance window using RDS Custom APIs.<br /> <br /> To view available OS updates, customers can use the <a href="https://docs.aws.amazon.com/cli/latest/reference/rds/describe-pending-maintenance-actions.html" target="_blank">describe-pending-maintenance-actions</a> API, or subscribe to RDS-EVENT-0230 to receive an alert when new updates become available for their database instance. Customers can use <a href="https://docs.aws.amazon.com/cli/latest/reference/rds/apply-pending-maintenance-action.html" target="_blank">apply-pending-maintenance-action</a> API to apply the updates immediately or schedule them within their next maintenance window.</p> 
<p>Using these features, customers can efficiently track and apply OS updates. To learn more, refer to the <a href="https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/working-with-custom-sqlserver.html" target="_blank">Amazon RDS Custom for SQL Server User Guide</a>. These features are available in all the AWS Regions where RDS Custom for SQL Server is available.</p>

### AWS Lambda now supports Availability Zone metadata

- **Link**: https://aws.amazon.com/about-aws/whats-new/2026/03/lambda-availability-zone-metadata/
- **Published**: 2026-03-19

<p>AWS Lambda now provides Availability Zone (AZ) metadata through a new metadata endpoint in the Lambda execution environment. With this capability, developers can&nbsp;determine&nbsp;the AZ ID (e.g., use1-az1) of the AZ their Lambda function is running in, enabling them to&nbsp;build functions that make AZ-aware routing decisions,&nbsp;such as preferring same-AZ endpoints for downstream services to reduce cross-AZ latency.&nbsp;This capability&nbsp;also&nbsp;enables operators to implement AZ-aware resilience patterns like&nbsp;AZ-specific&nbsp;fault injection testing.</p> 
<p>Lambda automatically provisions and&nbsp;maintains&nbsp;execution environments ready to serve function invocations across multiple AZs within an AWS&nbsp;Region to provide high availability and fault tolerance without any&nbsp;additional&nbsp;configuration or management overhead for customers.&nbsp; As development teams scale their serverless applications, their functions often need to interact with other AWS services like Amazon&nbsp;ElastiCache&nbsp;and Amazon RDS that provide endpoints specific to each AZ.&nbsp;Until now, Lambda did not&nbsp;provide&nbsp;a way for functions to&nbsp;determine&nbsp;which AZ they were running in. With the new metadata endpoint, functions can&nbsp;now&nbsp;retrieve their AZ ID&nbsp;with&nbsp;a simple HTTP request, making it&nbsp;easy&nbsp;to implement AZ-aware logic without building and&nbsp;maintaining&nbsp;custom solutions.</p> 
<p>To get started, use the <a href="https://docs.aws.amazon.com/powertools/typescript/latest/" target="_blank">Powertools&nbsp;for AWS Lambda</a> metadata utility or call the metadata endpoint directly using the environment variables&nbsp;that&nbsp;Lambda automatically sets in&nbsp;the&nbsp;execution environment. This&nbsp;capability&nbsp;is supported for all&nbsp;Lambda runtimes, including custom runtimes and functions packaged as container&nbsp;images,&nbsp;and integrates seamlessly with&nbsp;Lambda capabilities like&nbsp;SnapStart&nbsp;and provisioned concurrency, regardless of whether your functions are VPC-enabled. </p> 
<p>AZ metadata support is available&nbsp;at no&nbsp;additional&nbsp;cost&nbsp;in all&nbsp;commercial <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/" target="_blank">AWS Regions</a>&nbsp;where Lambda is available.&nbsp;To learn more, visit&nbsp;<a href="https://docs.aws.amazon.com/lambda/latest/dg/configuration-metadata-endpoint.html" target="_blank">Lambda documentation</a>.</p>

### AWS adds support for NIXL with EFA to accelerate LLM inference at scale

- **Link**: https://aws.amazon.com/about-aws/whats-new/2026/03/aws-support-nixl-with-efa/
- **Published**: 2026-03-19

<p>AWS announces support for NVIDIA Inference Xfer Library (NIXL) with Elastic Fabric Adapter (EFA) to accelerate disaggregated large language model (LLM) inference on Amazon EC2. This integration enhances disaggregated inference serving through three key improvements: increased KV-cache throughput, reduced inter-token latency, and optimized KV-cache memory utilization.<br /> <br /> NIXL with EFA enables high throughput, low-latency KV-cache transfer between prefill and decode nodes, and it enables efficient KV-cache movement between various storage layers. NIXL is interoperable with all EFA-enabled EC2 instances and integrates natively with frameworks including NVIDIA Dynamo, SGLang, and vLLM. Combined, NIXL with EFA enables flexible integration with your EC2 instance and framework of choice, providing performant disaggregated inference at scale.<br /> <br /> AWS supports NIXL version 1.0.0 or higher with EFA installer version 1.47.0 or higher on all EFA-enabled EC2 instance types in all AWS regions at no additional cost. For more information, visit the <a href="https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/efa.html">EFA documentation</a>.</p>

### Amazon Redshift supports federated permissions with IAM Identity Center in multiple AWS Regions

- **Link**: https://aws.amazon.com/about-aws/whats-new/2026/03/redshift-federated-permissions-idc-mrr/
- **Published**: 2026-03-19

<p>Amazon Redshift federated permissions are now supported with AWS IAM Identity Center (IdC) in multiple AWS Regions. You can extend IdC from your primary AWS Region to additional Regions for improved performance through proximity to users and reliability. In the additional regions, you now have simplified administration of Redshift fine-grained access controls at the table and column level using existing workforce identities with IdC.<br /> <br /> When a new Region is added in IdC, you can create Redshift and Lake Formation Identity Center applications in the new Region without replicating identities from the primary Region. This enables you to use existing workforce identities to query data across warehouses in the new Region. Regardless of which warehouse is used for querying, row-level, column-level, and masking controls always apply automatically, delivering fine-grained access compliance. You can also access Amazon Redshift with single sign-on in these new Regions from Amazon QuickSight, Amazon Redshift Query Editor, or third-party SQL tools.<br /> <br /> To get started with Redshift federated permissions using IdC, read the <a href="https://aws.amazon.com/blogs/big-data/scale-fine-grained-permissions-across-warehouses-with-amazon-redshift-and-aws-iam-identity-center/">blog</a> and <a href="https://docs.aws.amazon.com/redshift/latest/dg/federated-permissions.html">documentation</a>. To extend IdC support in multiple regions, read <a href="https://docs.aws.amazon.com/singlesignon/latest/userguide/multi-region-iam-identity-center.html">IdC documentation</a>, <a href="https://docs.aws.amazon.com/redshift/latest/mgmt/redshift-iam-access-control-idp-connect-console.html">Redshift documentation</a>, <a href="https://docs.aws.amazon.com/lake-formation/latest/dg/connect-lf-identity-center.html">Lake Formation documentation</a>, and see the region <a href="https://docs.aws.amazon.com/accounts/latest/reference/manage-acct-regions.html#manage-acct-regions-regional-availability">availability</a>.</p>

## AWS Security Bulletins

### CVE-2026-4428: Issues with AWS-LC - CRL Distribution Point Scope Check Logic Error

- **Link**: https://aws.amazon.com/security/security-bulletins/rss/2026-010-aws/
- **Published**: 2026-03-19

<p><b>Bulletin ID:</b> 2026-010-AWS<br /> <b>Scope:</b> AWS<br /> <b>Content Type:</b> Important (requires attention)<br /> <b>Publication Date:</b> 2026/03/19 13:30 PM PDT</p> 
<p><b>Description:</b></p> 
<p>AWS-LC is a general-purpose cryptographic library maintained by AWS. We identified CVE-2026-4428 affecting X.509 certificate verification.</p> 
<p>A logic error in the CRL (Certificate Revocation List) distribution point matching in AWS-LC allows a revoked certificate to bypass revocation checks during certificate validation, when the application enables CRL checking and uses partitioned CRLs with Issuing Distribution Point (IDP) extensions.</p> 
<p>Applications that do not enable CRL checking (X509_V_FLAG_CRL_CHECK) are not affected. Applications using complete (non-partitioned) CRLs without IDP extensions are also not affected.</p> 
<p><b>Impacted versions:</b><br /> - CRL Distribution Point Scope Check Logic Error in AWS-LC &gt;= v1.24.0, &lt; v1.71.0<br /> - CRL Distribution Point Scope Check Logic Error in AWS-LC-FIPS &gt;= AWS-LC-FIPS-3.0.0, &lt; AWS-LC-FIPS-3.3.0<br /> - CRL Distribution Point Scope Check Logic Error in aws-lc-sys &gt;= v0.15.0, &lt; v0.39.0<br /> - CRL Distribution Point Scope Check Logic Error in aws-lc-fips-sys &gt;= v0.13.0, &lt; v0.13.13</p> 
<p><b>Please refer to the article below for the most up-to-date and complete information related to this AWS Security Bulletin.</b></p>
