### Amazon Redshift reduces manual snapshot cost for Serverless and RG instances

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-redshift-incremental-manual-snapshots/](https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-redshift-incremental-manual-snapshots/)
- **Published**: 2026-06-09 00:00:00
- **Fetched**: 2026-06-09 05:09:33

<p><a href="https://aws.amazon.com/redshift/">Amazon Redshift</a> announces a new billing model for manual snapshots on <a href="https://aws.amazon.com/redshift/redshift-serverless/">Amazon Redshift Serverless</a> and <a href="https://aws.amazon.com/redshift/features/rg/">Amazon Redshift RG</a> instances. With this enhancement, Amazon Redshift now meters manual snapshot storage based on the unique data blocks stored across your snapshots rather than the total size of each individual snapshot. This results in lower manual snapshot costs for customers who maintain multiple snapshots.<br /> <br /> Customers who maintain multiple manual snapshots for disaster recovery, testing, or long-term retention will see reduced storage costs. With this new billing model, you can take more frequent manual snapshots to achieve a better recovery point objective (RPO) without proportional cost increases, enabling more robust disaster recovery strategies. The new billing model automatically applies to both existing and new manual snapshots.<br /> <br /> The new manual snapshot billing model is available in all AWS commercial and AWS GovCloud (US) Regions where Amazon Redshift Serverless and Amazon Redshift RG instances are available. To learn more about Amazon Redshift snapshots, please visit our <a href="https://aws.amazon.com/redshift/pricing/">documentation</a> or the <a href="https://aws.amazon.com/blogs/big-data/unlock-cost-savings-with-incremental-snapshot-billing-for-amazon-redshift-serverless-and-amazon-redshift-rg/">blog</a>.</p>

### AWS now provides AI-powered cost investigations for cost anomalies

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/06/aws-ai-powered-cost-investigations/](https://aws.amazon.com/about-aws/whats-new/2026/06/aws-ai-powered-cost-investigations/)
- **Published**: 2026-06-09 01:41:00
- **Fetched**: 2026-06-09 07:23:09

<p><a href="https://aws.amazon.com/aws-cost-management/aws-cost-anomaly-detection/">AWS Cost Anomaly Detection</a> now includes AI-powered cost investigation, which uses Amazon Q to analyze the root cause of detected cost anomalies. Investigating a cost change typically requires correlating cost data with AWS CloudTrail events and resource activity, which can take hours. Cost investigation delivers a plain-language explanation in minutes, helping FinOps practitioners and engineering teams move from alert to action faster.</p> 
<p>When you investigate an anomaly, Amazon Q determines whether the cost change is usage-driven or rate-driven, identifies the contributing services, accounts, and regions, and for usage-driven changes, correlates with AWS CloudTrail to attribute the change to specific API calls and IAM principals. For organizations with a CloudTrail organization trail, the investigation works across all member accounts automatically. You can continue the conversation with follow-up questions to explore patterns or drill into specific resources.&nbsp;</p> 
<p>AI-powered cost investigation is available today in all commercial AWS Regions at no additional charge.&nbsp;Cross-account investigations that use an&nbsp;organization-wide CloudTrail trail delivered to Amazon CloudWatch Logs might incur&nbsp;standard CloudWatch Logs Insights charges based on data scanned.</p> 
<p>To get started, navigate to AWS Cost Anomaly Detection in the <a href="https://console.aws.amazon.com/costmanagement/">AWS Billing and Cost Management console</a> and choose Investigate with Amazon Q on any detected anomaly. To learn more, see <a href="https://docs.aws.amazon.com/cost-management/latest/userguide/investigating-ad.html">Investigating anomaly root causes with Amazon Q</a> in the AWS Billing and Cost Management User Guide.&nbsp;</p>

### CVE-2026-11393 - Code Injection via Improper Triple-Quote Escaping in AgentCore CLI Bedrock Agent Import

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-040-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-040-aws/)
- **Published**: 2026-06-09 03:54:30
- **Fetched**: 2026-06-09 05:09:34

<p><b>Bulletin ID:</b> 2026-040-AWS<br /> <b>Scope:</b> AWS<br /> <b>Content Type:</b> Important (requires attention)<br /> <b>Publication Date:</b> 06/08/2026 11:45 AM PDT</p> 
<p><b>Description:</b></p> 
<p>The AWS AgentCore CLI (@aws/agentcore) is a developer tool for managing agent infrastructure lifecycle on Amazon Bedrock AgentCore. We identified CVE-2026-11393 in which improper neutralization of triple-quote characters during Python code generation may allow an authenticated user in the same AWS account to inject arbitrary Python code into the source file generated by the "agentcore add agent ‐‐type import" command.</p> 
<p>Specifically, the collaborationInstruction field of a Bedrock Agent collaborator association was interpolated into a triple-quoted Python docstring using single-quote escaping rather than triple-quote escaping. A user with bedrock:AssociateAgentCollaborator IAM permission could craft a collaborationInstruction value containing """ to break out of the docstring boundary in the generated main.py of the imported agent. If that generated file was subsequently executed - either via agentcore dev on the developer's local machine, or via agentcore deploy followed by agentcore invoke in the AgentCore Runtime environment - the injected Python would run with the credentials available in that context.</p> 
<p><b>Impacted versions:</b><br /> - @aws/agentcore &gt;= 0.4.0 AND &lt;= 0.14.1<br /> - preview versions &gt;= 0.3.0-preview.7.0 and &lt;= 1.0.0-preview.8</p>
