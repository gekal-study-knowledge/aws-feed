### AWS Managed Microsoft AD adds Multi-Region replication for Opt-In regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/04/multi-region-opt-in-aws-microsoft-ad/](https://aws.amazon.com/about-aws/whats-new/2026/04/multi-region-opt-in-aws-microsoft-ad/)
- **Published**: 2026-04-01 16:00:00
- **Fetched**: 2026-04-01 16:00:00

<div class="entry-summary">
<p>AWS Directory Service for Microsoft Active Directory, also known as AWS Managed Microsoft AD, now supports Multi-Region replication in AWS Opt-In regions. This expands the existing Multi-Region replication capability to&nbsp;additional&nbsp;AWS regions,&nbsp;eliminating&nbsp;the need to create and manually synchronize independent directories in each region&nbsp;and allowing domain-joined workloads in those regions to connect to AWS Managed Microsoft AD.</p> 
<p>With automated Multi-Region replication, AWS Managed Microsoft AD handles inter-region networking, deploys domain controllers in separate Availability Zones per region, and replicates all directory data including users, groups, Group Policy Objects, and schema. The service configures an Active Directory site per region to&nbsp;optimize&nbsp;authentication performance and minimize cross-region data transfer costs.&nbsp;</p> 
<p>Multi-Region replication is available in&nbsp;<a href="https://docs.aws.amazon.com/directoryservice/latest/admin-guide/regions.html">AWS Opt-In regions</a>&nbsp;where AWS Managed Microsoft AD is available, except the Middle East (UAE) and Middle East (Bahrain) Regions. You pay by the hour for the domain controllers in each region, plus the cross-region data transfer.&nbsp; To get started, see the&nbsp;<a href="https://docs.aws.amazon.com/directoryservice/latest/admin-guide/ms_ad_configure_multi_region_replication.html">Configure Multi-Region replication guide</a>.</p>
</div>

<div class="entry-summary">
<p>Today,<b> </b><a href="https://aws.amazon.com/marketplace/featured-seller/oracle/" target="_blank">Oracle Database@AWS</a> (ODB@AWS) announced high performance networking that provides customers consistent sub-millisecond roundtrip latency from their AWS applications to the database. Many applications such as payment processing, securities trading, and high volume transaction processing require predictable and consistent low-latency network connectivity to the application database. Customers who run such latency-sensitive applications on Oracle Exadata systems on-premises optimize their infrastructure to obtain the performance that these applications require. <p><a href="https://aws.amazon.com/rds/oracle/">Amazon RDS for Oracle</a> now supports cross-account snapshot sharing for database instances with additional storage volumes. Additional storage volumes allow customers to scale database storage up to 256 TiB by adding up to three storage volumes, each with up to 64 TiB, in addition to the primary storage volume. With this launch, customers can create, share, and copy a database snapshot across AWS accounts for database instances set up with additional storage volumes. ### Amazon CloudFront now supports SHA-256 for signed URLs and signed cookies

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-cloudfront-sha-256-signed-urls/](https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-cloudfront-sha-256-signed-urls/)
- **Published**: 2026-04-02 02:38:00
- **Fetched**: 2026-04-02 02:38:00

<div class="entry-summary">
<p>Amazon CloudFront now supports SHA-256 as a hash algorithm for creating signed URLs and signed cookies. SHA-256 provides an improved security posture with stronger collision detection and alignment with modern cryptographic standards, giving you stronger cryptographic signing when restricting access to content. Previously, CloudFront signed URLs and signed cookies used SHA-1 exclusively for signature generation. This feature helps you meet security and compliance requirements that mandate SHA-256 for digital signatures, while also future-proofing your content delivery workflows.<br /> <br /> To use SHA-256, include the <i>Hash-Algorithm=SHA256</i> query parameter in your signed URLs, or the <i>CloudFront-Hash-Algorithm=SHA256</i> cookie attribute for signed cookies. Existing signed URLs and signed cookies that don't specify a hash algorithm continue to use SHA-1, so this change is fully backwards compatible.</p> 
<p>This feature is available in all edge locations where Amazon CloudFront is available. There is no additional cost to use SHA-256 signing. To learn more, see <a href="https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-creating-signed-url-canned-policy.html" rel="noopener noreferrer" target="_blank">Create a signed URL using a canned policy</a> or <a href="https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-setting-signed-cookie-canned-policy.html" rel="noopener noreferrer" target="_blank">Set signed cookies using a canned policy</a> in the <i>Amazon CloudFront Developer Guide</i>.</p>
</div>

### AWS VPC Encryption Controls now available in AWS GovCloud (US) Regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/03/aws-vpc-encryption-controls/](https://aws.amazon.com/about-aws/whats-new/2026/03/aws-vpc-encryption-controls/)
- **Published**: 2026-04-02 03:20:00
- **Fetched**: 2026-04-02 03:20:00

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS launches VPC Encryption Controls in AWS GovCloud (US) Regions to make it easy to audit and enforce encryption in transit within and across Amazon Virtual Private Clouds (VPC), and demonstrate compliance with encryption standards. You can turn it on your existing VPCs to monitor encryption status of traffic flows and identify VPC resources that are unintentionally allowing plaintext traffic. This feature also makes it easy to enforce encryption across different network paths by automatically (and transparently) turning on hardware-based AES-256 encryption on traffic between multiple VPC resources including AWS Fargate, Network Load Balancers, and Application Load Balancers.</p> 
<p>To meet stringent compliance standards like HIPAA, PCI DSS, FedRAMP, and FIPS 140-2, government customers rely on both application layer encryption and the hardware-based encryption that AWS offers across different network paths. AWS provides hardware-based AES-256 encryption transparently between modern EC2 Nitro instances. AWS also encrypts all network traffic between AWS data centers in and across Availability Zones, and AWS Regions before the traffic leaves our secure facilities. All inter-region traffic that uses VPC Peering, Transit Gateway Peering, or AWS Cloud WAN receives an additional layer of transparent encryption before leaving AWS data centers. Prior to this release, customers had to track and confirm encryption across all network paths. With VPC Encryption Controls, customers can now monitor, enforce and demonstrate encryption within and across Virtual Private Clouds (VPCs) in just a few clicks. Your information security team can turn it on centrally to maintain a secure and compliant environment, and generate audit logs for compliance and reporting.</p> 
<p>With this launch, VPC Encryption Controls is now available in AWS GovCloud (US-East) and AWS GovCloud (US-West) Regions. To learn more about this feature and its use cases, please see our <a href="https://docs.aws.amazon.com/vpc/latest/userguide/vpc-encryption-controls.html">documentation</a>.</p>
</details>

### Amazon ECS announces Managed Daemons for ECS Managed Instances

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-ecs-managed-daemons/](https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-ecs-managed-daemons/)
- **Published**: 2026-04-02 06:00:00
- **Fetched**: 2026-04-02 06:00:00

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon ECS announces Managed Daemons for <a href="https://aws.amazon.com/ecs/managed-instances/">ECS Managed Instances</a>, enabling organizations to centrally deploy and manage software agents such as security, observability, and networking across their container infrastructure independent of application deployments. By decoupling daemon lifecycle management from application operations, Managed Daemons helps guarantee reliable agent coverage across all workloads, simplifies deployments and version updates, and improves resource utilization by running a single daemon task per managed instance.<br /> <br /> With Managed Daemons, you can create a daemon for one or more Managed Instances capacity providers in your cluster. ECS places exactly one daemon task per managed instance and guarantees that daemons are running before any application tasks are placed, so cross-cutting functions such as logging, tracing, and metrics collection are always available. ECS orchestrates daemons as independent processes bound to the instance lifecycle rather than individual application tasks, allowing platform administrators to manage them independently from application teams. When you update daemon versions, ECS drains existing instances and provisions new instances with the updated daemon, automatically replacing service tasks with circuit breaker protection and rollback capabilities for reliable coverage across all your workloads.<br /> <br /> To get started, you can use AWS Console, CLI, CloudFormation, or AWS SDKs to register a daemon task definition specifying your container image, then create a daemon with associated capacity providers in your clusters. This feature is now available in all AWS Regions. For more details, refer to our <a href="https://docs.aws.amazon.com/AmazonECS/latest/developerguide/managed-daemons.html">documentation</a> and launch <a href="http://aws.amazon.com/blogs/aws/announcing-managed-daemon-support-for-amazon-ecs-managed-instances">blog post</a>. There is no additional cost - you pay only for the standard compute resources consumed by your daemon tasks.&nbsp;</p>
</details>

<p>Amazon Simple Email Service (SES) Mail Manager now offers enhancements to email security and processing while simplifying email infrastructure migrations.
