### Amazon FSx for Lustre delivers 16x higher metadata IOPS on Intelligent-Tiering file systems

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-fsx-for-lustre-intelligent-tiering-16x-higher-metadata-iops](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-fsx-for-lustre-intelligent-tiering-16x-higher-metadata-iops)
- **Published**: 2026-11-06 00:39:00
- **Fetched**: 2026-11-06 12:04:48

<div class="entry-summary">
<p><a></a><a href="https://aws.amazon.com/fsx/lustre/">Amazon FSx for Lustre</a> now supports up to 192,000 metadata I/O operations per second (IOPS) on file systems that use the Intelligent-Tiering storage class, 16x higher than the previous maximum of 12,000 IOPS.</p> 
<p>The FSx for Lustre Intelligent-Tiering storage class delivers the lowest-cost and only fully elastic Lustre file storage in the cloud. It is optimized for workloads that mix hot and cold data and do not require consistent SSD-level performance. A file system's metadata IOPS determine how many files and directories you can create, list, read, and delete per second. Today's launch allows you to scale to even higher levels of performance, accelerate time-to-results, and optimize your storage costs for metadata-intensive machine learning research and high-performance computing (HPC) workloads.</p> 
<p>Higher metadata IOPS are available on new FSx for Lustre Intelligent-Tiering file systems in all <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/">AWS Regions</a> where the Intelligent-Tiering storage class is available. For more information about the file system metadata performance, see the Amazon FSx for Lustre <a href="https://docs.aws.amazon.com/fsx/latest/LustreGuide/performance.html#dne-metadata-performance">User Guide</a>.</p>
</div>

### Amazon OpenSearch Service optimized engine now supports agent traces

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-service-support-traces](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-service-support-traces)
- **Published**: 2026-11-06 02:00:00
- **Fetched**: 2026-11-06 12:04:48

<div class="entry-summary">
<p>Today, the Amazon OpenSearch Service optimized engine adds support for agent traces, including OpenTelemetry traces. Your traces and logs now live in the same place. You can follow a request or an agent session from start to finish, find the step that failed or slowed down, and check the related logs without switching tools.&nbsp;</p> 
<p>The optimized engine maps OpenTelemetry logs and traces to object, nested, and flat object fields, with support for multi-valued arrays. Span events, span links, prompts, and tool calls retain their nested structure, allowing field-level queries without flattening data during ingestion.</p> 
<p>On hot-tier data, the engine supports update, delete, and upsert operations by document ID.&nbsp;When data arrives late or with errors, you can correct it in place, so your dashboards and alerts work from accurate data. In OpenSearch UI, you can analyze this data with Discover Traces, application performance monitoring, the service map, and the agent traces and sessions views.</p> 
<p>These features are available on OpenSearch 3.7, at no additional charge in the following AWS Regions: US East (N. Virginia), US East (Ohio), US West (Oregon), Canada (Central), Asia Pacific (Mumbai), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Tokyo), Europe (Frankfurt), Europe (Ireland), Europe (London), and Europe (Spain).&nbsp;&nbsp;To get started, send OpenTelemetry data to your domain, for example by using Amazon OpenSearch Ingestion. To learn more, see the <a href="https://docs.aws.amazon.com/opensearch-service/latest/developerguide/optimized-log-analytics.html">documentation</a>.</p>
</div>

### IAM Roles Anywhere now supports automatic certificate revocation checking

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/iam-roles-anywhere-cdp/](https://aws.amazon.com/about-aws/whats-new/2026/11/iam-roles-anywhere-cdp/)
- **Published**: 2026-11-06 02:38:00
- **Fetched**: 2026-11-06 07:29:42

<div class="entry-summary">
<p><a href="https://aws.amazon.com/iam/roles-anywhere">AWS Identity and Access Management (IAM) Roles Anywhere</a> now supports automatic revocation checking using certificate revocation list (CRL) distribution points (CDPs). This helps keep revocation checks in sync with your certificate authority (CA) and can help improve your security posture. When you enable this capability on a trust anchor, IAM Roles Anywhere reads the CDP URLs embedded in authenticating certificates, downloads the corresponding CRLs, and denies credential requests that use revoked certificates.</p> 
<p>Previously, to check revocation status, you had to import CRLs into IAM Roles Anywhere and re-import them each time your CA published an update, which added operational overhead. With this launch, IAM Roles Anywhere downloads CRLs from your CDPs and refreshes them periodically, so you no longer need to re-import them. You can use this capability with <a href="https://aws.amazon.com/private-ca/">AWS Private Certificate Authority</a> or your own public key infrastructure (PKI), provided your certificates include publicly accessible CDP URLs that meet the <a href="https://docs.aws.amazon.com/rolesanywhere/latest/userguide/trust-model.html#crl-distribution-point-revocation">distribution point requirements</a>. To enable it on a trust anchor, use the IAM Roles Anywhere console, AWS SDKs, or AWS CLI.</p> 
<p>This feature is available at no additional cost in all commercial AWS Regions. To learn more, see <a href="https://docs.aws.amazon.com/rolesanywhere/latest/userguide/trust-model.html#crl-distribution-point-revocation">Automatic revocation checking with CRL distribution points</a> in the IAM Roles Anywhere User Guide.</p>
</div>

### Amazon DynamoDB now supports bulk put items

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-dynamodb-now-supports-bulk-put-items/](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-dynamodb-now-supports-bulk-put-items/)
- **Published**: 2026-11-06 03:00:00
- **Fetched**: 2026-11-06 07:29:42

<div class="entry-summary">
<p>Today, AWS announces the general availability of bulk put items for Amazon DynamoDB, a fully managed feature that writes data from Amazon S3 into your existing DynamoDB tables. Many DynamoDB applications use data that other systems produce and store in Amazon S3. Writing this data into existing DynamoDB tables has typically meant building custom pipelines and managing table capacity. With bulk put items, developers and data engineers can write this data without impacting existing workloads or building a custom ingestion pipeline, in a cost-efficient way.</p> 
<p>You point bulk put items at the S3 location of your input files, and DynamoDB handles the rest. Each item supports its own condition expression, so you can enforce insert-only or version-guarded writes. The Standard tier fits most workloads, and the Accelerated tier is for more time-sensitive workloads. Common use cases include daily refreshes, large catalog enrichments, backfills, and migrations.</p> 
<p>Bulk put items with Standard tier is available in all commercial AWS Regions and the AWS GovCloud (US) Regions, to see the list where the Accelerated tier is available see the <a href="https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/BulkPutItems.Tiers.html#BulkPutItems.Tiers.Accelerated" target="_blank">regional availability.</a> To learn more, visit the <a href="https://aws.amazon.com/blogs/database/introducing-bulk-put-items-for-amazon-dynamodb-load-data-from-amazon-s3-into-existing-tables-at-scale/" target="_blank">Introducing bulk put items for Amazon DynamoDB</a> blog and the <a href="https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/BulkPutItems.HowItWorks.html" target="_blank">Amazon DynamoDB Developer Guide</a>.</p>
</div>

### AWS Network Load Balancer is now available in the AWS Phoenix Local Zone

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-nlb-available-phx-local-zone/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-nlb-available-phx-local-zone/)
- **Published**: 2026-11-06 05:00:00
- **Fetched**: 2026-11-06 12:04:48

<div class="entry-summary">
<p>AWS Network Load Balancer is now available in the Phoenix Local Zone (us-west-2-phx-2a). AWS Local Zones is a type of AWS infrastructure deployment that places AWS compute, storage, database, and other select services closer to large population, industry, and IT centers where no AWS Region exists today.</p> 
<p>With this launch, you can create an AWS Network Load Balancer directly in the Phoenix Local Zone. Previously, if your targets ran in the Phoenix Local Zone, you had to place the load balancer in an Availability Zone in the parent Region, so connections and their traffic had to travel to the parent Region and back. This added latency and routed traffic outside the zone where your application runs. Now, connection routing stays local to your targets, delivering lower and more consistent latency to end users in the Phoenix metro area and keeping traffic within the Local Zone. This is especially valuable for latency-sensitive workloads such as real-time gaming, media streaming, and live financial applications serving users in the region.</p> 
<p>To learn more about Network Load Balancer, visit the <a href="https://docs.aws.amazon.com/elasticloadbalancing/latest/network/introduction.html">documentation</a>. For more information on AWS Local Zones, visit the <a href="https://aws.amazon.com/about-aws/global-infrastructure/localzones/">AWS Local Zones website</a>. The <a href="https://aws.amazon.com/about-aws/global-infrastructure/localzones/locations/">Locations webpage</a> lists the available and announced Local Zones. You can enable AWS Local Zones from the <a href="https://us-east-1.console.aws.amazon.com/awsglobalview/home#RegionsAndZones:tabId=lz">Local Zones </a>tab in the AWS Global View console, or the <a href="https://docs.aws.amazon.com/AWSEC2/latest/APIReference/API_ModifyAvailabilityZoneGroup.html">ModifyAvailabilityZoneGroup</a> API.</p>
</div>

### Announcing Web Answer on Amazon Bedrock AgentCore

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/web-answer-amazon-bedrock/](https://aws.amazon.com/about-aws/whats-new/2026/11/web-answer-amazon-bedrock/)
- **Published**: 2026-11-06 05:56:00
- **Fetched**: 2026-11-06 07:29:42

<div class="entry-summary">
<p>Today, we are announcing the general availability of Web Answer on Amazon Bedrock AgentCore. Web Answer is a managed tool that returns a synthesized, grounded, cited answer to a natural-language question in a single call, so agent builders can attach it to an agent and get back a finished answer grounded in current web sources, without building and maintaining their own search, retrieve, synthesis, and citation pipeline.&nbsp;</p> 
<p>Web Answer builds on Web Search on Amazon Bedrock AgentCore, which launched in June, extending it from "find the web content" to "return the finished answer," a capability customers have been asking for. With Web Answer, your agent sends a question and receives a synthesized cited answer in one tool call. Web Answer works like an agent; it plans its own searches, runs several in parallel, and decides when it has gathered enough evidence to answer. You stay in control of the boundaries, with domain include, deny lists and publish-date filters that scope where it looks. It attaches as a target on an AgentCore Gateway and is called over MCP, authenticated with IAM, with zero data egress.&nbsp;</p> 
<p>Web Answer is available in the US East (N. Virginia) Region, with per-tool call pricing.&nbsp;</p> 
<p>To learn more about Web Answer on Amazon Bedrock AgentCore, see Web Answer’s documentation <a href="https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connector-web-answer-tool.html">page</a> and Web Answer’s <a href="http://aws.amazon.com/bedrock/grounding/web-answer/">website</a>. For Region availability, see the AWS Region <a href="https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html">table</a>.&nbsp;</p>
</div>
