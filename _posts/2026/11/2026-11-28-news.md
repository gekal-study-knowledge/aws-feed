# AWS Updates - 2026-11-28

## AWS What's New

### Amazon Neptune introduces Neptune Graph Sessions, smaller graphs designed for agents that scale to zero and resume automatically

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-neptune-graph-sessions-generally-available](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-neptune-graph-sessions-generally-available)
- **Published**: 2026-11-28 04:00:00
- **Fetched**: 2026-11-28 10:00:55

<div class="entry-summary">
<p><a href="https://aws.amazon.com/neptune/">Amazon Neptune</a> now supports Neptune Graph Sessions, a compute mode designed for agents that scales memory and CPU automatically and scales to zero when idle. You can give each agent, user or task its own graph without paying for the 16 m-NCU minimum of a provisioned graph. You choose a starting size of 4 s-NCU (sessions Neptune capacity units) or 8 s-NCU of working memory when you create a graph.</p> 
<p>Applications such as GraphRAG assistants, AI agents and per-user analytics improve accuracy when using a graph. These use cases often need a separate graph for each conversation or task, and the size of that graph is hard to predict. Each Graph Sessions graph starts at the size you choose and includes memory headroom up to twice that size for the data you load and the queries you run (a 4 s-NCU graph has up to 8 s-NCU of memory, and an 8 s-NCU graph has up to 16 s-NCU), so the starting size does not have to cover your largest graph. You are billed for the memory your graph uses, so a graph that fits in the smaller size is billed at the smaller size.</p> 
<p>When a graph is idle, Graph Sessions scales to zero automatically after 15 minutes, and the graph resumes in seconds when the next query arrives. Your graph and its data are kept, so you do not reload data for each session and pay for the running price.</p> 
<p>You can create a Neptune Graph Sessions graph using the AWS Management Console, AWS CLI, or AWS SDKs, and query it with openCypher like any other Neptune Analytics graph. For more information, see the <a href="https://docs.aws.amazon.com/neptune-analytics/latest/userguide/gettingStarted.html">Neptune Analytics User Guide</a> and the <a href="https://aws.amazon.com/neptune/pricing/">Amazon Neptune pricing page</a>.</p>
</div>

### Amazon CloudWatch announces basic OpenTelemetry enrichment at no additional cost

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-opentelemetry-enrichment/](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-opentelemetry-enrichment/)
- **Published**: 2026-11-28 06:03:00
- **Fetched**: 2026-11-28 10:00:55

<div class="entry-summary">
<p>Amazon CloudWatch now offers basic OpenTelemetry enrichment for AWS service metrics at no additional cost. Basic enrichment turns the metrics that AWS services publish to CloudWatch into OpenTelemetry data points you can query with PromQL. It covers metrics that identify a resource, such as Amazon EC2 CPUUtilization with an InstanceId dimension. Enriched metrics get resource attributes for the Amazon Resource Name, cloud provider, Region, and account ID, plus an instrumentation scope naming the source service. Your original CloudWatch dimensions become data point attributes.</p> 
<p>To query AWS resource tags as PromQL labels, choose resource tag enrichment instead. It is charged as OTel Vended Metric Enrichment, and you can switch levels at any time. Your AWS service metrics stay available through existing CloudWatch APIs.</p> 
<p>When you set up CloudWatch Omni, basic enrichment is enabled by default, so you can query your AWS service metrics with PromQL right away. Any account can also enable it directly in the CloudWatch console, AWS Command Line Interface, or the AWS SDKs. Basic enrichment is available in all AWS Regions where CloudWatch OpenTelemetry metrics are supported. To learn more, see <a href="https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-OTelEnrichment.html" title="AWS vended metrics in OpenTelemetry format with PromQL querying">AWS vended metrics in OpenTelemetry format</a>. For pricing, see <a href="https://aws.amazon.com/cloudwatch/pricing/" title="CloudWatch pricing">Amazon CloudWatch pricin</a>g.</p>
</div>

### Amazon Timestream for InfluxDB 3 now supports heterogeneous clusters

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/influxdb-heterogeneous-cluster/](https://aws.amazon.com/about-aws/whats-new/2026/11/influxdb-heterogeneous-cluster/)
- **Published**: 2026-11-28 07:30:00
- **Fetched**: 2026-11-28 10:00:55

<div class="entry-summary">
<p>Amazon Timestream for InfluxDB 3 now supports heterogeneous clusters, which let you assign a different instance size to each node role in an InfluxDB 3 Enterprise cluster. You can size the writer, reader, and compactor roles independently. You set the size for each role when you create a cluster or add nodes to an existing cluster, using the Amazon Timestream console, the AWS Command Line Interface (CLI), or the AWS SDKs.</p> 
<p>Time series workloads rarely load every part of a database the same way. Queries need memory for the query cache, writes are gated by durable flushes to object storage, and compaction needs vCPUs to merge files in the background. Because every node previously ran one instance size, scaling a single role meant scaling all of them and paying for headroom on nodes already sized correctly. You can now place reader nodes on a larger size for a bigger cache or more complex queries while keeping writer nodes smaller, or give the compactor more vCPUs without changing the rest of the cluster.</p> 
<p>There is no additional charge, and you pay the standard price for each node at the size you select. Heterogeneous clusters are available for InfluxDB 3 Enterprise clusters in all AWS <a href="https://docs.aws.amazon.com/general/latest/gr/timestream.html">Regions</a> where Amazon Timestream for InfluxDB is available. To get started, open the Amazon Timestream console. For more information, see the <a href="https://docs.aws.amazon.com/timestream/">Amazon Timestream for InfluxDB documentation</a> and <a href="https://aws.amazon.com/timestream/pricing/">pricing page</a>.</p>
</div>
