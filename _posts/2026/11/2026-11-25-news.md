### CVE-2026-134066 - Query injection via schema-derived identifiers in Graph Explorer

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-199-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-199-aws/)
- **Published**: 2026-11-25 03:44:47
- **Fetched**: 2026-11-25 04:54:15

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-199-AWS<br /> <b>Publication Date:</b> 11/24/2026 10:30 AM PST</p> 
<p><b>Description:</b></p> 
<p>Graph Explorer is an open-source tool for browsing and searching graph data, which customers self-host against Amazon Neptune or other graph databases.</p> 
<p>We identified CVE-2026-134066, an issue in the query construction of Graph Explorer before version 3.2.1. Graph Explorer inserted property keys and labels read from the connected graph database into Gremlin, openCypher and SPARQL query text without escaping. A user with write access to the connected graph database could create a crafted property key or label that, when another user performs a search, causes Graph Explorer to run unintended query logic that accesses and modifies data in that database with Graph Explorer's privileges. On Amazon Neptune, the SPARQL path is not affected.</p> 
<p><b>Impacted versions:</b> &lt; 3.2.1</p> 
<p><b><a href="https://aws.amazon.com/security/security-bulletins/2026-199-aws/">Refer to the article</a> for the most up-to-date and complete information.</b></p>
</div>

### CVE-2026-135614 - Sensitive data redaction bypass in the troubleshooting tool in Amazon ECS MCP Server

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-200-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-200-aws/)
- **Published**: 2026-11-25 04:27:19
- **Fetched**: 2026-11-25 04:54:15

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-200-AWS<br /> <b>Publication Date:</b> 11/24/2026 11:00 AM PST</p> 
<p><b>Description:</b></p> 
<p>Amazon ECS MCP Server is an open-source Model Context Protocol server that lets AI agents and assistants manage and troubleshoot Amazon ECS workloads using the operator's AWS credentials.</p> 
<p>We identified CVE-2026-135614, an issue in the troubleshooting tool of the Amazon ECS MCP Server (awslabs.ecs-mcp-server) before 0.1.36. With the sensitive data setting at its default, the troubleshooting tool returned container environment variable values and secret references from ECS task definitions without the redaction the setting is intended to apply. This might allow a remote actor who can influence the agent's input, for example through prompt injection, to obtain those values.</p> 
<p><b>Impacted versions:</b> &lt; 0.1.36</p> 
<p><b><a href="https://aws.amazon.com/security/security-bulletins/2026-200-aws/">Refer to the article</a> for the most up-to-date and complete information.</b></p>

### CVE-2026-135414 - Server-side request forgery in snapshot repository registration in Amazon OpenSearch Service

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-201-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-201-aws/)
- **Published**: 2026-11-25 04:27:19
- **Fetched**: 2026-11-25 04:54:15

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-201-AWS<br /> <b>Publication Date:</b> 11/24/2026 11:15 AM PST</p> 
<p><b>Description:</b></p> 
<p>Amazon OpenSearch Service is a managed service for deploying, operating, and scaling OpenSearch clusters in the AWS Cloud.</p> 
<p>We identified CVE-2026-135414, an issue in snapshot repository registration in Amazon OpenSearch Service. A user with snapshot management permissions on a domain could set a repository endpoint that caused the domain's service-operated nodes to send requests to network destinations that the user specified. This issue is addressed in service software R20260720. We recommend that customers update their domains to R20260720 or later.</p> 
<p><b>Impacted versions:</b> Amazon OpenSearch Service service software before R20260720</p> 
<p><b><a href="https://aws.amazon.com/security/security-bulletins/2026-201-aws/">Refer to the article</a> for the most up-to-date and complete information.</b></p>
