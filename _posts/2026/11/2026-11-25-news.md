### Amazon OpenSearch Service new engine now joins logs, traces, and metadata

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-service-distributed-joins](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-service-distributed-joins)
- **Published**: 2026-11-25 02:00:00
- **Fetched**: 2026-11-27 08:27:49

<div class="entry-summary">
<p>Amazon OpenSearch Service now supports distributed joins, high-cardinality aggregations, and OpenSearch query DSL on the new engine. Observability data often spans logs, traces, service metadata, deployment records, and tenant data. Engineers and their AI agents must connect these datasets to determine what failed, where it failed, and who was affected.</p> 
<p>With Piped Processing Language (PPL) or SQL, engineers and agents can query multiple petabytes of data to connect an error log to its trace, and enrich telemetry with service ownership or deployment metadata, in one query. High-cardinality aggregations measure incident impact across millions of distinct hosts, users, or tenants. The new engine spreads aggregations and joins across data nodes, so you don't need to copy related data into a single index first. With routing key support, you can keep related documents on the same shard, so lookups and joins on that key stay fast.</p> 
<p>In addition to PPL and SQL, the new engine now supports OpenSearch query DSL. You get the engine's cost savings and performance improvements for supported analytics workloads without rewriting queries in PPL or SQL. Applications, alerts, and integrations that send query DSL keep working.</p> 
<p>These features are available on OpenSearch 3.9, at no additional charge, in the following AWS Regions: US East (N. Virginia), US East (Ohio), US West (Oregon), Canada (Central), Asia Pacific (Mumbai), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Tokyo), Europe (Frankfurt), Europe (Ireland), Europe (London), and Europe (Spain). To get started, create or upgrade a domain to OpenSearch 3.9 with the new engine. To learn more, see the <a href="https://docs.aws.amazon.com/opensearch-service/latest/developerguide/optimized-log-analytics-queries.html">documentation</a>.</p>
</div>

### AWS IAM extends trusted identity propagation to IAM federation and IAM Roles Anywhere, and simplifies it in IAM Identity Center

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-iam/](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-iam/)
- **Published**: 2026-11-25 15:00:00
- **Fetched**: 2026-11-26 07:55:11

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><a href="https://docs.aws.amazon.com/singlesignon/latest/userguide/trustedidentitypropagation-overview.html" rel="noopener noreferrer" target="_blank">Trusted identity propagation (TIP)</a> carries the identity of a human user or workload with requests to supported AWS Services. Customers can use that identity in IAM policy conditions for access control and to identify the originating human user or workload in AWS CloudTrail. AWS is expanding TIP to <a href="https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers.html#id_roles_providers_federation" rel="noopener noreferrer" target="_blank">AWS Identity and Access Management (IAM) federation</a> and <a href="https://docs.aws.amazon.com/rolesanywhere/latest/userguide/introduction.html" rel="noopener noreferrer" target="_blank">IAM Roles Anywhere</a>, while simplifying the existing TIP experience in AWS IAM Identity Center. In addition, <a href="https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_outbound.html" rel="noopener noreferrer" target="_blank">IAM outbound identity federation</a> now enables customers to request an AWS-signed JSON Web Token (JWT) that includes identity information from TIP sessions, allowing external services to identify the human user or workload that originated the request.</p> 
<p>With TIP for IAM federation, customers can map the human or workload identity, along with optional runtime claims such as a risk score or a CI/CD workflow name, from the SAML assertion or OIDC token used for federation to the role session. IAM Roles Anywhere extends TIP to identities sourced from X.509 certificates. For IAM Identity Center, which supports workforce identities, the simplified experience adds the username, an identifier provided by your identity source, alongside the user ID that IAM Identity Center generates, and carries this information uniformly whether users access applications or AWS accounts. Across all supported paths, TIP preserves identity information as requests move between IAM roles and AWS services without requiring per-role trust policy updates.&nbsp;</p> 
<p>TIP for IAM federation, IAM Roles Anywhere, IAM outbound identity federation, and the simplified IAM Identity Center experience are available in all commercial AWS Regions, the AWS GovCloud (US) Regions, and the AWS European Sovereign Cloud (Germany) Region. To get started, see the <a href="https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_tip.html" rel="noopener noreferrer" target="_blank">Trusted Identity Propagation for IAM documentation</a>, <a href="https://docs.aws.amazon.com/singlesignon/latest/userguide/simplified-tip-overview.html" rel="noopener noreferrer" target="_blank">Trusted Identity Propagation in IAM Identity Center documentation</a>, and the&nbsp;<a href="https://aws.amazon.com/blogs/security/know-the-identity-behind-the-role-authorize-and-audit-with-trusted-identity-propagation/" rel="noopener noreferrer" target="_blank">TIP launch blog</a>.</p>

### AWS IoT Core now uses dedicated IPv6 address ranges for the HTTP rule action

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-iot-core-dedicated-ipv6-ranges/](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-iot-core-dedicated-ipv6-ranges/)
- **Published**: 2026-11-25 17:00:00
- **Fetched**: 2026-11-26 07:55:11

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><a href="https://aws.amazon.com/iot-core/">AWS IoT Core</a> can now send traffic to HTTPS endpoints within a dedicated, published IPv6 address range. This launch enables you to configure your HTTPS endpoints to accept requests only from AWS IoT Core and block all other traffic, thereby reducing your endpoint's exposure to public internet.</p>
<p>AWS IoT Core is a fully managed service that securely connects&nbsp;IoT devices at scale to the AWS cloud and routes IoT device data to AWS and third-party services. AWS IoT Core's <a href="https://docs.aws.amazon.com/iot/latest/developerguide/https-rule-action.html" target="_blank">HTTP rule action</a> delivers IoT device data to any HTTPS endpoint, such as your application servers, on-premises systems, or partner services. With this launch, you can choose from AWS IoT Core's published IPv6 range, and add the fixed IPv6 range to an <a href="https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-resource-policies.html" target="_blank">Amazon API Gateway resource policy</a>, a <a href="https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html" target="_blank">security group</a>, or your <a href="https://docs.aws.amazon.com/network-firewall/latest/developerguide/rule-groups.html" target="_blank">firewall rules</a>. Your HTTPS endpoints will then accept traffic only from AWS IoT Core, giving you network layer control over who can reach your endpoint.</p>
<p>To get started, configure your HTTPS endpoint destination to be reachable only over IPv6 by publishing AAAA DNS records (and removing the A DNS records). This allows IoT Core's HTTP rule action to use only IPv6 addresses when sending data to your HTTP destination. Then allow AWS IoT Core's published IPv6 range for your Region, and create or update your HTTP rule action with the endpoint destination. Dedicated IPv6 ranges are available at no additional charge in all AWS Global Regions where AWS IoT Core is available, including AWS GovCloud (US). To find the range for your Region, see <a href="https://docs.aws.amazon.com/iot/latest/developerguide/iot-create-role.html#rules-engine-ip-ranges" target="_blank">Restricting HTTP action traffic to the rules engine IPv6 ranges</a> in the AWS IoT Core Developer Guide.</p>
</details>

### Amazon Transcribe Turbo: more accurate transcripts and natural turn-taking for voice agents, now in public preview

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/transcribe-turbo-preview/](https://aws.amazon.com/about-aws/whats-new/2026/11/transcribe-turbo-preview/)

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon Transcribe Turbo, our next-generation speech-to-text model, is now in public preview in US East (Ohio) for batch and streaming. Turbo improves accuracy, supports custom vocabulary, and formats numbers, dates, currency, phone numbers and addresses following each locale's conventions.</p> 
<ul> 
 <li><p><b>Streaming:</b> English, Portuguese, French, Italian, German and Spanish supported. Word Error Rate (WER) drops ~14% relative in English and 11% relative in the other languages versus the current production model, and formatting accuracy improves by more than 20 points.</p> </li> 
 <li><p><b>Batch:</b> English Turbo is generally available in most AWS Regions. Portuguese, French, Italian, German, Spanish, Chinese, Japanese, Korean and Arabic are now in preview, with ~16% lower word error rate.</p> </li> 
</ul> 
<p>The base model needs no API, code, or SDK changes.</p> 
<p>Turbo streaming also adds two new features for voice agents in English at launch and for other languages by the end of December 2026.</p> 
<p><b>Semantic turn-taking</b> detects when a caller is done speaking from <i>what</i> they said and their <i>prosody </i>in speech, not silence alone. It won't cut callers off mid-sentence ("I'd like to transfer… $250 to savings") or make short answers like "yes", "no" wait on silence timeouts. It responds in about 615 ms with a 5% interruption rate, and you can tune it.</p> 
<p><b>Runtime ASR hints</b> give your agent context at every turn. Unlike static custom vocabulary, set once per session, hints enable your client application to send menu options, expected names and the expected entity type (date, phone number, currency) before each turn. On English customer service data, hints raise menu-routing accuracy from 87% to 97%.</p> 
<p>Both features come at no additional charge. To try them, turn on EndOfTurnDetection and send hints in a ConfigureEvent.</p>

### AWS Device Farm now supports Android emulators and iOS simulators

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/device-farm-virtual-devices/](https://aws.amazon.com/about-aws/whats-new/2026/11/device-farm-virtual-devices/)
- **Published**: 2026-11-25 17:00:00
- **Fetched**: 2026-11-26 13:40:56

<div class="entry-summary">
<p><a href="https://aws.amazon.com/device-farm/">AWS Device Farm</a>, a service for testing mobile and web apps, now supports Android emulators and iOS simulators alongside real devices for automated and manual testing, enabling faster testing at scale early in your development pipeline. With virtual devices, you can shift testing left to stages that need high speed and volume, such as pull requests, code merges, and smoke tests, and keep real devices for later stages that need high fidelity, such as regression and release testing. Virtual devices running the latest device and OS typically start in seconds, and others start in around a minute.</p>
<p>Previously, you could build and maintain your own Android emulator and iOS simulator infrastructure, which requires separate tooling and compute such as Mac hosts for iOS, or run every stage on real devices, which is slower, limited by device availability, and costs more than early-stage testing needs. Now you can use the same fully managed Device Farm APIs, test environment, private endpoint access, and test frameworks for both virtual and real devices. To switch, you change only the device type, so your pipeline and tests stay the same and you avoid maintaining two separate orchestration layers.</p>
<p>Virtual devices use the existing metered <a href="https://aws.amazon.com/device-farm/pricing/">pricing</a>. For Android, your existing unmetered slots now go further and run either a real or a virtual device at no additional charge.</p>
<p>Android emulators and iOS simulators are available in all <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/">AWS Regions</a> where AWS Device Farm is offered.</p>
<p>To get started, see the AWS Device Farm <a href="https://docs.aws.amazon.com/devicefarm/latest/developerguide/virtual-devices.html" target="_blank">Developer Guide</a>.</p>

<p><b>Description:</b></p> 
<p>Graph Explorer is an open-source tool for browsing and searching graph data, which customers self-host against Amazon Neptune or other graph databases.</p> 
<p>We identified CVE-2026-134066, an issue in the query construction of Graph Explorer before version 3.2.1.
