### Elastic Load Balancing for Envoy is now generally available

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/elastic-load-balancing-for-envoy-generally-available](https://aws.amazon.com/about-aws/whats-new/2026/11/elastic-load-balancing-for-envoy-generally-available)
- **Published**: 2026-11-26 01:00:00
- **Fetched**: 2026-11-26 13:40:56

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Today, AWS announces the general availability of ELB for Envoy, a new load balancer type in Elastic Load Balancing (ELB) that runs open-source Envoy proxies. Platform teams that run Envoy themselves own upgrades, security patching, and capacity across Availability Zones (AZs). ELB for Envoy takes on that work. Each load balancer runs its proxies on dedicated Amazon Elastic Compute Cloud (Amazon EC2) instances with hardware isolation from the AWS Nitro System, so a zero-day in Envoy stays contained to your load balancer. ELB for Envoy also monitors for security vulnerabilities (CVEs) and applies Envoy and operating system patches automatically, so you can focus on your applications instead of your proxy fleet.</p> 
<p>You can bring your existing Envoy configurations, extensions, and control planes as they are, and add AWS&nbsp;integrations such as AWS&nbsp;Certificate Manager (ACM)&nbsp;and AWS WAF&nbsp;with minimal configuration. If you run Envoy Gateway on Kubernetes, install the <a href="https://github.com/aws/elb-envoy-remote-infra-provider" rel="noopener noreferrer" target="_blank">ELB for Envoy remote infrastructure provider</a>&nbsp;alongside Envoy Gateway to move your proxies to ELB&nbsp;for Envoy without rewriting your Gateway API&nbsp;resources.</p> 
<p>You can add custom logic with WebAssembly, Lua scripting, or external processing. ELB for Envoy runs inside your VPC, integrates with Amazon Virtual Private Cloud (Amazon VPC) security groups, and supports VPC encryption. It's well suited to workloads that need Envoy's extensibility, such as custom authentication, request transformation, or advanced traffic routing, along with Kubernetes ingress and migrations from self-managed Envoy.</p> 
<p>At general availability, ELB for Envoy is available in 14 AWS Regions: US East (N. Virginia), US East (Ohio), US West (Oregon), Europe (Ireland), Europe (Frankfurt), Europe (Stockholm), Europe (Spain), Asia Pacific (Sydney), Asia Pacific (Hong Kong), Asia Pacific (Tokyo), Asia Pacific (Singapore), Asia Pacific (Mumbai), Asia Pacific (Malaysia), and Asia Pacific (Thailand). To learn more, visit the <a href="https://aws.amazon.com/elasticloadbalancing/elbproxy" rel="noopener noreferrer" target="_blank">ELB for Envoy product page</a>, <a href="https://aws.amazon.com/elasticloadbalancing/pricing/" rel="noopener noreferrer" target="_blank">ELB pricing page</a>, and <a href="http://docs.aws.amazon.com/elasticloadbalancing/latest/elbproxy/what-is.html" rel="noopener noreferrer" target="_blank">documentation</a>. To get started, visit the <a href="https://aws.amazon.com/elasticloadbalancing/getting-started/#Getting_started_with_the_AWS_Management_Console" rel="noopener noreferrer" target="_blank">AWS Management Console</a>.</p>
</details>

### AWS Lambda now supports orchestrating MicroVMs with Lambda durable functions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/lambda-durable-microvm/](https://aws.amazon.com/about-aws/whats-new/2026/11/lambda-durable-microvm/)
- **Published**: 2026-11-26 05:00:00
- **Fetched**: 2026-11-26 13:40:56

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Today, AWS announces a developer preview of a new extension for orchestrating <a href="https://aws.amazon.com/lambda/lambda-microvms/">Lambda MicroVMs</a> with <a href="https://aws.amazon.com/lambda/lambda-durable-functions/">Lambda durable functions</a>. The extension adds durable operations for running work on MicroVMs and managing their lifecycle. You can use the new operations to build software factories, security scanners, or orchestrate CI/CD jobs that run untrusted or agent-generated code in isolated sandboxes.</p> 
<p>With Lambda durable functions, you can build resilient, multi-step applications and AI workflows that run for up to one year, with built-in checkpointing and automatic retries. Lambda MicroVMs are a serverless compute primitive that provides VM-level isolation, near-instant launch and resume, and state preservation for running user-generated or AI-generated code. With this launch, you can run individual tasks in a MicroVM or launch a MicroVM session, where tasks share the same files and memory. The durable function manages the MicroVM lifecycle and runs each task as a durable operation. It checkpoints progress, retries failed tasks, and refreshes MicroVM tokens as needed. A single durable function can orchestrate multiple MicroVMs in parallel, and you can trigger it from event sources such as <a href="https://aws.amazon.com/sqs/">Amazon SQS</a> or <a href="https://aws.amazon.com/eventbridge/">Amazon EventBridge</a>. An optional worker library runs inside your MicroVM image to receive tasks, send heartbeats, and report results.</p> 
<p>The MicroVM extension is available as a developer preview for the AWS Durable Execution SDK for <a href="https://github.com/aws/aws-durable-execution-sdk-js/tree/main/packages/aws-durable-execution-sdk-js-extensions">TypeScript </a>and <a href="https://github.com/aws/aws-durable-execution-sdk-python/tree/main/packages/aws-durable-execution-sdk-python-extensions">Python</a>. To get started, add the extensions package to your function alongside the Durable Execution SDK (<a href="https://github.com/aws/aws-durable-execution-sdk-js/tree/main">JS/TS</a>, <a href="https://github.com/aws/aws-durable-execution-sdk-python/tree/main">Python</a>) and add the MicroVM worker library (<a href="https://github.com/aws/aws-durable-execution-sdk-js/tree/main/packages/aws-durable-execution-sdk-js-compute-worker">JS/TS</a>, <a href="https://github.com/aws/aws-durable-execution-sdk-python/tree/main/packages/aws-durable-execution-sdk-python-compute-worker">Python</a>) to your MicroVM image. Developer preview features may change, so do not use them for production workloads. The extension is available in all AWS Regions that support Lambda durable functions and Lambda MicroVMs.</p> 
<p>To learn more, see the MicroVM orchestration <a href="https://github.com/aws/aws-durable-execution-sdk-js/tree/main/packages/aws-durable-execution-sdk-js-extensions">documentation </a>and the <a href="https://github.com/aws/aws-durable-execution-sdk-js/tree/main/packages/aws-durable-execution-sdk-js-examples">sample application</a>. To share feedback, open an issue in the Durable Execution SDK GitHub repository in <a href="https://github.com/aws/aws-durable-execution-sdk-js/issues">JavaScript </a>or <a href="https://github.com/aws/aws-durable-execution-sdk-python/issues">Python</a>.</p>
</details>

- **Published**: 2026-11-26 05:00:00
- **Fetched**: 2026-11-26 13:40:56

<div class="entry-summary">
<p>Amazon CloudWatch Omni alerts can now automatically create PagerDuty incidents, so notifications flow directly into your existing incident management workflows. This reduces mean time to resolution (MTTR) by eliminating manual notification steps and ensuring consistent incident workflows.&nbsp;</p> 
<p>CloudWatch Omni is a fully managed AI-powered observability experience built on open standards that unifies monitoring for AI agents, applications, and infrastructure. PagerDuty is an incident management platform that routes alerts to the right on-call responders and coordinates their response. When an Omni alert fires, Omni creates a PagerDuty incident. In PagerDuty, Omni alerts follow your existing on-call schedules and escalation policies, so critical alerts reach the right responder wherever they are, at any hour. Omni alerts include severity, the affected service, and a link back to the related data in Omni, so responders have the context they need to diagnose the problem.</p> 
<p>For PagerDuty integration in Amazon CloudWatch Omni regional availability, see <a href="https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/omni-supported-regions.html">Supported Regions for CloudWatch Omni</a>.</p>

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-203-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-203-aws/)
- **Published**: 2026-11-26 04:41:20
- **Fetched**: 2026-11-26 07:55:13

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-203-AWS<br /> <b>Publication Date:</b> 11/25/2026 11:30 AM PST</p> 
<p><b>Description:</b></p> 
<p>AWS Systems Manager Automation provides AWS-managed runbooks that customers can run directly or through integrations such as AWS Config remediation. Session Manager, a capability of AWS Systems Manager, stores each account's regional session preferences in the SSM-SessionManagerRunShell document.</p> 
<p>We identified CVE-2026-134070, where improper input validation in the AWS-managed AWS Systems Manager Automation runbook AWSConfigRemediation-EnableSystemsManagerSessionManagerAuditLogsToS3 might allow an authenticated remote user who is permitted to run the runbook to set unintended configuration in the account's Regional Session Manager preferences document (SSM-SessionManagerRunShell) via a crafted S3KeyPrefix parameter value. This applies only when that document does not already exist in the Region. The unintended configuration can include arbitrary commands, which then run on managed instances when other users start Session Manager sessions.</p> 
<p><b>Impacted versions:</b> Revisions created before 2026-10-22 (UTC)</p>
