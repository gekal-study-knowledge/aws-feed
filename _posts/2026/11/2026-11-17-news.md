### AWS Marketplace Metering Service now supports decimal usage quantities

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-marketplace-metering-service-decimal-usage-quantities/](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-marketplace-metering-service-decimal-usage-quantities/)
- **Published**: 2026-11-17 02:39:00
- **Fetched**: 2026-11-17 10:29:51

<div class="entry-summary">
<p><a href="https://aws.amazon.com/marketplace">AWS Marketplace</a> Metering Service now supports decimal usage quantities in the MeterUsage and BatchMeterUsage APIs. Previously, AWS Marketplace sellers reported usage to both APIs in whole numbers, and now they can report usage with up to six decimal places.</p> 
<p>Sellers can price and meter in the units that match how customers consume their product, for example reporting 1.5 terabytes (TB) of storage instead of 1 or 2 TB. To report decimal quantities, sellers use the new UsageQuantityAsDecimal parameter in MeterUsage and QuantityAsDecimal parameter in BatchMeterUsage, and existing integrations that report whole numbers continue to work without changes. Usage allocations, which split reported usage into buckets by tags, also support decimal quantities with the new AllocatedUsageQuantityAsDecimal parameter.</p> 
<p>This new feature is available in all AWS <a href="https://docs.aws.amazon.com/marketplace/latest/developerguide/metering-regions.html">Regions</a> where AWS Marketplace Metering Service is available. To learn more, see <a href="https://docs.aws.amazon.com/marketplace/latest/APIReference/API_marketplace-metering_MeterUsage.html">MeterUsage</a> and <a href="https://docs.aws.amazon.com/marketplace/latest/APIReference/API_marketplace-metering_BatchMeterUsage.html">BatchMeterUsage</a> in the AWS Marketplace API Reference.</p>
</div>

### AWS KMS now supports key sharing with AWS Resource Access Manager

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/kms-key-sharing-resource-access-manager/](https://aws.amazon.com/about-aws/whats-new/2026/11/kms-key-sharing-resource-access-manager/)
- **Published**: 2026-11-17 03:00:00
- **Fetched**: 2026-11-17 10:29:51

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS Key Management Service (KMS) now integrates with AWS Resource Access Manager (RAM), giving you a simpler and more consistent way to share KMS keys across your AWS accounts, within your organization in AWS Organizations, and with specific IAM roles and users. You can now let trusted parties define the access they need through reusable managed permissions in RAM, while keeping full control of your keys and key policies. To share a key, create a resource share by selecting the keys to share, choosing a managed permission, and specifying the principals. You can use AWS managed permissions for common scenarios, or customer managed permissions (CMPs) authored by you or by trusted parties such as SaaS providers and central security teams.</p> 
<p>Sharing KMS keys through RAM makes enabling cross-account access faster to set up and safer to maintain. The trusted parties who need access to your keys can publish the policy once as a CMP, without the need for you to modify the key policies by hand. You simply fill in the values that scope it to your environment and attach it to the resource share. Your existing key policy is untouched, so you are always in control of your key as your environment grows. When a new policy version is available via an updated CMP, you decide when to apply it to your resource shares.</p> 
<p>This enhancement is built on new AWS RAM capabilities that are available for every resource type RAM supports. CMPs now support multiple policy statements and additional IAM condition operators, including StringNotEquals, BoolIfExists, and ArnLike, along with the ForAnyValue and ForAllValues prefixes, so you can express precise, least-privilege access. The&nbsp;parameterized managed permissions lets you place a temporary placeholder in CMPs that allows each resource share owner to customize and scope down CMPs to their environment, enabling CMPs to be reused and serve many accounts. CMPs can now be published and shared across accounts, so the authors can maintain one permission, manage its versions centrally, and see every resource share that uses it, while other accounts can use it directly without keeping their own copy.</p> 
<p>KMS key sharing with RAM is available in all AWS Regions where both services are available, except the Middle East (UAE) and Middle East (Bahrain).&nbsp;For more information, see <a href="https://docs.aws.amazon.com/kms/latest/developerguide/key-sharing-ram.html">Sharing KMS keys with AWS RAM</a> in the AWS KMS Developer Guide and <a href="https://docs.aws.amazon.com/ram/latest/userguide/working-with.html">Working with shared AWS resources</a> in the AWS RAM Developer Guide.</p>
</details>

### Set up, connect, and govern AI agents faster with Amazon WorkSpaces

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-workspaces-AI-agents-connect-govern](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-workspaces-AI-agents-connect-govern)
- **Published**: 2026-11-17 03:00:00
- **Fetched**: 2026-11-17 10:29:51

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Building AI agents has become essential. Across your organization, teams want agents to handle ERP transactions, work through a claims queue, and operate the same applications your people use every day. But how do you move from experiments to production? Before an agent touches real systems and real data, you need to verify who it acted on behalf of, what it did, and whether it stayed within the limits you set. Without that visibility, the agent stays stuck in testing, and the value is never realized.</p> 
<p>Earlier this year, we <a href="https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-workspaces-ai/">launched Amazon WorkSpaces for AI agents</a>, extending the power and security of a cloud work environment to agents, not just people. Today, we're excited to announce new capabilities that make it even easier to operate agents confidently across your enterprise and move them from proof of concept to governed production in fewer steps.&nbsp; You can set up new agents or connect the ones your builders have already built, run them under your own identity providers and policies, and keep a record of everything they do. You don't need to stitch together new tools or build custom monitoring.</p> 
<p>Setup used to mean configuring the machine by hand. Now, you can just describe what your agent needs to your AI coding assistant such as Claude Code, Codex, and Kiro. Guided by AWS MCP skills, the assistant builds the WorkSpace from defaults you can adjust. If your teams build on Amazon Bedrock AgentCore, you can connect an agent directly with your AWS credentials and skip writing any agent code. New tools also reduce agent costs and increase accuracy by letting an agent carry out a series of actions in a single call and use the computer-use actions its model already knows.</p> 
<p>But an agent that can work is not necessarily an agent you can trust with mission-critical work and sensitive data. This release gives you the same oversight over an agent that you have over the employees you manage. First, agents can now sign in through any identity provider (IdP) that supports OIDC, in addition to the existing SAML support. Administrators can send sign-in straight to their IdP, so users authenticate with their usual corporate credentials, and you don't build custom authentication. Second, with on-behalf-of (OBO) sign-in, an agent works as the signed-in user, with that user's existing directory identity, permissions, and Group Policies on the desktop.&nbsp;</p> 
<p>WorkSpaces now offers session replay, giving you a reviewable record of what your agent did. Session replay turns session screenshots into a video and pairs it with a plain-language transcript of the agent's actions. Both are stored in your own Amazon S3 bucket and encrypted with your own keys. Your security team can see what the agent saw, and your compliance team gets evidence to support audits.</p> 
<p>Together, these updates help move agents out of pilots and into real production scale. Your teams can keep working the way they do today, with agents working alongside them in familiar and trusted cloud work environments. And every one of those agents is held to the same identity, policy, and audit standards as the rest of your workforce. With WorkSpaces, you can bring AI agents into your business without rebuilding decades of software or needing a separate environment to govern them.</p> 
<p>To get started operating AI agents on WorkSpaces, <a href="https://docs.aws.amazon.com/appstream2/latest/developerguide/agent-access.html">visit our documentation page</a>.&nbsp;</p>
</details>

### Amazon Redshift now supports multi-statement transactions, conflict resolution, and time travel for Apache Iceberg

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/redshift-time-travel-multi-statement](https://aws.amazon.com/about-aws/whats-new/2026/11/redshift-time-travel-multi-statement)
- **Published**: 2026-11-17 05:30:00
- **Fetched**: 2026-11-17 10:29:51

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon Redshift now supports multi-statement transactions, automatic write-conflict resolution, and time travel for Apache Iceberg tables. You can run multi-step, concurrent transformation pipelines directly on Iceberg tables and audit the results, with the transaction semantics you expect from a data warehouse. This helps anyone writing to Iceberg tables at production scale. Batch jobs get all-or-nothing commits across multiple steps. Streaming and scheduled jobs can write to the same tables at the same time. Analysts, auditors, and AI agents can query a table as it existed at any point in time.</p> 
<p>With multi-statement transactions, you group several statements in a single BEGIN…COMMIT statement and publish them as one atomic Iceberg snapshot. This means a multi-step load such as a MERGE followed by a DELETE, can be commited together as one atomic operation, are never queryable in a half-applied state, and roll back cleanly if there's a failure. Automatic conflict resolution lets concurrent writes, such as streaming inserts alongside scheduled deletes, write to the same table and commit together when their changes don't overlap, instead of failing and retrying. Time travel lets you query a table as it existed at a past point in time with AS OF TIMESTAMP. You can use it to reproduce reports, audit changes, or recover from a bad write without keeping extra copies. These capabilities are available in all AWS commercial Regions for Amazon Redshift’s provisioned RG or serverless clusters that are writing to or querying Iceberg tables.. ### Amazon S3 Vectors now supports hybrid search combining vector and full text for more relevant search results

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/s3-vectors-hybrid-search/](https://aws.amazon.com/about-aws/whats-new/2026/11/s3-vectors-hybrid-search/)
- **Published**: 2026-11-17 06:00:00
- **Fetched**: 2026-11-17 10:29:51

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon S3 Vectors now supports hybrid search that combines vector similarity search with full-text search within a single query.&nbsp;By combining semantic meaning and exact term matching into a single ranked list of results, hybrid search captures both intent and precise terms for retrieval-augmented generation (RAG), agent memory, and search applications. This can deliver more relevant ranked results than either method alone. Hybrid search works with the same S3 Vectors APIs and maintains subsecond latency for infrequent queries and latency around 100 milliseconds or less for frequent queries.</p> 
<p>S3 Vectors is designed to provide the same elasticity, durability, and availability as Amazon S3, and it reduces the total costs of storing and querying vectors by up to 90% compared to alternative vector solutions. With hybrid search, customers can now store the data that they want to make full-text searchable alongside the vectors. Customers write data with the PutVectors API as they do today and include the searchable text as another metadata field. S3 Vectors then automatically indexes that field for full-text search with BM25 relevance scoring. By default, S3 Vectors uses a language-agnostic text analyzer to index this data which works across most languages, and customers can optionally select a language-specific analyzer for more accurate language-aware matching. To perform a hybrid query, customers send their query text strings alongside their query vector in a single QueryVectors call; S3 Vectors runs both a vector search and a full-text search, fuses the two with Reciprocal Rank Fusion (RRF), and returns a single ranked list of the top K requested results. Customers can also run full-text and vector queries separately to apply own ranking logic, search across multiple text fields in a single query, and enable full-text search on existing data in place.</p> 
<p>Hybrid search is available today in all commercial AWS Regions where Amazon S3 Vectors is available, and in the AWS China Regions. To get started, use the AWS CLI, AWS SDKs, or the Amazon S3 console. To learn more, visit the Amazon S3 Vectors <a href="https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-hybrid-search.html" rel="noopener noreferrer" target="_blank">documentation</a>, and the Amazon S3 <a href="https://aws.amazon.com/s3/pricing/" rel="noopener noreferrer" target="_blank">pricing page</a> for pricing.</p>
</details>

### Amazon ECR now replicates image deletions across regions and accounts

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/replication-deletes-amazon-ecr](https://aws.amazon.com/about-aws/whats-new/2026/11/replication-deletes-amazon-ecr)
- **Published**: 2026-11-17 07:07:00
- **Fetched**: 2026-11-17 10:29:51

<div class="entry-summary">
<p>Amazon Elastic Container Registry (Amazon ECR) now supports replicating image deletions and tag removals to your replication destinations. Previously, ECR replication copied images to destination regions and accounts but did not replicate deletions, requiring you to manage deletions separately in each location. With replication of deletes, your destination repositories stay consistent with the source automatically.</p> 
<p>Teams running multi-region or multi-account architectures no longer need to script or manually track image cleanup across every destination. When you delete an image or remove a tag in your source registry, whether directly or through a lifecycle policy, ECR propagates that deletion to each destination in the replication rule. Replicated deletions emit EventBridge events and are recorded in CloudTrail, so you have the same visibility into deletions as you do for image pushes.</p> 
<p>Replication of deletes is available in all AWS Regions where Amazon ECR is available, at no additional cost. To get started, update your replication configuration in the Amazon ECR console or AWS CLI. For more information, see the <a href="https://docs.aws.amazon.com/AmazonECR/latest/userguide/replication-delete.html">Amazon ECR User Guide</a>.</p>
</div>
