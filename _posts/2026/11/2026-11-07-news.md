# AWS Updates - 2026-11-07

## AWS What's New

### AWS launches support for amortization of EC2 Capacity Blocks for ML

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-ec2-capacity-blocks-ml/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-ec2-capacity-blocks-ml/)
- **Published**: 2026-11-07 00:00:00
- **Fetched**: 2026-11-07 03:49:32

<div class="entry-summary">
<p>AWS Data Exports for Cost and Usage Report (CUR) 2.0 and AWS Cost Explorer now amortize the upfront fee for Amazon EC2 Capacity Blocks for ML across the duration of each reservation. You can see the amortized cost of each instance launched into a Capacity Block and the amortized cost of unused capacity, so you can attribute your upfront fee to the workloads that used it and identify capacity that went unused.</p> 
<p>Previously, a Capacity Block's upfront fee appeared as a single charge on the purchase date, making it difficult to see how that cost was spread across usage over the reservation. Now the amortized cost appears alongside your instance usage, so you can allocate GPU costs to the teams, projects, and applications that ran on the reserved capacity. You can also see what share of your reservation went unused and plan future Capacity Block purchases. In CUR 2.0, the amortized costs appear in the reservation_amortized_upfront_fee_for_billing_period, reservation_effective_cost columns, and reservation_net_effective_cost shows the amortized cost after discounts. In Cost Explorer, select the amortized cost view to see Capacity Block costs allocated for&nbsp;the reservation.</p> 
<p>&nbsp;Amortization for Capacity Blocks is available at no additional charge in all AWS Regions except the AWS GovCloud (US) Regions and the China Regions. To learn more, see the <a href="https://docs.aws.amazon.com/cur/latest/userguide/table-dictionary-cur2.html">CUR 2.0 data dictionary</a> and <a href="https://docs.aws.amazon.com/cost-management/latest/userguide/ce-exploring-data.html">exploring your data using Cost Explorer</a>.</p>
</div>

## AWS Security Bulletins

### CVE-2026-122193 - Issue with Trusted Remote Execution Setup Guide - OS command injection in the example SSM documents in Trusted Remote Execution (REX)

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-173-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-173-aws/)
- **Published**: 2026-11-07 02:19:55
- **Fetched**: 2026-11-07 03:49:33

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-173-AWS<br /> <b>Publication Date:</b> 11/06/2026 09:00 AM PST</p> 
<p><b>Description:</b></p> 
<p>We identified CVE-2026-122193, an OS command injection issue in an example provided in the set-up documentation. The example included a script that creates AWS Systems Manager (SSM) documents (Rex-RO and Rex-RW) for running scripts on managed instances. Due to how the example script handled input parameters, a user with permissions to invoke the SSM document could supply crafted input that would run unintended operating system commands on the managed instance, outside of the REX sandbox. The scriptArgs parameter is affected by the same class of issue.</p> 
<p><b>Impacted versions:</b></p> 
<p>This is not an issue in a shipped REX artifact version.</p> 
<p><b>Refer to the article below for the most up-to-date and complete information.</b></p> 
<p><a href="https://aws.amazon.com/security/security-bulletins/2026-173-aws/">Read this article</a></p>
