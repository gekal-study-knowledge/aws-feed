## AWS What's New

### AWS launches support for amortization of EC2 Capacity Blocks for ML

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/aws-ec2-capacity-blocks-ml/](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-ec2-capacity-blocks-ml/)
- **Published**: 2026-11-07 00:00:00
- **Fetched**: 2026-11-07 03:49:32

<div class="entry-summary">
<p>AWS Data Exports for Cost and Usage Report (CUR) 2.0 and AWS Cost Explorer now amortize the upfront fee for Amazon EC2 Capacity Blocks for ML across the duration of each reservation. You can see the amortized cost of each instance launched into a Capacity Block and the amortized cost of unused capacity, so you can attribute your upfront fee to the workloads that used it and identify capacity that went unused.</p> 
<p>Previously, a Capacity Block's upfront fee appeared as a single charge on the purchase date, making it difficult to see how that cost was spread across usage over the reservation. Now the amortized cost appears alongside your instance usage, so you can allocate GPU costs to the teams, projects, and applications that ran on the reserved capacity. You can also see what share of your reservation went unused and plan future Capacity Block purchases. In CUR 2.0, the amortized costs appear in the reservation_amortized_upfront_fee_for_billing_period, reservation_effective_cost columns, and reservation_net_effective_cost shows the amortized cost after discounts. In Cost Explorer, select the amortized cost view to see Capacity Block costs allocated for&nbsp;the reservation.</p> 
<p>&nbsp;Amortization for Capacity Blocks is available at no additional charge in all AWS Regions except the AWS GovCloud (US) Regions and the China Regions. To learn more, see the <a href="https://docs.aws.amazon.com/cur/latest/userguide/table-dictionary-cur2.html">CUR 2.0 data dictionary</a> and <a href="https://docs.aws.amazon.com/cost-management/latest/userguide/ce-exploring-data.html">exploring your data using Cost Explorer</a>.</p>
</div>

### Amazon MSK Replicator is now available in AWS GovCloud (US-East, US-West) Regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-msk-replicator-additional-aws-regions](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-msk-replicator-additional-aws-regions)
- **Published**: 2026-11-07 01:00:00
- **Fetched**: 2026-11-07 08:37:28

<div class="entry-summary">
<p>You can now use Amazon MSK Replicator in the AWS GovCloud (US-East, US-West) Regions to replicate streaming data across <a href="https://aws.amazon.com/msk/">Amazon MSK</a> clusters and from external Apache Kafka clusters including on-premises, self-managed on AWS, or other cloud providers to Amazon MSK Provisioned clusters.</p> 
<p>MSK Replicator is a feature of Amazon MSK that automates data replication between Kafka clusters, eliminating the need to manage custom replication infrastructure or configure open-source tools. With MSK Replicator, you can easily build regionally resilient streaming applications for increased availability and business continuity. MSK Replicator provides automatic asynchronous replication across Kafka clusters, eliminating the need to write custom code, manage infrastructure, or setup cross-region networking. MSK Replicator automatically scales the underlying resources so that you can replicate data on-demand without having to monitor or scale capacity. MSK Replicator also replicates the necessary Kafka metadata including topic configurations, Access Control Lists (ACLs), and consumer group offsets. If an unexpected event occurs in a region, you can failover to the other AWS Region and seamlessly resume processing.</p> 
<p>You can get started with MSK Replicator from the Amazon MSK console or the Amazon CLI. To learn more, visit the MSK Replicator <a href="https://docs.aws.amazon.com/msk/latest/developerguide/msk-replicator.html"><u>documentation</u></a>, <a href="https://aws.amazon.com/msk/features/msk-replicator/"><u>product page</u></a>, and <a href="https://aws.amazon.com/msk/pricing/"><u>pricing page</u></a>.</p>
</div>

### Amazon Redshift expands SUPER data type to store strings up to 16 million bytes

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-redshift-expands-super-to-16-million-bytes/](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-redshift-expands-super-to-16-million-bytes/)
- **Published**: 2026-11-07 01:00:00
- **Fetched**: 2026-11-07 08:37:28

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><a href="https://aws.amazon.com/redshift/">Amazon Redshift</a> now supports individual strings up to 16 million bytes within <a href="https://docs.aws.amazon.com/redshift/latest/dg/r_SUPER_type.html">SUPER data types</a>. Once you opt in through a database parameter, this enhancement applies when ingesting structured or semi-structured data from JSON, PARQUET, TEXT, and CSV source files, and when transforming data through extract load and transform (ELT) processes. Previously, individual strings within SUPER data types were limited to 65,535 bytes.</p> 
<p>Storing large individual strings in the SUPER data type helps avoid complex pre-loading transformations needed to store the source data in Amazon Redshift. You can now directly ingest large individual strings greater than 65,535 bytes without extra processing (for example, lengthy documents like terms and conditions and contracts), making them queryable using SQL. Once the data is in Amazon Redshift, you can use the flexibility of PartiQL language to explore and navigate through the data or use string functions to transform the data.&nbsp;Functions such as <a href="https://docs.aws.amazon.com/redshift/latest/dg/JSON_PARSE.html">JSON_PARSE</a>, <a href="https://docs.aws.amazon.com/redshift/latest/dg/r_CONCAT.html">CONCAT</a>, and <a href="https://docs.aws.amazon.com/redshift/latest/dg/r_LISTAGG.html">LISTAGG</a> can now take input strings and return output strings up to 16 million bytes in length.</p> 
<p>This enhancement is available in all AWS Regions, including the AWS GovCloud (US) Regions, where Amazon Redshift is available. See the <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/" style="background-color: rgb(255,255,255);">AWS Region Table</a> for more details. To learn more, please visit our <a href="https://docs.aws.amazon.com/redshift/latest/dg/r_enable_large_strings_opt_in.html" style="background-color: rgb(255,255,255);">documentation</a> or <a href="http://aws.amazon.com/blogs/big-data/store-and-process-large-strings-in-amazon-redshift-super-columns">blog</a>.&nbsp;&nbsp;</p>
</details>

### Agent Registry is now generally available in AWS GovCloud (US-West) Region

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-agent-registry-govcloud-us-west/](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-agent-registry-govcloud-us-west/)
- **Published**: 2026-11-07 04:48:00
- **Fetched**: 2026-11-07 08:37:28

<div class="entry-summary">
<p>AWS Agent Registry, available through Amazon Bedrock AgentCore, is now available in the AWS GovCloud (US-West) Region.</p> 
<p>AWS Agent Registry is a fully managed discovery service that gives your organization a central catalog for organizing, curating, and discovering resources. You can publish MCP servers, tools, agents, agent skills, and custom resources to a searchable registry, and control what becomes discoverable through an approval workflow. People and AI agents can then find the right tools and agents through hybrid search, catalog browsing, and a native MCP endpoint.</p> 
<p>With Agent Registry in AWS GovCloud (US-West), public sector organizations and their partners get a single governed inventory of the agents and tools in their environment. Approval workflows and AWS CloudTrail audit logs support their compliance and oversight requirements.</p> 
<p>To get started, see the <a href="https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/registry.html">AWS Agent Registry documentation</a>.</p>
</div>

<p>We identified CVE-2026-122193, an OS command injection issue in an example provided in the set-up documentation. The example included a script that creates AWS Systems Manager (SSM) documents (Rex-RO and Rex-RW) for running scripts on managed instances. Due to how the example script handled input parameters, a user with permissions to invoke the SSM document could supply crafted input that would run unintended operating system commands on the managed instance, outside of the REX sandbox.
