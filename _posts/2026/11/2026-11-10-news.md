### Amazon Athena introduces system tables for observability, auditing, and usage analytics

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/athena-system-tables/](https://aws.amazon.com/about-aws/whats-new/2026/11/athena-system-tables/)
- **Published**: 2026-11-10 01:00:00
- **Fetched**: 2026-11-10 10:51:35

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><a href="https://aws.amazon.com/athena/">Amazon Athena</a> now offers system tables which automatically capture your usage data and make it available for observability, usage analysis, and audit use cases. When you enable system tables, usage data is available within minutes of query completion across your workgroups and stored as service-managed, read-only Iceberg tables on <a href="https://aws.amazon.com/s3/features/tables/">Amazon S3 Tables</a> with configurable retention. You can query it directly with Athena, while AWS manages the tables for you, including schema definition, partitioning, compaction, and snapshot maintenance, removing all operational burden.</p> 
<p>Athena provides usage data through APIs like GetQueryExecution, CloudWatch metrics, and CloudTrail logs. With this launch, usage data is also available as iceberg tables that you can search, filter, aggregate, and join directly without building or maintaining custom pipelines. Platform teams can query the query_executions table to build cost allocation dashboards that show data scanned by workgroup, by user, or by table using simple SQL statements, and without custom ETL. Additionally, the <a href="https://github.com/aws/agent-toolkit-for-aws/tree/main/skills/specialized-skills/system-table-skills">AWS Agent Toolkit</a> provides skills for querying system tables to surface usage patterns and optimization recommendations. Because the data is stored in the open Apache Iceberg format, you can also query it with <a href="https://duckdb.org/">DuckDB</a>, <a href="https://aws.amazon.com/pm/redshift/?trk=de3518c5-eb66-4ef5-ab94-ec69c34b86df&amp;sc_channel=ps&amp;ef_id=CjwKCAjws_DTBhB_EiwAXZknGRt-CfJCeVl3UL127isQ9p0q7arv1kekRNZF_pd22P4m8ReyZkhvahoCNwYQAvD_BwE&amp;gads_camp=23522747487&amp;gads_ag=196433734207&amp;gads_ad=795876995213&amp;gads_kw=amazon%20redshift&amp;gads_matchtype=e&amp;gads_network=g&amp;gads_device=c&amp;gads_geo=1027744&amp;gad_campaignid=23522747487&amp;gbraid=0AAAAADjHtp9cwZBKiv30JXu5qrPDkKSyb&amp;gclid=CjwKCAjws_DTBhB_EiwAXZknGRt-CfJCeVl3UL127isQ9p0q7arv1kekRNZF_pd22P4m8ReyZkhvahoCNwYQAvD_BwE">Amazon Redshift,</a> <a href="https://aws.amazon.com/emr/">Amazon EMR</a> or any other Iceberg-compatible engine.</p> 
<p>Athena system tables are available in all AWS Regions where Athena and Amazon S3 Tables are available. To get started, enable system tables from the Athena console or API. To learn more, visit the Amazon Athena <a href="https://docs.aws.amazon.com/athena/latest/ug/athena-system-tables.html">documentation </a>or the &nbsp;<a href="https://aws.amazon.com/blogs/big-data/amazon-athena-introduces-system-tables-for-query-execution-observability/" style="background-color: rgb(255,255,255);">blog</a>.</p>

### Introducing an open-source UI for graph analytics over data lakes with Amazon Neptune Analytics

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-graphover-datalakes-generally-available](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-graphover-datalakes-generally-available)
- **Published**: 2026-11-10 02:00:00
- **Fetched**: 2026-11-10 10:51:35

<div class="entry-summary">
<p>Today, AWS is introducing an open-source solution with a local web UI that helps customers turn data lake records into graphs for analysis with Amazon Neptune Analytics. By projecting selected records and relationships, customers can investigate connections across tables and run graph algorithms without building their own ETL pipelines.</p> 
<p>For example, a customer could project accounts and transactions into a graph to explore how accounts are connected or identify communities that may warrant investigation. Doing this today often means writing queries to prepare node and relationship data, creating a Neptune Analytics graph, and managing the import. Customers may also need to build a selective projection so they do not load an entire dataset for a narrower question.</p> 
<p>The new UI brings those steps into single workflow. To run graph analytics over iceberg tables, customers select an Athena catalog and database, define a property graph using SQL/PGQ, and preview rows before import. The solution runs the projection queries through Athena, stages the selected data in Amazon S3, and imports it into Neptune Analytics. The UI helps customers manage the resulting graph. They can open the loaded graph in Graph Explorer to query and visualize relationships. <a href="https://github.com/awslabs/nx-neptune"><b>[1]</b></a></p> 
<p>The UI runs locally and it is available in all regions where Amazon Neptune Analytics is available. To get started, see the <a href="https://github.com/awslabs/nx-neptune/blob/main/proxy/README.md"><b>setup instructions</b></a>.</p>
</div>

### AWS STS now supports cross-partition federation for AWS identities

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-sts-cross-partition](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-sts-cross-partition)
- **Published**: 2026-11-10 05:03:00
- **Fetched**: 2026-11-10 10:51:35

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS Security Token Service (AWS STS) now lets your workloads use their AWS Identity and Access Management (IAM) identity in one partition to get temporary credentials for an IAM role in a different partition, without storing long-term credentials, which can help improve your security posture. <a href="https://docs.aws.amazon.com/whitepapers/latest/aws-fault-isolation-boundaries/partitions.html">Partitions</a> are groups of AWS Regions, such as the commercial and AWS GovCloud (US) Regions, and each partition has an independent instance of IAM, creating a hard boundary between them. Previously, organizations that run workloads across partitions commonly relied on long-term credentials, such as IAM user access keys, that don't expire automatically.</p> 
<p>With this launch, your workload requests a short-lived token from AWS STS in its own partition and exchanges it for temporary AWS credentials in the other partition, using the existing <a href="https://docs.aws.amazon.com/STS/latest/APIReference/API_GetWebIdentityToken.html">GetWebIdentityToken</a> and <a href="https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRoleWithWebIdentity.html">AssumeRoleWithWebIdentity</a> APIs. You control which identities can access each role, apply governance across your organization, and audit token use in AWS CloudTrail in both partitions. This launch helps with scenarios such as consolidated security and compliance reporting, and centralized operations tooling. If your organization already operates a public key infrastructure (PKI), <a href="https://aws.amazon.com/iam/roles-anywhere/">IAM Roles Anywhere</a> is another option for cross-partition access.</p> 
<p>Cross-partition federation is available at no additional charge in all commercial AWS Regions, the AWS GovCloud (US) Regions, the China Regions, and the AWS European Sovereign Cloud (Germany) Region. To learn more, see <a href="https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_outbound_cross_partition.html">Federating AWS identities across AWS partitions</a> in the IAM User Guide and the blog post <a href="https://aws.amazon.com/blogs/security/simplify-cross-partition-access-with-aws-iam-outbound-identity-federation/">Simplify cross-partition access with AWS IAM outbound identity federation</a>.</p>
</details>

### Amazon CloudWatch Logs announces account-level retention policies

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-log-retention/](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-log-retention/)
- **Published**: 2026-11-10 07:15:00
- **Fetched**: 2026-11-10 10:51:35

<div class="entry-summary">
<p>Amazon CloudWatch Logs now supports account-level retention policies, so you can use a single policy to set how long log data is kept across all or subset of log groups in an AWS account. Account-level policies allow platform and security teams to bring each log group in line with their retention standards.</p> 
<p>With today's launch, you can create policies that cover all log groups in the account or apply to a specific set of log groups with names that start with a prefix, such as /aws/lambda. You can additionally choose whether it applies to existing log groups or only new ones. When more than one policy matches a log group, the longest retention period applies. For example, a central platform team can set a 90-day baseline for the account and a 1-year policy for log groups that start with /security to meet audit requirements, without tracking individual log group names.</p> 
<p>Account-level retention policies are available in all commercial AWS Regions except Middle East (Bahrain), and Middle East (UAE) at no additional cost . You can create and manage up to 20 policies per account and region using the AWS Management Console, AWS CLI, and AWS SDKs. Learn more in the &nbsp;<a href="https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/Working-with-log-groups-and-streams.html#account-level-retention-policies">CloudWatch Logs documentation</a>, and the &nbsp;<a href="https://docs.aws.amazon.com/AmazonCloudWatchLogs/latest/APIReference/API_PutAccountPolicy.html">API reference&nbsp;</a>.</p>

### Amazon Bedrock AgentCore now offers a Web Search API

- **Fetched**: 2026-11-10 10:51:35

<div class="entry-summary">
<p>Today, AWS announces the general availability of the Web Search API on Amazon Bedrock AgentCore, which lets you search the web with a single API call. Web Search on AgentCore has been available as an MCP tool through AgentCore Gateway. The new InvokeWebSearch API gives applications, custom agent loops, and data pipelines search results with no resources to create.</p> 
<p>The API returns ranked results from the Amazon-operated web index behind Web Search on AgentCore. Each result includes a text extract and, when available, the page title, URL, and publication time. You can filter each request by domain and publication time, for example to find recent product announcements or check a claim against trusted domains.</p> 
<p>You call the API with the AWS SDKs or the AWS Command Line Interface (AWS CLI) and authorize calls with AWS Identity and Access Management (IAM). Web Search API queries are billed at $7 per 1,000 queries, the same rate as Web Search through AgentCore Gateway, with no gateway charges.</p> 
<p>The Web Search API is available in US East (N. Virginia), US East (Ohio), US West (Oregon), Asia Pacific (Sydney), Asia Pacific (Tokyo), and Europe (Ireland). To learn more, see&nbsp;<a href="https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/web-search-api.html">Search the web with the InvokeWebSearch API</a>&nbsp;in the AgentCore Developer Guide, the&nbsp;<a href="https://aws.amazon.com/bedrock/grounding/web-search/">Web Search&nbsp;</a> page, and <a href="https://aws.amazon.com/bedrock/agentcore/pricing/">AgentCore pricing&nbsp;</a>.</p>

<p>AWS ParallelCluster CLI is an open source command line tool, distributed on PyPI as aws-parallelcluster. We identified CVE-2026-124033, an issue where the export-cluster-logs and export-image-logs commands in the AWS ParallelCluster CLI before version 3.16.0 contain a relative path traversal issue.
