### Amazon API Gateway REST APIs now support JWT authorizers

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-api-gateway-rest-jwt-authorizers](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-api-gateway-rest-jwt-authorizers)
- **Published**: 2026-11-18 00:00:00
- **Fetched**: 2026-11-18 04:33:21

<div class="entry-summary">
<p>Amazon API Gateway now offers a native JWT authorizer for REST APIs, a new authorizer type that validates JSON Web Tokens directly in the gateway. Until now, validating tokens from an OpenID Connect or OAuth 2.0 identity provider other than Amazon Cognito required a Lambda authorizer. You now configure token validation instead of writing and operating code for it.</p> 
<p>You can define one or more issuers, the audiences accepted for each, the signing algorithms you permit, and any additional claims a token may present. API Gateway verifies each token's signature, issuer, audience, expiry, and claims on every request. You can attach one authorizer to many methods and require different scopes on each. This fits machine-to-machine APIs, mobile and web backends, and multi-tenant APIs that accept tokens from several identity providers.</p> 
<p>The JWT authorizer works on Regional, edge-optimized, and private REST APIs, and is available in all commercial AWS Regions and the AWS GovCloud (US) Regions. To get started, see <a href="https://docs.aws.amazon.com/apigateway/latest/developerguide/rest-api-jwt-authorizer.html">Amazon API Gateway documentation</a> and <a href="https://aws.amazon.com/blogs/compute/securing-rest-apis-with-jwt-authorizers-in-amazon-api-gateway/">AWS blog post</a>.&nbsp;</p>
</div>

### Amazon VPC, AWS Transit Gateway, and AWS Cloud WAN now offer a 99.999% availability SLA for cross-Region traffic

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/vpc-tgw-cloudwan-99999-sla/](https://aws.amazon.com/about-aws/whats-new/2026/11/vpc-tgw-cloudwan-99999-sla/)
- **Published**: 2026-11-18 01:00:00
- **Fetched**: 2026-11-18 04:33:21

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS now offers a 99.999% availability service level agreement (SLA) for cross-Region traffic over Amazon Virtual Private Cloud (Amazon VPC) cross-Region peering, AWS Transit Gateway, and AWS Cloud WAN, with a new capability called Multipath Resilience. Multipath Resilience makes it easier to improve the resilience of mission-critical applications that send traffic across Regions, such as payment processing, financial trading, telephony, and live media streaming.</p> 
<p>The AWS backbone is highly resilient and connects Regions over physically diverse fiber paths. When a path fails, such as during a fiber cut, the network's automatic sub-second rerouting moves traffic to a healthy path. In the rare event that such mechanisms do not resolve the issue in a timely manner, such as when there's a partial degradation, it might take minutes for connectivity to be reestablished. Some applications, such as payment processing, financial trading, telephony, and live media streaming, can't tolerate single-digit seconds interruptions, let alone minutes of unavailability. Until now, customers running these applications relied on workarounds, including modifying their applications and operating systems to split a single connection into multiple connections, or replicating data into every Region to avoid cross-Region calls. These workarounds add complexity and don't always work, because applications can't control which network paths their traffic takes.</p> 
<p>Now, when you turn on Multipath Resilience for a cross-Region VPC peering connection, cross-Region Transit Gateway peering attachment, or cross-Region traffic on Cloud WAN, the network sends copies of each packet across physically diverse paths. It delivers whichever copy reaches your resources in the destination Region first and discards the duplicates. If one path drops packets, a copy is already in flight on another path, so your applications stay connected without waiting for the network protocols to reroute. Multipath Resilience moves this work out of your applications and into the network. Your applications keep using a single connection, with no changes to application code or operating systems, and no need to duplicate data to keep calls within a single Region.</p> 
<p>Multipath Resilience is now generally available in US East (N. Virginia), US East (Ohio), US West (N. California), US West (Oregon), and Europe (Ireland).</p> 
<p>To learn more, visit the <a href="https://aws.amazon.com/vpc/features/vpc-multipath-resilience/" rel="noopener noreferrer" target="_blank">Multipath Resilience documentation</a>. For SLA details, visit the <a href="https://aws.amazon.com/vpc/features/vpc-multipath-resilience/sla" rel="noopener noreferrer" target="_blank">Multipath Resilience SLA</a>. For pricing, visit the <a href="https://aws.amazon.com/vpc/pricing/" rel="noopener noreferrer" target="_blank">Amazon VPC pricing page</a>.</p>
</details>

### Amazon WorkSpaces Advisor now helps you find issues before your users notice them (Public Preview)

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/workspaces-advisor-proactive-troubleshooting-preview](https://aws.amazon.com/about-aws/whats-new/2026/11/workspaces-advisor-proactive-troubleshooting-preview)
- **Published**: 2026-11-18 01:00:00
- **Fetched**: 2026-11-18 04:33:21

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>When a WorkSpace is slow or won't connect, the IT administrator trying to help has traditionally had to dig through Amazon CloudWatch metrics, logs, and configuration data across multiple tools to find out why. And in the meantime, the user on the other end can't get their work done. In April this year, we launched Amazon WorkSpaces Advisor, an AI-powered agent that helps IT administrators diagnose and fix WorkSpaces performance, connectivity and provisioning issues and get users back to work faster. With Advisor, administrators can investigate a WorkSpace from the console and, in minutes, see the likely root cause and recommended actions they can take right away. Since then, we've continued to invest in Advisor so your team can spend less time chasing down issues one by one, and more time on the projects your business is counting on you to deliver.</p> 
<p>Today, we're excited to announce the preview of proactive troubleshooting in WorkSpaces Advisor, which moves your team from reacting to individual tickets to staying ahead of issues across your whole environment. Advisor can identify issues across your WorkSpaces, explain the likely cause of each one and recommend a fix. You don't need to start an investigation, wait for a user to report a problem, or set alarm thresholds first. &nbsp;</p> 
<p>If the same problem affects many WorkSpaces, Advisor will show it as a single issue with the likely cause and a recommended fix. &nbsp;Your team fixes the root cause once instead of chasing the same symptom one WorkSpace at a time. For example, Advisor can tell you when a group of WorkSpaces became unhealthy at the same time, when WorkSpaces are running low on CPU or memory, or when a certificate your users need to sign in is about to expire. That gives you time to act before a small issue turns into an outage or a queue of support tickets. You'll find these issues in the WorkSpaces console.</p> 
<p>Proactive troubleshooting also extends Advisor to your users, which means fewer tickets reach your help desk and the ones that do come with better information. When a session is slow or won't connect, Advisor will tell users whether the problem is with their device, their network, or their WorkSpace. It then walks them through the fixes you've approved, such as restarting their WorkSpace. When an issue does need IT, the user gets a clear explanation to pass along, so your team starts from a diagnosis instead of "my WorkSpace is slow." &nbsp;You stay in control because you decide which fixes users can make on their own, and you can turn this off for any directory.</p> 
<p>Proactive troubleshooting is available in preview at no additional charge in AWS commercial Regions where Amazon WorkSpaces Personal is available. Troubleshooting for end users requires version 5.37 or later of the WorkSpaces client for Windows, with the new experience turned on.&nbsp;Troubleshooting for users requires the WorkSpaces client for Windows version 5.37 or later with new experience. To get started, see the <a href="https://docs.aws.amazon.com/workspaces/latest/adminguide/workspaces-advisor.html">Amazon WorkSpaces Advisor Administration Guide.</a></p>
</details>

### CVE-2026-130621- Time-of-check time-of-use race condition in the port selection in AWS efs-utils

- **Link**: [https://aws.amazon.com/security/security-bulletins/rss/2026-186-aws/](https://aws.amazon.com/security/security-bulletins/rss/2026-186-aws/)
- **Published**: 2026-11-18 04:18:32
- **Fetched**: 2026-11-18 04:33:22

<div class="entry-summary">
<p><b>Bulletin ID:</b> 2026-186-AWS<br /> <b>Publication Date:</b> 11/17/2026 11:00 AM PST</p> 
<p><b>Description:</b></p> 
<p>A time-of-check time-of-use (TOCTOU) race condition in the local port selection in AWS efs-utils (amazon-efs-utils) before 3.3.5 might allow a user that can start EFS mounts on a shared host to read and write a different Amazon EFS or S3 Files file system that is mounted on that same host, under that mount's IAM identity and access point, via concurrent mount operations. Only file systems mounted on the same host at the same time can be affected.</p> 
<p><b>Impacted versions:</b><br /> - amazon-efs-utils &lt; v3.3.5<br /> - aws-efs-csi-driver &lt; v3.5.4</p>
