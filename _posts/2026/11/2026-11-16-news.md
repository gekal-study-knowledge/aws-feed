### AgentCore runtime instances are now available in six more AWS Regions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/agentcore-aws-regions/](https://aws.amazon.com/about-aws/whats-new/2026/11/agentcore-aws-regions/)

<p>Amazon Bedrock AgentCore <a href="https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-instances.html">runtime instances</a> are now available in six additional AWS Regions: US West (N. California), Canada (Central), Europe (London), Europe (Paris), Europe (Stockholm), and Asia Pacific (Seoul). Runtime instances run your agents on Amazon EC2 instances while AgentCore handles provisioning, patching, scaling, and lifecycle management.</p>

You can run your agents closer to your users to reduce invocation latency, and keep agent instances, storage volumes, and session data in the Region that your data residency requirements call for.</p>

You are charged for managing the provisioned compute, in addition to your Amazon EC2 costs.</p>

### AWS Secrets Manager adds managed external secrets support for Auth0, Okta, and Palo Alto Networks

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/secrets-manager-managed-external-secrets-auth0-okta-palo-alto/](https://aws.amazon.com/about-aws/whats-new/2026/11/secrets-manager-managed-external-secrets-auth0-okta-palo-alto/)
- **Published**: 2026-11-16 17:00:00
- **Fetched**: 2026-11-17 10:29:51

<div class="entry-summary">
<p>AWS Secrets Manager now supports managed external secrets for Auth0, Okta, and Palo Alto Networks. Long-lived credentials that are not rotated increase the risk of unauthorized access if exposed. Rotating a third-party credential requires coordinated updates to the external service and every application that uses it. You set a rotation schedule from the AWS Management Console or API. Secrets Manager rotates the credential and stores the current value without a custom rotation Lambda function.</p> 
<p>Secrets Manager offers self-rotation and administrator-assisted rotation for Auth0 credentials. With self-rotation, the target application replaces its own secret. With administrator-assisted rotation, a separate Auth0 application with Management API permissions replaces the target application's secret. For Okta, Secrets Manager offers administrator-assisted rotation with a separate administrator JSON Web Token (JWT) key and validates the replacement before deactivating the old secret. For Palo Alto Networks, Secrets Manager offers self-rotation, in which the current API key authorizes its replacement.</p> 
<p>Applications that already retrieve credentials from Secrets Manager receive the rotated value without a code change or deployment. </p> 
<p>These integrations join existing managed external secrets support for BigID, Cisco Security Platform, Confluent Cloud, Databricks, Datadog, GitLab, Jenkins, MongoDB Atlas, Netskope, Paddle, Salesforce, Snowflake, SonarQube, and Twilio.</p> 
<p>Auth0, Okta, and Palo Alto Networks managed external secrets are available in all AWS Regions where AWS Secrets Manager managed external secrets is supported. To learn more, visit the &nbsp;<a href="https://docs.aws.amazon.com/secretsmanager/latest/userguide/managed-external-secrets.html">AWS Secrets Manager managed external secrets documentation&nbsp;</a>.</p>
</div>

### IAM Identity Center now supports VPC endpoints and network access controls

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/iam-identity-center-vpc-endpoints/](https://aws.amazon.com/about-aws/whats-new/2026/11/iam-identity-center-vpc-endpoints/)
- **Published**: 2026-11-16 17:00:00
- **Fetched**: 2026-11-17 10:29:51

<div class="entry-summary">
<p>AWS IAM Identity Center now supports interface VPC endpoints powered by AWS PrivateLink and network access controls, enabling you to keep IAM Identity Center traffic private and restrict which networks can reach your&nbsp;IAM Identity Center services.</p> 
<p>Previously, IAM Identity Center rejected traffic arriving through VPC endpoints, requiring all sign-in and API traffic to use public endpoints. With this launch, you can create interface VPC endpoints for&nbsp;AWS access portal and service APIs to route traffic over the AWS private network. IAM Identity Center sign-in traffic flows through the AWS Sign-in VPC endpoint. You can attach VPC endpoint policies to each endpoint to scope which AWS organizations, accounts and resources are reachable through your private connection.</p> 
<p>Network access controls add a second layer of enforcement at the IAM Identity Center instance level. When enabled, you can require that all access arrive through a VPC endpoint, allow specific IP address ranges or VPCs as trusted sources, and exclude individual applications from enforcement to accommodate services that connect from outside your VPC. SCIM provisioning traffic from your external identity provider can be independently restricted to known IP address ranges. Network access controls are configured through the IAM Identity Center API and are disabled by default.</p> 
<p>This capability is available in all commercial AWS Regions and the AWS GovCloud (US) Regions at no additional cost. To learn more, see <a href="https://docs.aws.amazon.com/singlesignon/latest/userguide/vpc-interface-endpoints.html" rel="noopener noreferrer" target="_blank">Interface VPC endpoints</a> in the IAM Identity Center User Guide.&nbsp;For more information, visit the <a href="https://aws.amazon.com/iam/identity-center/" rel="noopener noreferrer" target="_blank">IAM Identity Center product page</a>.</p>
</div>

### AWS Backup adds logically air-gapped vault support for Amazon RDS

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-backup-air-gapped-vault-rds/](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-backup-air-gapped-vault-rds/)
- **Published**: 2026-11-16 17:00:00
- **Fetched**: 2026-11-17 10:29:51

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>AWS Backup logically air-gapped vault now supports Amazon Relational Database Service (Amazon RDS) DB instances. Logically air-gapped vaults are a type of AWS Backup vault that stores immutable, isolated backups, which are locked by default with AWS Backup Vault Lock in compliance mode. Secure sharing across accounts and AWS Organizations enables direct restore, reducing recovery time from a data loss event.</p> 
<p>You can now protect your Amazon RDS DB instances in logically air-gapped vaults. A logically air-gapped vault stores immutable backups that are locked by default, and isolated with encryption using AWS owned keys or customer-managed keys. This helps reduce the risk of downtime, ensure business continuity, and meet compliance requirements.</p> 
<p>To get started, use the AWS Backup console, AWS Command Line Interface (CLI), or AWS SDKs. Assign your RDS DB instances to a backup plan and specify a logically air-gapped vault in the same AWS Region as the copy destination. Share the vault for recovery or restore testing with other accounts using AWS Resource Access Manager (RAM), or safeguard vault access during account compromise using <a href="https://docs.aws.amazon.com/aws-backup/latest/devguide/multipartyapproval.html" rel="noopener noreferrer" target="_blank">Multi-party approval</a>. Once shared, you can initiate direct restore jobs from that account.</p> 
<p>This support is available in most AWS Regions where both logically air-gapped vault and Amazon RDS are available. For more information and detailed regional availability, visit the <a href="https://docs.aws.amazon.com/aws-backup/latest/devguide/backup-feature-availability.html#features-by-resource" rel="noopener noreferrer" target="_blank">AWS Backup documentation</a>. To learn more about logically air-gapped vaults for RDS, read the <a href="https://aws.amazon.com/blogs/storage/introducing-aws-backup-logically-air-gapped-vault-support-for-amazon-rds/" rel="noopener noreferrer" target="_blank">launch blog</a> and visit the <a href="https://docs.aws.amazon.com/aws-backup/latest/devguide/logicallyairgappedvault.html" rel="noopener noreferrer" target="_blank">feature documentation</a> and <a href="https://aws.amazon.com/backup/pricing/">pricing page</a>.</p>
</details>

### AWS WAF advanced rate-based rules are now available in AWS GovCloud (US), Thailand, and Mexico

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/waf-advanced-rate-rules-available/](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-advanced-rate-rules-available/)
- **Published**: 2026-11-16 17:00:00
- **Fetched**: 2026-11-17 10:29:51

<div class="entry-summary">
<p>AWS WAF advanced rate-based rules are now available in the Asia Pacific (Thailand), Mexico (Central), AWS GovCloud (US-East), and AWS GovCloud (US-West) Regions. Customers in these Regions can now aggregate requests using custom keys and choose a 1 or 2 minute evaluation window in addition to the existing 5 and 10 minute options, the same capabilities already available in other AWS Regions.</p>
<p>A rate-based rule counts requests and applies an action, such as Block or CAPTCHA, when the request rate exceeds a limit you set. Previously, rate-based rules in these Regions could aggregate requests only by IP address and used a 5 or 10 minute evaluation window. Now you can aggregate by request components such as HTTP headers, cookies, query strings, URI paths, HTTP methods, and label namespaces, and combine up to five of them into a composite key. For example, you can limit login attempts per IP address and User-Agent pair, or per session cookie, which helps against attacks spread across many IP addresses. A shorter evaluation window detects request floods sooner, and a longer window catches slower, sustained attacks.</p>
<p>You can configure these options in the AWS WAF console, the AWS CLI and SDKs, and AWS CloudFormation. There is no additional charge for these capabilities, and standard AWS WAF pricing applies. Advanced rate-based rules are now available in all commercial AWS Regions where AWS WAF is available and in the AWS GovCloud (US) Regions. To learn more, see <a href="https://docs.aws.amazon.com/waf/latest/developerguide/waf-rule-statement-type-rate-based.html" target="_blank">Using rate-based rule statements</a> in the AWS WAF Developer Guide.</p>
</div>

### AWS announces Networking Flexible Cost Allocation for Amazon VPC

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/networking-flexible-cost-allocation/](https://aws.amazon.com/about-aws/whats-new/2026/11/networking-flexible-cost-allocation/)
- **Published**: 2026-11-16 17:00:00
- **Fetched**: 2026-11-17 10:29:51

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Amazon Virtual Private Cloud (VPC) now supports Networking Flexible Cost Allocation (FCA), which splits shared networking costs by the resources that actually drive them, so you can see what each team or application used. Until now, <a href="https://aws.amazon.com/aws-cost-management/aws-cost-and-usage-reporting/">AWS Cost and Usage Report</a> (CUR), including CUR 2.0 in AWS Data Exports, showed networking usage as a single item, and most customers split it across teams with custom scripts and manual estimates. FCA splits this line item by the resources that generated it. It supports NAT gateway data processing and data transfer, including traffic to the internet, and in-Region Amazon Elastic Compute Cloud (Amazon EC2) and VPC peering data transfer.</p>
<p>Today, when several teams share a resource such as a NAT gateway, the account that owns it pays the full cost and can't see which team or application drove it. To work around this, some customers built custom scripts to analyze VPC Flow Logs, which takes ongoing engineering effort. Others used fixed-percentage splits, which overcharge some teams and undercharge others. FCA breaks down usage based on traffic sources, helping you accurately track financial metrics based on applications and teams. To get started, attach a cost allocation policy to a NAT gateway, VPC peering connection, or Amazon EC2 instance, then select Networking flexible cost allocation under split cost allocation data in the AWS Billing and Cost Management console. Allocated line items appear in your CUR within 24 hours. FCA changes only how costs are shown in your reports. Your bill and total charges stay the same.</p>
<p>FCA is available at no additional charge. It's supported in all AWS commercial Regions except Middle East (Bahrain) and Middle East (UAE). It's also available in the China Regions. It is not available in the AWS GovCloud (US) Regions. To learn more, visit the <a href="https://docs.aws.amazon.com/vpc/latest/userguide/networking-flexible-cost-allocation.html" target="_blank">Networking FCA product page</a>.</p>
</details>

### AWS IAM Identity Center now supports ForceAuthn in SAML requests

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/iam-identity-center-reauth/](https://aws.amazon.com/about-aws/whats-new/2026/11/iam-identity-center-reauth/)
- **Published**: 2026-11-16 17:00:00
- **Fetched**: 2026-11-17 10:29:51

<div class="entry-summary">
<p>AWS IAM Identity Center now gives you the option to require workforce users to re-authenticate with your external identity provider (IdP) each time their user interactive session expires. By default, when a user's session expires, IAM Identity Center renews it through the user's existing IdP session, and the user isn't prompted to sign in again. For organizations with strict security or compliance requirements that mandate explicit user verification at regular intervals, this automatic renewal may not meet policy requirements.</p> 
<p>When you set user re-authentication to Required and a user's user interactive session expires, IAM Identity Center prompts the user to re-authenticate with your external IdP. This helps you enforce stronger sign-in controls for regulated workloads. IAM Identity Center implements this by adding the SAML 2.0 ForceAuthn attribute to the SAML request sent to your IdP.</p> 
<p>You can configure user re-authentication for any IAM Identity Center instance (organization or account) that's connected to an external IdP as its identity source. The setting applies only to service provider initiated sign-ins, where users sign in through your AWS access portal URL. Changes to the user re-authentication setting are logged in AWS CloudTrail, so you can audit when it was turned on or off.</p> 
<p>User re-authentication is available in all AWS Regions where IAM Identity Center is available at no additional cost. To learn more, see <a href="https://docs.aws.amazon.com/singlesignon/latest/userguide/require-user-reauthentication.html" rel="noopener noreferrer" target="_blank">Require user re-authentication</a> in the AWS IAM Identity Center User Guide.</p>
</div>
