### AWS Emulator is now available for building and testing AWS applications locally

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-emulator-now-available/](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-emulator-now-available/)
- **Published**: 2026-11-12 02:00:00
- **Fetched**: 2026-11-12 10:15:17

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><a href="https://aws.amazon.com/products/developer-tools/emulator/">AWS Emulator</a> is now available for building and testing AWS applications locally.</p> 
<p>Starting today, you can use AWS Emulator to build and test AWS applications on your computer or in your continuous integration (CI) environment. Your existing AWS SDK and CLI calls go to AWS Emulator and come back in milliseconds, so you and your coding agents can find and fix errors locally, with no deployments or AWS account required.</p> 
<p>You create and manage resources with the same AWS SDK and AWS CLI calls you use with AWS, signed with credentials the emulator provides. <i>For the operations it supports, AWS Emulator returns the same result as AWS for valid calls and the same errors for invalid ones. Operations it doesn’t yet support return 501 Not Implemented.</i>&nbsp;AWS Emulator keeps the state of your resources in memory until you stop it. Each copy you start gets its own port, keys and in-memory state, so agents, test suites, and CI jobs never see each other’s resources. For example, a coding agent can create an Amazon DynamoDB table, test against it offline, and fix its code before it deploys.</p> 
<p>Services in AWS Emulator are generated from the API models AWS publishes, the same models behind the AWS SDKs. When AWS adds a service or API, it shows up in AWS Emulator, and its behavior is filled in and verified release by release. To see how its responses compare to AWS, review the <a href="http://docs.aws.amazon.com/emulator/latest/userguide/fidelity.html">AWS Emulator fidelity report</a>.</p> 
<p>AWS Emulator doesn’t depend on an AWS Region. AWS Emulator has no additional service fee. You pay only for AWS resources when you deploy to AWS. Its source code is published under the CC0 1.0 Universal public domain dedication. To get started, see the <a href="https://docs.aws.amazon.com/emulator">AWS Emulator documentation</a>, or view the source in the <a href="https://github.com/aws/aws-emulator">AWS Emulator GitHub repository</a>.</p>
</details>

### Amazon EKS Auto Mode now supports security groups for Pods

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-eks-auto-mode-security-groups-for-pods/](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-eks-auto-mode-security-groups-for-pods/)
- **Published**: 2026-11-12 02:26:00
- **Fetched**: 2026-11-12 10:15:17

<div class="entry-summary">
<p>Amazon EKS Auto Mode now supports security groups for Pods, letting you apply dedicated Amazon EC2 security group rules to individual Pods. Different workloads on the same node can carry different security groups, giving your Pods network-level segmentation without creating separate node pools for each application.</p> 
<p>Security groups for Pods extends your existing AWS network controls to the Pod level, so your Pods can reach resources such as Amazon RDS and Amazon ElastiCache databases that authorize connections by security group under the same rules the rest of your VPC uses. You define which Pods receive which security groups with a SecurityGroupPolicy resource, and Pods not matched by a policy keep using their node’s security groups.</p> 
<p>Security groups for Pods is included as part of EKS Auto Mode at no additional charge and is available on clusters running Kubernetes version 1.36 or later, in all AWS Regions where EKS Auto Mode is supported. To learn more, see <a href="https://docs.aws.amazon.com/eks/latest/userguide/auto-sgp.html">Security groups for Pods</a> in the Amazon EKS User Guide and the <a href="https://aws.amazon.com/eks/auto-mode/">Amazon EKS Auto Mode</a> product page.</p>
</div>

### AWS Lambda MicroVMs now supports the x86 CPU architecture

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-microvms-x86-architecture/](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-microvms-x86-architecture/)
- **Published**: 2026-11-12 03:00:00
- **Fetched**: 2026-11-12 10:15:17

<div class="entry-summary">
<p>AWS Lambda MicroVMs now supports the x86 CPU architecture, so you can run your existing x86 applications, tools, and software dependencies without recompiling or porting them. When you create a MicroVM image, you can now choose between x86 and Arm (AWS Graviton) to give each user or job an isolated MicroVM on the architecture your workload uses.</p> 
<p>Lambda MicroVMs is a serverless compute primitive that provides VM-level isolation, near-instant launch and resume, and state preservation for running user or AI-generated code, in applications such as AI coding assistants, CI/CD runners, interactive development environments, and vulnerability scanners. Today’s launch enables you to run x86-based workloads on Lambda MicroVMs as-is. For workloads that run on Arm, you can continue using AWS Graviton processors which is the default CPU architecture option.</p> 
<p>To start building x86 workloads on Lambda MicroVMs, choose the x86 architecture when you create a MicroVM image from your Dockerfile, then launch MicroVMs from that image. You can use&nbsp;MicroVMs through the AWS Lambda console, AWS CloudFormation, AWS Cloud Development Kit, or with your preferred agentic development tools using the <a href="https://github.com/aws/agent-toolkit-for-aws/tree/main/skills/specialized-skills/serverless-skills/aws-lambda-microvms">Agent Toolkit for AWS</a>.</p> 
<p>Support for the x86&nbsp;CPU architecture is available in all AWS Regions where Lambda MicroVMs is available, except Asia Pacific (Hong Kong), Asia Pacific (Malaysia), Asia Pacific (Thailand), and Europe (Spain). To learn more, visit the <a href="https://docs.aws.amazon.com/lambda/latest/dg/lambda-microvms-guide.html">AWS Lambda MicroVMs developer guide</a>. For information on pricing, see <a href="https://aws.amazon.com/lambda/pricing/">Lambda MicroVMs pricing</a>.</p>

### Amazon Cognito now supports user pool session management

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cognito-session-management/](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cognito-session-management/)
- **Published**: 2026-11-12 04:00:00
- **Fetched**: 2026-11-12 10:15:17

<div class="entry-summary">
<p>Amazon Cognito now supports session management for user pools, giving you visibility into and control over the sessions your users establish when they sign in to your applications. Single sign-on (SSO) sessions are created when a user signs in through managed login and let them access other app clients without re-authenticating. Token sessions are created when a user signs in to an app client and receives tokens. Session management lets you list a user's active SSO and token sessions across all devices and app clients and revoke any of them on demand. You can also now configure how long each app client reuses an SSO session before requiring re-authentication, instead of the previous fixed one-hour duration.</p> 
<p>Each session includes details such as session type, app client ID, device type, last activity time and location, and initial sign-in time, so you can build your own end-user or admin session experiences. You can revoke an individual session, optionally with its linked sessions, or use global sign-out to end all sessions associated with one user. You can also set a maximum number of active token sessions per user.</p> 
<p>Session management is available for user pools in the Essentials or Plus feature plans in all AWS Regions where Amazon Cognito is available.<i> </i>You can manage sessions using the AWS Management Console, API, AWS Command Line Interface, and AWS Software Development Kits, and configure settings with AWS CloudFormation. Visit the <a href="https://docs.aws.amazon.com/cognito/latest/developerguide/managing-user-sessions.html">Developer Guide</a> and <a href="https://docs.aws.amazon.com/cognito-user-identity-pools/latest/APIReference/API_Operations.html">API Reference</a> for details.&nbsp;</p>
</div>

### AWS Cloud WAN now supports Flow Logs

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/11/aws-cloud-wan-flow-logs/](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-cloud-wan-flow-logs/)
- **Published**: 2026-11-12 05:05:00
- **Fetched**: 2026-11-12 10:15:17

<div class="entry-summary">
<p>AWS Cloud WAN now supports VPC Flow Logs, giving you central visibility into IP traffic across your global network. Flow Logs capture detailed information for each flow, so you can understand how traffic moves across your core network without leaving your AWS Cloud WAN account.</p> 
<p>Until now, network administrators had to stitch together VPC Flow Logs from many VPCs, accounts, and Regions to see traffic across their global network. They often depended on other teams for access to those logs. Cloud WAN Flow Logs give core network owners one consolidated view of traffic between VPCs, Regions, and on-premises networks connected over AWS Direct Connect, AWS Site-to-Site VPN, or SD-WAN. You can use this data to troubleshoot connectivity and performance problems, plan capacity from historical bandwidth trends, find unusual traffic patterns, and keep records for security and compliance. Flow log records include IP addresses, ports, protocol, traffic volume, and packet-loss counters, along with Cloud WAN metadata such as segment, Region, service insertion hops and attachment details. You can turn on Flow Logs for an entire core network, a single core network edge, or individual attachments. You can publish them to Amazon CloudWatch Logs, Amazon Simple Storage Service (Amazon S3), or Amazon Data Firehose. Cloud WAN adds no charge for Flow Logs. Standard charges apply for each destination.</p> 
<p>Cloud WAN Flow Logs are available in all AWS Regions where AWS Cloud WAN is available. You can get started with the AWS Management Console, AWS CLI, or API. To learn more, see AWS Cloud WAN Flow Logs&nbsp;<a href="https://docs.aws.amazon.com/network-manager/latest/cloudwan/cwan-flow-logs">user guide</a>.</p>
</div>
