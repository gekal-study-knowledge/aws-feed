### AWS India customers can now use UPI Scan and Pay for sign-up and payments

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/04/aws-india-upi-scanandpay/](https://aws.amazon.com/about-aws/whats-new/2026/04/aws-india-upi-scanandpay/)
- **Published**: 2026-05-08 00:00:00
- **Fetched**: 2026-05-08 01:08:02

<p>India customers can now use <a href="https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/edit-aispl-payment-method.html#using-aispl-autopay-UPI">UPI (Unified Payments Interface)</a> Scan and Pay to sign up for AWS or make payments to their invoices.<br /> <br /> UPI is a popular and convenient payment method in India, which facilitates instant bank-to-bank transfers between two parties through mobile phones with internet. The new Scan and Pay experience simplifies payments by allowing customers to scan a QR code displayed on the AWS Console using their UPI mobile app (such as Google Pay, PhonePe, Paytm, or Amazon Pay), eliminating the need to manually enter a UPI ID.<br /> <br /> This enhancement makes the UPI payment experience more secure, convenient, and error-free for customers signing up for AWS or making one-time payments. Scan and Pay reduces friction and aligns with how customers commonly use UPI for everyday transactions. Customers can also set up UPI AutoPay using Scan and Pay for automatic monthly payments up to INR 15,000.<br /> <br /> To use this feature, customers log in to the AWS Console and select UPI as their payment method during signup or when making a payment. A QR code is displayed on screen, which customers scan using their UPI mobile app to verify and authorize the transaction.<br /> <br /> To learn more, see <a href="https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/edit-aispl-payment-method.html"><u>Managing Payment Methods in India</u></a><u>.</u></p>

### Amazon SageMaker HyperPod now supports AMI-based node lifecycle configuration for Slurm clusters

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/05/amazon-sagemaker-hyperpod-ami-based-node/](https://aws.amazon.com/about-aws/whats-new/2026/05/amazon-sagemaker-hyperpod-ami-based-node/)
- **Published**: 2026-05-08 01:00:00
- **Fetched**: 2026-05-08 05:11:32

<p>Amazon SageMaker HyperPod now supports AMI-based configuration that provisions Slurm cluster nodes with the software and configurations needed for a production-ready environment to run AI/ML training workloads. This removes the need to download, configure, or upload lifecycle configuration scripts to Amazon S3. With fewer operational steps to prepare a cluster and no lifecycle configuration scripts executing during node provisioning, cluster creation time is significantly reduced, so you can start running jobs sooner.</p> 
<p>AMI-based configuration includes required software such as Docker, Enroot, and Pyxis, and configurations such as Slurm accounting, SSH key generation, Slurm log rotation and user home directory setup. To enable AMI-based configuration, omit the LifeCycleConfig block from the instance group configuration when creating clusters using the CreateCluster API, or when using the SageMaker AI console, select "None" under Lifecycle scripts in Custom setup. For additional customization on top of the AMI-based configuration baseline, an extension script can be provided, allowing you to focus only on what capabilities and software to add, such as user configuration, observability, or LDAP integration.</p> 
<p>Extension scripts can be configured when creating clusters through both the API and the SageMaker AI console. Using the CreateCluster API, specify the new OnInitComplete parameter and SourceS3Uri in the LifeCycleConfig block. Via the console, provide the S3 URI to the extension script in the "Extension script file in S3" field in Custom setup. For advanced use cases that require full control over provisioning, custom lifecycle configuration scripts remain fully supported through both the API and the SageMaker AI console.</p> 
<p>This feature is available in all AWS Regions where SageMaker HyperPod is available. To get started with creating HyperPod Slurm clusters with AMI-based node lifecycle configuration, see <a href="https://docs.aws.amazon.com/sagemaker/latest/dg/smcluster-getting-started-slurm-cli.html" rel="noopener noreferrer" target="_blank">Getting started with SageMaker HyperPod using the AWS CLI</a> or <a href="https://docs.aws.amazon.com/sagemaker/latest/dg/smcluster-getting-started-slurm-console.html" rel="noopener noreferrer" target="_blank">Getting started with SageMaker HyperPod using the SageMaker AI console</a> in the SageMaker AI developer guide.</p>

### AWS Elemental MediaTailor launches Monetization Functions

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/05/aws-elemental-mediatailor-monetization-functions](https://aws.amazon.com/about-aws/whats-new/2026/05/aws-elemental-mediatailor-monetization-functions)
- **Published**: 2026-05-08 02:20:00
- **Fetched**: 2026-05-08 05:11:32

<p>AWS Elemental MediaTailor now supports&nbsp;monetization&nbsp;functions,&nbsp;a new capability that lets customers customize how MediaTailor builds ad decision server (ADS) requests and manages session data during ad-personalized playback.&nbsp;With&nbsp;monetization&nbsp;functions, customers can call external APIs and run inline data transformations at defined points in the playback session —&nbsp;eliminating&nbsp;the need to build and&nbsp;operate&nbsp;middleware between the player and the ADS.</p> 
<p>Common use cases include resolving hashed email addresses into&nbsp;privacy-compliant identity envelopes through providers&nbsp;such as&nbsp;LiveRamp,&nbsp;appending contextual metadata from a content management system to every ad request&nbsp;through providers like&nbsp;GraceNote,&nbsp;activate header bidding workflows through providers like The Trade Desk&nbsp;and running A/B tests across multiple ad decision servers. Monetization&nbsp;functions&nbsp;are fail-open&nbsp;by design: if a function&nbsp;encounters&nbsp;an error, exceeds its timeout, or hits a resource limit, MediaTailor discards the output and&nbsp;proceeds&nbsp;with default ad-insertion behavior, so viewers' playback is never interrupted.</p> 
<p>Monetization&nbsp;functions&nbsp;is&nbsp;available at general availability in all AWS regions where AWS Elemental MediaTailor operates.&nbsp;You are billed per&nbsp;lifecycle&nbsp;hook invocation at a flat rate that does not depend on&nbsp;the number,&nbsp;type,&nbsp;or complexity&nbsp;of functions.&nbsp;For full details, see the&nbsp;<a href="https://aws.amazon.com/mediatailor/pricing/" title="MediaTailor pricing page">MediaTailor pricing page</a>, the&nbsp;<a href="https://aws.amazon.com/mediatailor/pricing/" title="MediaTailor User Guide">Monetization Functions section of the MediaTailor User Guide</a>, and the&nbsp;<a href="https://docs.aws.amazon.com/mediatailor/latest/ug/monetization-functions.html" title="MediaTailor product page">MediaTailor product page</a>.<a href="https://aws.amazon.com/mediatailor/pricing/" title="MediaTailor pricing page"></a></p>

### AWS Capabilities by Region now supports availability notifications

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/05/aws-regional-planning-tool-notification](https://aws.amazon.com/about-aws/whats-new/2026/05/aws-regional-planning-tool-notification)
- **Published**: 2026-05-08 02:48:00
- **Fetched**: 2026-05-08 03:21:17

<p>Today, AWS announces availability notifications for AWS Capabilities by Region in AWS Builder Center, a new subscription-based system that automatically alerts builders when&nbsp;an&nbsp;AWS service(s)&nbsp;and/or&nbsp;features(s)&nbsp;become available in their target Regions.&nbsp;Availability notifications&nbsp;make&nbsp;it easy for builders to&nbsp;track availability&nbsp;of&nbsp;1,500+&nbsp;services and features across&nbsp;37&nbsp;AWS&nbsp;Regions,&nbsp;accelerating&nbsp;infrastructure planning and deployment decisions.</p> 
<p>With availability notifications,&nbsp;builders can subscribe&nbsp;at&nbsp;the service level through&nbsp;AWS Builder Center UI, and the subscription automatically covers all underlying features across selected Regions, so&nbsp;there's&nbsp;no need to track each feature individually. Notifications are delivered through two channels: instantaneous in-app alerts within AWS Builder Center, and a&nbsp;consolidated&nbsp;weekly email digest.&nbsp;Subscriptions and notification preferences can be managed through&nbsp;Settings &gt; Notifications&nbsp;in AWS Builder Center. Common use cases include tracking a specific capability launch, monitoring service parity across&nbsp;AWS&nbsp;Regions, and preparing for upcoming migrations or&nbsp;Regional&nbsp;expansions. For example, a solutions architect expanding a generative AI application into new Regions can subscribe to Amazon Bedrock and receive automatic&nbsp;updates&nbsp;as Knowledge Bases, Guardrails, and other features become available.</p>

- **Link**: [https://aws.amazon.com/about-aws/whats-new/2026/05/smus-identity-user-management/](https://aws.amazon.com/about-aws/whats-new/2026/05/smus-identity-user-management/)

- **Fetched**: 2026-05-08 05:11:32

<p>Amazon SageMaker Unified Studio announces new administration features that give administrators more control over identity configuration and user management for both IAM and Identity Center domain types.<br /> <br /> In SageMaker IAM domains, administrators can now onboard users through single sign-on by configuring AWS IAM Identity Center. After configuration, administrators can add IAM roles, IAM users, IAM Identity Center users, and IAM Identity Center groups as project members. Teams can collaborate on project data and resources regardless of how individual members authenticate. Administrators can set up IAM Identity Center integration in the SageMaker Unified Studio admin portal. SageMaker Unified Studio creates a unique user session for each federated user, so users sharing the same role don't overwrite each other's work. Administrators can audit individual actions even when multiple users share a single IAM role.<br /> <br /> With these features, customers can use IAM identity or IAM Identity Center corporate identity across both domain types, giving teams flexibility to collaborate in SageMaker Unified Studio regardless of their authentication method.<br /> <br /> These features are available in the following <a href="https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/">AWS Regions</a>: Asia Pacific (Mumbai), Asia Pacific (Seoul), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Tokyo), Canada (Central), Europe (Frankfurt), Europe (Ireland), Europe (London), Europe (Paris), Europe (Stockholm), South America (São Paulo), US East (N. Virginia), US East (Ohio), and US West (Oregon).<br /> <br /> To learn more, visit the <a href="https://docs.aws.amazon.com/sagemaker-unified-studio/latest/adminguide/working-with-domains.html">SageMaker Unified Studio documentation</a>.</p>
